### 2.3 进度更新节流（优）

[downloader/progress_reporter.py](file:///d:/Program/Douyin_Catcher/downloader/progress_reporter.py)：

- `DEFAULT_FLUSH_INTERVAL_MS = 500`：500ms 批量更新，而非每 64KB 更新

符合项目硬约束"进度更新必须节流到 500ms 批量以防止 UI 卡顿"。

### 2.4 进度持久化频率（优）

[downloader/downloader.py:703-710](file:///d:/Program/Douyin_Catcher/downloader/downloader.py)：

```python
now = time.monotonic()
if (
    now - last_persist_time >= PERSIST_INTERVAL_SECONDS  # 5 秒
    or downloaded_bytes - last_persist_bytes >= PERSIST_INTERVAL_BYTES  # 1 MB
):
    self._persist_progress(task_item.id, downloaded_bytes, total_bytes)
```

双触发条件（5 秒 或 1MB），平衡了磁盘 IO 与断点恢复精度。

### 2.5 并发控制（良）

[downloader/scheduler.py](file:///d:/Program/Douyin_Catcher/downloader/scheduler.py)：

- `DEFAULT_MAX_CONCURRENT = 3`，clamp 到 [1, 10]
- `set_max_concurrent()` 支持运行时动态调整
- 分片下载使用独立 Semaphore，不占用主并发槽位（符合硬约束）

**隐患**：`set_max_concurrent` 重建 Semaphore 后，已运行下载持有旧 Semaphore 不受影响，新 Semaphore 仅对新入队下载生效。若运行中下载占满旧槽位，新任务仍需等待旧任务完成。非缺陷，但用户体验上"调整并发数后不立即生效"可能令人困惑。

[crawlers/exceptions.py](file:///d:/Program/Douyin_Catcher/crawlers/exceptions.py)（192 行）：

```
Exception
└── DouyinCatcherError            # 项目异常根（line 31）
```

### 3.5 Cookie 池故障切换（良）

[crawlers/http_client.py](file:///d:/Program/Douyin_Catcher/crawlers/http_client.py)：

| 机制 | 位置 | 说明 |
|---|---|---|
| 取用策略 | line 255-275 | `status='valid'` 中 `last_used` 最早的优先（最久未用优先，均衡负载） |
| 失败检测 | line 277-306 | `fail_count += 1`，达到 `MAX_FAIL_COUNT=3` 置 `invalid` |
| 自动切换 | line 219-251 | 461/412 触发后从池中取下一条 Cookie 重试 |
| 全池失效检测 | line 318-325 | `check_all_cookies_invalid()` 检查池中是否还有 valid Cookie |

**缺陷**：`_retry_with_next_cookie` 只重试一次。若重试仍返回 461/412，`CookieInvalidError` 不会被再次捕获，直接传播给上层。即一次请求最多尝试 2 条 Cookie（原 Cookie + 1 条切换）。若池中有 5 条 valid Cookie 但前 2 条都触发 461，会直接抛错而非继续尝试第 3 条。

**改进建议**：把 `_retry_with_next_cookie` 改为循环遍历池中可用 Cookie，直至池空或成功，配合总尝试次数上限避免雪崩。

## 四、安全性

### 4.1 评级：良

### 4.2 Cookie 保护（优）

#### 4.2.1 Cookie 仅本地存储

- [app/database.py:83-94](file:///d:/Program/Douyin_Catcher/app/database.py)：Cookie 存于本地 SQLite 文件 `data.db`
- [app/config.py:17-18](file:///d:/Program/Douyin_Catcher/app/config.py)：DB 路径为 `%APPDATA%/DouyinCatcher/data.db`，位于用户私有目录

- **无任何 Cookie 上传/外发到第三方服务的代码**

#### 4.2.2 Cookie 不会被日志记录

Grep 统计 `logger.(info|debug|warning|error|exception).*cookie` 全项目 26 条命中，逐一核对，**全部只记录 cookie_id、label、is_valid、fail_count 等元数据**，无一处记录 `content`/`cookie_str`/`cookie_content` 字段值。

典型证据：
- [http_client.py:244](file:///d:/Program/Douyin_Catcher/crawlers/http_client.py)：`logger.info("Cookie 自动切换，重试使用 Cookie id=%s", next_record.id)`
- [http_client.py:274](file:///d:/Program/Douyin_Catcher/crawlers/http_client.py)：`logger.debug("从 Cookie 池取用 Cookie id=%s label=%s", cookie.id, cookie.label)`

#### 4.2.3 Cookie 跨层传递以 frozen dataclass 封装

[http_client.py:61-77](file:///d:/Program/Douyin_Catcher/crawlers/http_client.py)：`CookieRecord(frozen=True)`，`_cookie_to_record` 从数据层 `Cookie` 转换为爬虫层不可变记录，避免跨层修改。

### 4.3 敏感信息泄漏（优）

Grep 搜索 `cookie\s*=|s_v_web_id|passport_csrf_token|passportauth|sid_guard|sid_tt|uid_tt` 全项目 50 条命中：

| 类别 | 命中数 | 风险 |
|---|---|---| 
| `cookie=` 作为函数参数关键字传参 | 4 处 | 无 |
| `cookie =` 作为局部变量赋值 | 多处 | 无 |
| `s_v_web_id` | 全部位于 `signer/verify_fp.py` 生成器模块 | 无（公开设备标识生成算法，非凭据） |
| `passport_csrf_token`/`passportauth`/`sid_guard`/`sid_tt`/`uid_tt` | 0 | 无 |

**结论**：无硬编码 Cookie/Token/密钥。
