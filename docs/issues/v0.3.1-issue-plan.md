## Issue 1 — 下载任务删除功能异常：删除单个任务时误删其他任务

- **类型**：Bug（数据破坏，严重）
- **严重程度**：严重（可能导致用户任务数据丢失）
- **合并的原始问题**：#3、#17

### 问题描述

下载任务列表中，点击某个任务项的删除键时，删除的目标对象不是用户点击的那一项，导致误删：

- 现象一（原#3）：点击某一个下载任务项的删除键，**全部**下载任务都被删除。
- 现象二（原#17）：对**已完成**任务点击删除键，执行的是**随机删除**——被删除的是其他任务，而非点击的那一项，严重问题。

### 复现步骤

1. 进入"下载任务"页面；
2. 列表中包含多个任务（含已完成任务）；
3. 点击其中某一项的删除键（尤其是已完成任务）；
4. 观察被删除的任务。

### 预期行为

仅删除用户点击的那一个下载任务项，其余任务不受影响。

### 实际行为

- 全部任务被删除；或
- 随机删除了其他任务项。

### 备注

- 两条现象可归并为同一问题：删除操作的**目标标识（ID）与点击项不一致**（例如使用错误字段作为 ID、ID 映射错乱、同一 ID 复用等），需统一排查 `TaskItem` 删除回调与删除 API 的传参链路。

## Issue 2 — 下载任务完成状态 / 进度条显示异常

- **类型**：Bug
- **严重程度**：高
- **合并的原始问题**：#4、#5、#13、#16

### 问题描述

下载任务的"完成状态 / 绿色进度条"显示不可靠，且"清空已完成"操作会触发状态异常刷新：

- 现象一（原#4）：下载已完成（进度100%）也不显示绿色进度条；此时点击"清空已完成"，会把这类进度条全部变成完成的绿色进度条。
- 现象二（原#5）：点击"清空已完成"会让**正在进行中**的任务突然卡住不动；如果任务接近完成（如95%、97%），点击"清空已完成"后立刻变成完成的绿色。
- 现象三（原#16）：任务**已经完成**，但进度条仍不显示绿色（卡在 96%、97%、100% 等），直到点击"清空已完成"，才全部变成绿色进度条。
- 现象四（原#13）：进度条和颜色问题是**偶然出现**，暂无法确定稳定复现路径和异常原因。

### 复现步骤

（部分为偶现，以下为触发路径）

1. 进入"下载任务"页面，开始多个下载任务；
2. 等待任务完成（或接近完成）；
3. 观察：已完成任务进度条未变为绿色；
4. 点击"清空已完成"按钮；
5. 观察：进度条状态被异常刷成绿色完成（即使该任务实际还在进行中/刚完成）。

### 预期行为

- 任务完成（100%）后进度条应立即、稳定地显示为绿色完成状态；
- 点击"清空已完成"只应移除已完成任务，不应改变进行中任务的进度与颜色状态。

### 实际行为

- 已完成任务进度条长时间不显示绿色（卡在 96/97/100）；
- 点击"清空已完成"后，将未完成任务（含进行中的）错误地刷成绿色完成状态，或使进行中任务卡住不动。

### 备注

- 四个现象指向同一类根因：**任务完成状态在前端未正确/及时刷新**，而"清空已完成"（触发重新加载数据）恰好暴露或放大了该问题。排查方向：进度更新推送（WebSocket）与完成状态的落库时机不一致、前端对 `completed` 状态判断 / 渲染条件错误、状态刷新与列表更新的竞态。
- 与 Issue 3（"清空已完成"未生效）现象上相邻，修复时可一并验证，但按用户可见缺陷分开记录。

## Issue 3 — "清空已完成"功能未生效

- **类型**：Bug
- **严重程度**：中
- **合并的原始问题**：#1

### 问题描述

点击"清空已完成"按钮后，已完成任务并没有被清空，仍显示在下载任务列表中。

### 复现步骤

1. 进入"下载任务"页面，存在已完成（绿色/100%）任务；
2. 点击"清空已完成"按钮；
3. 观察列表。

### 预期行为

已完成任务被清空，列表中不再显示。

### 实际行为

已完成任务仍然保留在列表中，清空无效。

### 备注

- 需排查 `clearCompleted` 的 API 调用（后端过滤条件、完成状态判定）与前端列表刷新链路。

## Issue 4 — 新增"全部失败重试"功能

- **类型**：Feature（新功能）
- **严重程度**：中
- **合并的原始问题**：#2

### 问题描述

当前只支持对单个下载任务进行重试。需要一个**一键对全部失败任务重试**的功能，方便批量失败的场景下快速重新下载。

### 期望行为

- 在"下载任务"页面提供"全部失败重试"入口；
- 一键将所有失败（failed）状态的任务重新加入下载队列；
- 已在进行的任务不受影响。

### 备注

- 参考现有单项重试（`retryItem` / `retryDownload`）实现批量版本，可复用后端重试逻辑。

## Issue 7 — 输入框内容无法缓存，切换页面后丢失

- **类型**：Bug
- **严重程度**：中
- **合并的原始问题**：#11

### 问题描述

在各个输入框（如批量抓取链接输入框、主页抓取链接输入框等）中输入的内容，无法缓存：切换其他页面（或离开再回来）后，输入的内容就丢失了。

### 复现步骤

1. 在任意输入框（如批量链接输入框）输入内容；
2. 切换到其他页面再切回；
3. 观察输入内容。

### 预期行为

切换页面后输入内容仍被保留（缓存），除非用户主动清空。

### 实际行为

输入内容丢失，输入框恢复为空。

### 备注

- 排查点：页面卸载时未保存输入状态、组件未做本地缓存（如 store / localStorage / 会话级状态）。
