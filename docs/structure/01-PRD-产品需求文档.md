## 2. 产品概述

### 2.1 背景与动机

抖音已成为国内主流的短视频内容平台，大量用户出于内容收藏、二次创作素材准备、行业研究、教学归档等目的，希望批量下载抖音视频（含图文、长视频）及元数据。

目前社区中已有开源项目 `Douyin_TikTok_Download_API` 提供了抖音/TikTok 数据抓取的 API 接口。然而该项目的交付形态是 **API 服务**，存在以下现实问题：

- **使用门槛极高**：用户需要懂 Python、命令行、HTTP 请求，甚至需要自行部署服务端。
- **非技术用户被排除在外**：内容创作者、教师、研究员等目标人群普遍没有编程基础。
- **缺少完整桌面端体验**：没有任务队列、断点续传、Cookie 管理、失败重试等产品化能力。
- **签名算法频繁失效**：项目维护者需要持续跟进抖音的签名机制变化。

本项目的动机是：**将开源社区已验证可行的抓取能力，封装为面向非技术用户的 Windows 桌面应用**，让用户双击安装、图文配置 Cookie 后即可一键下载。

### 2.2 产品定位

| 维度 | 定位 |
|---|---|
| 产品形态 | Windows 桌面端单机应用（PySide6 实现） |
| 用户角色 | 个人用户，无需任何技术背景 |
| 核心价值 | 把"调 API 抓抖音"这件事变成"点按钮下载抖音" |
| 价格策略 | 开源免费公开发布 |
| 平台范围 | 仅 Windows（首次发布不覆盖 macOS / Linux） |
| 部署方式 | 安装包（Inno Setup），双击安装，无运行时依赖 |

### 2.3 目标用户画像

**画像 A：内容创作者 / 二次创作者**
- 年龄 18-35 岁，活跃于抖音、B 站、小红书
- 需要收集同行视频作为素材或灵感参考
- 不会写代码，但能熟练使用剪映、PR 等工具
- 痛点：手动一条条保存太慢，希望批量下载并保留作者信息

**画像 B：教师 / 培训师**
- 年龄 30-50 岁，技术能力一般
- 需要将抖音教学视频下载到本地用于课堂播放（避免现场网络问题）
- 痛点：不知道什么是 API，需要明确的图文引导

**画像 C：行业研究员 / 数据分析师**
- 年龄 25-40 岁，有一定数据意识
- 需要批量抓取某账号主页全部视频及元数据（点赞、评论、标签）用于研究
- 痛点：希望下载同时拿到结构化元数据（JSON / CSV）

**画像 D：普通用户 / 内容收藏者**
- 任何年龄，技术水平不限
- 想收藏自己喜欢的博主内容，防止作品被删除
- 痛点：希望操作简单、出错时能看懂提示

### 2.4 与开源项目的关系说明

本项目与 `Evil0ctal/Douyin_TikTok_Download_API` 的关系明确如下：

- **不 vendoring 其源码**：不复制其代码到本仓库
- **不 import 其模块**：不作为依赖引入
- **设计思路参考**：签名算法、解析逻辑参考其公开设计，但**完全自主实现**为本项目自有组件
- **致谢与声明**：仓库 README 中明确注明设计参考来源
- **外部依赖独立**：仅使用宽松协议的通用库（PySide6 LGPL、httpx BSD），不引入开源项目的任何专有依赖
- **维护责任独立**：签名算法失效时由本项目维护者独立修复，与开源项目无关联

## 3. 市场分析

### 3.1 痛点分析

**痛点 1：非技术用户不会用 API**
- 现有开源方案以 API 形态交付，用户需要：装 Python → 装依赖 → 启动服务 → 调 HTTP 接口 → 处理 JSON 响应 → 自己写下载逻辑
- 上述流程对非技术用户而言等于"无法使用"
- 数据：目标用户中约 90% 不具备 Python 编程能力

**痛点 2：单文件下载工具缺乏批量能力**
- 浏览器扩展或在线解析站只能一次下载一个视频
- 用户主页几百条作品时，手动逐条操作不现实
- 缺少任务队列、断点续传等"产品化"体验

**痛点 3：Cookie 风控门槛高**
- 抖音 Web API 普遍需要携带 Cookie 才能访问
- 用户不知道 Cookie 是什么、从哪里取、怎么用
- 现有工具普遍把"获取 Cookie"这件事甩给用户自己研究

**痛点 4：下载失败后无法恢复**
- 网络波动、应用崩溃、Cookie 失效都会导致下载中断
- 现有工具普遍不支持断点续传，失败后只能从头再来
- 批量场景下中断成本极高

**痛点 5：缺少元数据**
- 单纯下载视频文件丢失了作者、发布时间、点赞数、标签等结构化信息
- 研究类用户需要这些数据做分析
- 现有工具普遍只给文件不给数据

### 3.2 竞品参考

| 竞品类型 | 代表 | 形态 | 优势 | 不足 |
|---|---|---|---|---|
| 开源 API 项目 | `Douyin_TikTok_Download_API` | Python API 服务 | 功能全面、社区维护、可扩展 | 非技术用户无法使用，需自行部署 |
| 在线解析网站 | 各类抖音解析站 | 网页 | 无需安装 | 单条下载、无批量、有广告、不稳定、隐私风险 |
| 浏览器扩展 | 各类视频下载扩展 | 浏览器插件 | 安装方便 | 受浏览器策略限制、易被封、无批量、无 Cookie 管理 |
| 命令行工具 | yt-dlp 等通用工具 | CLI | 强大 | 需要命令行基础、抖音支持不稳定、无 GUI |

### 3.3 差异化定位

本产品的差异化定位如下：

| 差异点 | 说明 |
|---|---|
| **桌面 GUI + 非技术用户优先** | 双击安装、图文引导、零命令行，对标"小白可用" |
| **完整任务队列与断点续传** | 任务级续传 + 单文件分块续传，崩溃/断网后可恢复 |
| **Cookie 池管理** | 单/多 Cookie 轮询 + 健康检查，单条失效不中断下载 |
| **批量场景全覆盖** | 单链接、批量粘贴、用户主页抓取、文件导入四种入口 |
| **元数据结构化保存** | 同时输出视频文件 + JSON/CSV 元数据，支持研究类需求 |
| **自主可控的签名模块** | 签名算法独立模块化，失效时只改一处，维护成本低 |
| **无水印直链下载** | 自主实现无水印提取，画质有保障 |

## 4. 用户故事与场景

### 场景 1：单视频下载

**用户故事**：作为一名普通用户，我希望粘贴一条抖音视频链接就能下载到本地，这样我能收藏喜欢的视频。

**详细场景**：
1. 用户在抖音 App 或网页看到喜欢的视频，复制分享链接
2. 打开 Douyin_Catcher，进入"链接抓取页"
3. 把链接粘贴到顶部文本框
4. 点击"开始解析"，几秒后看到视频标题、作者、缩略图、类型
5. 勾选该条，选择下载目录，点"开始下载"
6. 切换到"下载任务页"看到进度条推进
7. 下载完成后，在目录中看到无水印视频文件 + 元数据 JSON

**验收要点**：
- 支持短链（`v.douyin.com/xxx`）、长链、分享口令文本
- 解析结果展示完整元信息
- 单文件下载成功率 ≥ 95%

### 场景 2：批量链接下载

**用户故事**：作为一名内容创作者，我希望一次性粘贴几十条链接批量下载，这样能高效收集素材。

**详细场景**：
1. 用户从多个来源收集了 30 条抖音视频链接
2. 在"链接抓取页"文本框每行粘贴一条链接
3. 点"开始解析"，应用并发解析所有链接
4. 解析结果列表显示每条的状态（成功/失败 + 失败原因）
5. 全选所有成功项，选择下载目录，点"开始下载"
6. 在"下载任务页"看到 30 条任务排队下载，可暂停/恢复
7. 失败的任务行下方显示红色原因，不影响其他任务

**验收要点**：
- 批量解析支持并发，单条失败不阻塞其他条目
- 下载队列按用户配置的并发数（默认 3）执行
- 全部暂停/全部开始/清空已完成等批量操作立即响应

### 场景 3：用户主页批量抓取

**用户故事**：作为一名研究员，我希望输入某博主主页链接就能下载其全部作品及元数据，这样能做内容分析。

**详细场景**：
1. 用户访问某抖音博主主页，复制主页链接
2. 在"链接抓取页"粘贴主页链接，点"开始解析"
3. 应用识别为主页链接后，显示过滤栏：
   - 类型：全部 / 视频 / 图文 / 长视频
   - 数量上限：例如 100 条
   - 时间段：起止日期
4. 设置过滤条件后，应用分页拉取作品列表
5. 拉取完成后，列表展示所有作品（缩略图 + 标题 + 作者 + 类型 + 时长/图片数）
6. 全选，选择下载目录，点"开始下载"
7. 在"下载任务页"看到全部任务排队执行
8. 下载完成后，目录中包含所有视频 + 元数据 JSON / CSV

**验收要点**：
- 主页链接自动识别（含 `sec_user_id` 或 `/user/` 路径）
- 分页拉取支持 `max_cursor` 翻页，直到无更多或达到上限
- 过滤条件实时生效（类型、数量、时间段）
- 元数据保存完整（点赞、评论、分享、收藏、标签）

### 场景 4：文件导入链接列表

**用户故事**：作为一名长期收集者，我有一个存放了几百条抖音链接的文本文件，希望能直接导入批量下载。

**详细场景**：
1. 用户有一个 `links.txt`，每行一条抖音链接（可能含注释行、空行）
2. 在"链接抓取页"点"导入文件"按钮，选择该文件
3. 应用读取文件内容，把每行作为一条链接填入文本框
4. 自动跳过空行和以 `#` 开头的注释行
5. 点"开始解析"，后续流程同场景 2

**验收要点**：
- 支持 `.txt` 文件导入
- 自动跳过空行和 `#` 注释行
- 导入后内容显示在文本框，用户可二次编辑
- 单次导入无硬性上限（受内存限制）

### 场景 5：Cookie 失效后恢复下载

**用户故事**：作为一名用户，我下载到一半时 Cookie 突然失效了，希望应用能自动切换到备用 Cookie，或者提示我更新后能继续未完成的任务。

**详细场景**：

**子场景 5a：多 Cookie 池自动切换**
1. 用户配置了 3 个 Cookie（账号1/账号2/账号3）
2. 下载进行中，账号1 的 Cookie 被抖音风控失效（返回 461/412）
3. 应用自动把账号1 标记为失效，切换到账号2 继续下载
4. 用户在 Cookie 配置页看到账号1 状态变红，其他正常
5. 下载任务未中断

**子场景 5b：所有 Cookie 失效**
1. 3 个 Cookie 全部失效
2. 应用暂停所有任务，弹窗提示"所有 Cookie 已失效，请更新"
3. 弹窗提供"去配置 Cookie"按钮，点击跳转到 Cookie 配置页
4. 用户按教程重新获取 Cookie，添加并测试通过
5. 回到下载任务页，点"全部开始"，任务从暂停处继续

**验收要点**：
- Cookie 池轮询采用"最久未用优先"策略
- 单条 Cookie 连续失败 3 次自动标记为 invalid
- 所有 Cookie 失效时自动暂停任务并弹窗提示
- 新增有效 Cookie 后可恢复未完成任务，无需重新解析

### 场景 6：断点续传（应用异常关闭后恢复）

**用户故事**：作为一名用户，我下载到 70% 时电脑突然断电，希望重启应用后能从 70% 处继续，而不是重头再来。

**详细场景**：

**子场景 6a：任务队列续传**
1. 用户有 50 条任务，已完成 20 条，正在下载第 21 条，应用突然崩溃
2. 重启应用
3. 应用扫描数据库，发现第 21 条状态为 `downloading`（中断态）
4. 应用把 `downloading` 重置为 `paused`，等待用户操作
5. 用户点"开始"，第 21 条从断点继续，第 22-50 条排队等待

**子场景 6b：单文件分块续传**
1. 第 21 条视频总大小 100MB，已下载 70MB，应用崩溃
2. 本地有一个 `.part` 临时文件，大小 70MB
3. 数据库中 `downloaded_bytes = 73400320`（70MB）
4. 重启后用户点继续，应用用 `Range: bytes=73400320-` 请求剩余 30MB
5. 下载完成后，`.part` 文件去掉后缀变为最终文件

**验收要点**：
- 应用启动时自动扫描未完成任务（`pending`/`downloading`/`paused`）
- `downloading` 状态在重启后重置为 `paused`
- 单文件支持 HTTP Range 分块续传
- 本地 `.part` 文件保留，完成后自动改名
- 进度持久化每 5 秒或每 1MB 落库一次，崩溃丢失进度不超过 1MB

## 5. 功能需求列表

> 优先级说明：
> - **P0（必须）**：首次发布必须完成，缺失则产品不成立
> - **P1（重要）**：首次发布应完成，缺失影响核心体验
> - **P2（可选）**：可延后到后续版本

### 5.1 链接解析功能

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|
| F-LINK-01 | 支持解析单条抖音视频链接 | P0 | 输入含 `aweme_id` 的链接，输出 `{type, url, aweme_id}` |
| F-LINK-02 | 支持解析抖音短链（`v.douyin.com/xxx`） | P0 | 短链经 HTTP 重定向后正确提取 `aweme_id` |
| F-LINK-03 | 支持解析分享口令文本 | P0 | 输入"X.X 复制打开抖音..."文本，能正则提取出 URL |
| F-LINK-04 | 支持识别用户主页链接 | P0 | 含 `sec_user_id` 或 `/user/` 的链接识别为 `user_home` 类型 |
| F-LINK-05 | 批量解析多链接（每行一条） | P0 | 支持 30+ 条链接并发解析，单条失败不阻塞其他 |
| F-LINK-06 | 文件导入链接列表 | P1 | 支持 `.txt` 文件，自动跳过空行和 `#` 注释行 |
| F-LINK-07 | 解析结果可勾选/全选/取消全选 | P0 | 列表项支持复选框，顶部有全选/取消全选按钮，已选计数实时显示 |
| F-LINK-08 | 无法识别的链接给出明确提示 | P0 | 输入框下方红字提示"无法识别该链接，请确认是抖音视频/主页链接" |

### 5.2 视频解析功能

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|
| F-VIDEO-01 | 调用抖音 `aweme/detail` 接口解析视频元数据 | P0 | 输入 `aweme_id` + Cookie，输出 `{type, title, author, duration, cover_url, no_watermark_url, image_urls[]}` |
| F-VIDEO-02 | 提取无水印视频直链 | P0 | 从 `video.play_addr.url_list` 取直链，或替换 `playwm` → `play` |
| F-VIDEO-03 | 支持图集类型解析（多图） | P0 | 从 `images[].url_list` 取原图直链列表，`image_count` 正确 |
| F-VIDEO-04 | 支持长视频类型解析 | P1 | 长视频（>1 分钟）能正确识别并提取直链 |
| F-VIDEO-05 | 解析结果展示缩略图/标题/作者/时长/类型 | P0 | 列表行展示完整元信息，缩略图异步加载不阻塞 UI |
| F-VIDEO-06 | 作品已删除/私密时标记失败并说明原因 | P0 | `status_code` 非 0 时标记失败，`fail_reason = "该作品已被删除或设为私密"` |

### 5.3 主页批量抓取功能

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|
| F-HOME-01 | 输入主页链接分页拉取作品列表 | P0 | 调用 `aweme/post` 接口，维护 `max_cursor` 翻页直到无更多 |
| F-HOME-02 | 支持按类型过滤（全部/视频/图文/长视频） | P1 | 过滤栏选择类型后，结果列表只显示对应类型 |
| F-HOME-03 | 支持按数量上限过滤 | P1 | 设置上限后，拉取达到上限即停止 |
| F-HOME-04 | 支持按时间段过滤（起止日期） | P1 | 按 `create_time` 过滤，只显示时间段内作品 |
| F-HOME-05 | 抓取过程显示进度（已拉取条数 / 总数） | P1 | 顶部显示进度条或计数，可取消 |
| F-HOME-06 | 抓取完成后结果可勾选下载 | P0 | 列表项支持复选框，与单链接解析结果一致 |

### 5.4 下载引擎功能

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|
| F-DL-01 | 批量下载（任务队列） | P0 | 多任务按并发数排队执行，并发数可配（默认 3，上限 10） |
| F-DL-02 | 任务队列断点续传 | P0 | 应用重启后扫描未完成任务，重建队列，`downloading` 重置为 `paused` |

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 |
|---|---|
| 并发下载数 | 用户可配，默认 3，上限 10（`asyncio.Semaphore` 控制） |
| 单文件下载响应时间 | 单视频（< 50MB）在 10Mbps 带宽下 ≤ 60 秒完成 |
| 链接解析响应时间 | 单条链接解析 ≤ 5 秒（含重定向） |
| 主页抓取响应时间 | 单页（约 20 条）≤ 10 秒 |
| UI 响应时间 | 用户操作（点击/输入）响应 ≤ 200ms，不卡顿 |
| 进度更新频率 | 进度信号每 500ms 批量发送一次，UI 只刷新可见行 |
| 启动时间 | 应用冷启动 ≤ 3 秒进入主界面 |
| 内存占用 | 50 任务并发下载时内存峰值 ≤ 500MB |

### 6.2 可靠性

| 指标 | 要求 |
|---|---|
| 任务队列断点续传 | 应用崩溃/异常关闭后重启，未完成任务可恢复，`downloading` 重置为 `paused` |
| 单文件分块续传 | 中断后用 HTTP Range 从 `downloaded_bytes` 处继续，`.part` 文件保留 |
| 进度持久化 | 每 5 秒或每 1MB 落库一次，崩溃丢失进度不超过 1MB |
| 失败重试 | 网络异常/5xx/风控限流自动重试，最多 3 次，指数退避（2s/4s/8s） |
| Cookie 池容错 | 单条 Cookie 失效自动切换，不打断下载；全部失效时安全暂停 |
| 数据库可靠性 | SQLite 开启 WAL 模式，提升并发写入性能，避免写锁竞争 |
| 卸载不丢数据 | 用户数据存 `%APPDATA%/DouyinCatcher/`，卸载/重装不丢失 |

### 6.3 易用性

| 指标 | 要求 |
|---|---|
| 非技术用户友好 | 双击安装、零命令行、零 Python 知识要求 |
| 图文引导 | Cookie 配置含 7 步图文教程（含截图），默认折叠可展开 |
| 首次引导 | 首次启动 4 步引导（欢迎→下载目录→Cookie→完成） |
| 错误信息人话化 | 绝不让用户看到原始异常栈，每个错误有人话解释 + 下一步建议 |
| 操作反馈 | 耗时操作显示 loading + 可取消；批量操作立即响应不阻塞 |
| 视觉风格 | 简洁现代扁平化，品牌色（紫）为主，完成绿、失败红 |
| 窗口可缩放 | 任务列表区域可滚动，适应不同屏幕尺寸 |
| 无弹窗轰炸 | 所有信息在应用内展示，不使用系统通知/弹窗骚扰 |

### 6.4 可维护性

| 指标 | 要求 |
|---|---|
| 签名算法独立模块 | `crawlers/signer/` 独立子模块，算法失效时只改这一处，不影响其他组件 |
| 分层职责清晰 | UI → worker → {downloader, crawlers} → models → database 单向依赖，下层不依赖上层 |
| 代码覆盖率 | 整体行覆盖率 ≥ 80%，方法覆盖率 ≥ 30%，签名算法模块 ≥ 90% |
| 日志规范 | 按天滚动，保留 7 天，记录 API 请求/响应摘要、异常栈、任务状态变化 |
| 测试策略分层 | 签名（输入输出对）/ 解析器（纯函数）/ 爬虫（VCR.py 录制）/ 下载（mock httpx）/ 数据（内存 SQLite）/ UI（手动验收） |
| 配置外置 | 非敏感配置存 `config` 表，敏感配置（Cookie）加密存储于 `cookies` 表 |

### 6.5 安全性

| 指标 | 要求 |
|---|---|
| Cookie 不泄漏 | Cookie 存储于本地 SQLite，不上传任何远端服务器 |
| 日志脱敏 | 日志中不得记录完整 Cookie 字符串，需脱敏处理 |

| 不硬编码 Cookie | 代码、测试、日志中均不得硬编码 Cookie |
| 安装包无敏感信息 | PyInstaller 打包产物不含任何 Cookie / 密钥 |
| gitleaks 扫描 | CI 流程包含安全扫描，检测 Cookie / 密钥泄漏（设计保留，暂不实现 CI） |

| PySide6 | Qt for Python 的官方绑定，LGPL 协议 |
| httpx | Python 异步 HTTP 客户端库，BSD 协议 |
| PyInstaller | Python 打包工具，将应用打包为 Windows 可执行文件 |
| Inno Setup | Windows 安装包制作工具 |
| asyncio | Python 异步编程框架，本项目工作线程承载 |
| Semaphore | asyncio 的并发控制原语，用于限制下载并发数 |
| VCR.py | Python 测试工具，录制 HTTP 响应回放，避免测试打真实 API |
| `.part` 文件 | 下载未完成的临时文件，完成后去掉后缀变为最终文件 |
| `%APPDATA%` | Windows 用户应用数据目录，本项目用户数据存放位置 |
| `%USERPROFILE%` | Windows 用户主目录，默认下载目录的父级 |

### 10.2 错误码对照表

| 错误类型 | 触发场景 | 用户提示 | 用户操作 |
|---|---|---|---|
| Cookie 无效/过期 | 签名请求返回 461/412，或测试 Cookie 失败 | "Cookie 已失效，抖音需要重新登录验证" | 跳转 Cookie 配置页，按教程重新获取 |
| 网络连接失败 | httpx 连接超时/DNS 失败 | "网络连接失败，请检查网络后重试" | 检查网络，点"重试" |
| 视频不存在/已删除 | aweme/detail 返回 status_code 非 0 | "该作品已被删除或设为私密，无法下载" | 跳过该项 |
| 触发验证 | 响应含滑动验证 HTML | "抖音要求安全验证，暂时无法下载此作品" | 稍后重试，或更新 Cookie |
| 下载失败（3 次重试后） | 重试耗尽 | "下载失败：{具体原因}（已重试 3 次）" | 检查原因后可手动重新加入队列 |
| 磁盘空间不足 | 写入 .part 文件时 OSError | "磁盘空间不足，无法保存到 {目录}" | 更换下载目录或清理磁盘 |
| 链接格式错误 | URLParser 无法识别 | "无法识别该链接，请确认是抖音视频/主页链接" | 检查链接格式 |
| 未知错误 | 未预期的异常 | "发生未知错误：{简短描述}" | 可点"复制详情"反馈给开发者 |
