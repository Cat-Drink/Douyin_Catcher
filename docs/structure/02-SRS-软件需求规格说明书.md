## 1. 引言

### 1.1 目的

本《软件需求规格说明书》（SRS）旨在完整、准确地描述"抖音抓取器（Douyin_Catcher）"桌面应用的功能需求、非功能需求、接口需求与数据需求，为后续的概要设计、详细设计、编码实现、测试验证以及用户验收提供唯一权威的需求基线。

本文件的预期读者包括：

- 项目开发者（设计、编码、自测）
- 测试人员（编写测试用例、执行验收测试）
- 项目维护者（理解系统行为、评估变更影响）
- 终端用户代表（参与需求评审与验收）

### 1.2 文档范围

本说明书覆盖抖音抓取器 V1.0 版本的全部需求，包括但不限于：

- 链接解析（单链接、批量链接、短链重定向、主页链接识别、文件导入）
- 视频解析（抖音 Web API 调用、无水印直链提取、图集解析、元数据提取）
- 主页批量抓取（分页拉取、类型过滤、数量上限、时间段过滤）
- 下载引擎（并发控制、Range 续传、.part 文件、进度持久化、失败重试、暂停/恢复、去重）
- Cookie 池管理（添加/删除/测试/轮询/健康检查/自动切换）
- 任务管理（任务列表、批量操作、状态显示、断点续传恢复）
- 首次使用引导（欢迎页、目录设置、Cookie 配置引导）
- 设置（下载目录、并发数、分块大小、元数据格式、日志导出）
- 非功能需求（性能、可靠性、易用性、可维护性、安全性）

本说明书**不**包含：

- 详细算法实现（属于详细设计文档）
- 数据库表结构完整定义（属于数据库设计文档，本文档仅概述）
- 外部接口的字段级定义（属于接口设计文档）
- CI/CD 实施细节（设计文档已规划，但不在 V1.0 范围内强制实现）

### 1.3 定义与缩略语

| 术语 | 全称/释义 |
|---|---|
| **aweme_id** | 抖音作品的唯一标识符，用于定位单个视频或图集作品 |
| **sec_user_id** | 抖音用户的安全用户 ID，用于定位用户主页，是主页抓取接口的关键参数 |
| **X-Bogus** | 抖音 Web API 请求所需的签名参数之一，由客户端签名算法生成 |
| **A_Bogus** | 抖音 Web API 较新版本的签名参数，与 X-Bogus 同类，基于请求参数和环境信息生成 |
| **msToken** | 抖音 Web API 的动态令牌参数，随请求生成，用于风控校验 |
| **verify_fp / s_v_web_id** | 抖音浏览器指纹参数，用于标识访问来源 |
| **WAL** | Write-Ahead Logging，SQLite 的一种日志模式，提升并发读写性能 |
| **Range 请求** | HTTP 协议中的范围请求（`Range: bytes=start-end`），用于从断点继续下载文件 |
| **.part 文件** | 下载未完成时的临时文件，完成后去掉 `.part` 后缀转为正式文件 |
| **无水印直链** | 抖音视频原始文件（不含水印）的直下载 URL，由解析接口返回 |
| **图集** | 抖音图文作品类型，由多张图片组成 |
| **长视频** | 时长较长的视频作品（一般 > 1 分钟） |
| **Cookie 池** | 多个抖音账号 Cookie 的集合，通过轮询和健康检查实现负载均衡与容错 |
| **max_cursor** | 主页作品分页拉取的游标参数，用于获取下一页作品 |
| **PySide6** | Qt for Python 的官方绑定，用于构建桌面 GUI |
| **httpx** | Python 的异步 HTTP 客户端库，支持 HTTP/2 和 Range 请求 |
| **asyncio** | Python 的异步 I/O 框架，用于并发执行爬虫与下载任务 |
| **Semaphore** | asyncio 提供的并发原语，用于限制同时进行的任务数量 |
| **FR** | Functional Requirement，功能需求编号前缀 |
| **NFR** | Non-Functional Requirement，非功能需求编号前缀 |

## 2. 总体描述

### 2.1 产品概述

抖音抓取器是一款面向非技术用户的 **Windows 桌面端应用**，以 PySide6 构建 GUI、Python 实现爬虫与下载逻辑、SQLite（WAL 模式）持久化任务状态。用户通过简单的图形界面粘贴抖音链接或主页链接，即可下载视频/图集文件及其元数据。

产品定位：

- **单机本地运行**，无需服务端，无需注册账号
- **安装即用**，双击安装包完成部署，无任何命令行操作
- **自主实现爬虫组件**，不 vendoring、不 import 任何开源项目的源码模块，签名算法、解析逻辑均为本项目自有组件
- **Cookie 配置图文引导**，让非技术用户也能完成 Cookie 获取与配置
- **断点续传**：任务级（重启后恢复队列）+ 文件级（Range 分块续传）

### 2.2 产品功能

产品功能概要列表如下：

| 功能域 | 功能概述 |
|---|---|
| 链接解析 | 支持单链接、批量链接粘贴、短链重定向、主页链接识别、文件导入链接列表 |
| 视频解析 | 调用抖音 aweme/detail 接口，提取无水印直链、图集原图、视频元数据 |
| 主页抓取 | 基于 sec_user_id 分页拉取作品列表，支持类型/数量/时间段过滤 |
| 下载引擎 | 并发控制（1-10）、Range 续传、.part 临时文件、进度持久化、失败重试、暂停/恢复、去重 |
| Cookie 池管理 | 添加/删除/测试/轮询/健康检查/自动切换，全部失效时统一提示 |
| 任务管理 | 任务列表展示、批量操作（全部暂停/开始/清空已完成）、状态显示、断点续传恢复 |
| 首次引导 | 欢迎页、下载目录设置、Cookie 配置图文引导 |
| 设置 | 下载目录、并发数、分块大小、元数据格式（JSON/CSV）、日志导出 |

### 2.3 用户特征

本产品的目标用户为**非技术用户**，其典型画像如下：

| 维度 | 描述 |
|---|---|
| 技术背景 | 不熟悉命令行操作，不会使用 Python/抓包工具，不了解 HTTP/API 概念 |
| 使用动机 | 想下载抖音上的视频/图文作品用于个人收藏、二次创作素材整理、内容研究 |
| 操作习惯 | 期望"双击即用"，所有操作通过鼠标完成；遇到错误期望有人话解释和明确的下一步指引 |
| Cookie 配置能力 | 不了解 Cookie 是什么，需要图文步骤逐步引导获取；可能因 Cookie 过期而困惑，需要清晰的失效提示与重新配置指引 |
| 容错期望 | 不接受看到异常栈、错误码、技术性报错；期望每个错误都有可读的解释和操作建议 |
| 设备环境 | Windows 10/11 桌面或笔记本，常规家用配置，不期望安装额外运行时（如 Java、Node） |

### 2.4 约束条件

| 编号 | 约束类型 | 约束内容 |
|---|---|---|
| C-001 | 平台约束 | 仅支持 Windows 10/11（x64）桌面操作系统 |
| C-002 | 语言约束 | 后端逻辑使用 Python 实现 |
| C-003 | UI 框架约束 | 使用 PySide6（Qt for Python）构建 GUI |
| C-004 | 数据库约束 | 使用 SQLite（开启 WAL 模式）作为本地持久化存储 |
| C-005 | 依赖约束 | 运行时不依赖任何开源抖音抓取项目（不 vendoring、不 import），签名算法与解析逻辑自主实现 |
| C-006 | 外部依赖约束 | 仅使用宽松协议的通用库：PySide6（LGPL）、httpx（BSD） |
| C-007 | 打包约束 | 使用 PyInstaller `--onedir` 打包 + Inno Setup 生成安装包，安装包体积目标 60-80MB |
| C-008 | 数据存储约束 | 用户数据存放于 `%APPDATA%/DouyinCatcher/`，程序目录只放代码与资源 |
| C-009 | 进程约束 | 单进程架构，UI 主线程 + 后台 asyncio 工作线程 |
| C-010 | 联网约束 | 需要可访问 douyin.com 的网络环境；不提供代理配置 UI（V1.0） |

### 2.5 假设与依赖

**假设**：

- A-001：用户能够使用现代浏览器（Chrome/Edge）访问抖音网页版并完成登录
- A-002：用户能够按照图文教程完成 Cookie 的复制与粘贴
- A-003：抖音 Web API 的整体结构（aweme/detail、aweme/post 接口）在 V1.0 周期内保持相对稳定
- A-004：签名算法（X-Bogus / A_Bogus / msToken）的公开原理在 V1.0 周期内可被自主实现并验证
- A-005：用户的 Windows 设备已具备可用的网络栈与文件系统权限
- A-006：用户拥有目标下载目录的读写权限

**依赖**：

- D-001：依赖 PySide6 >= 6.6 提供 GUI 能力
- D-002：依赖 httpx[http2] >= 0.27 提供 HTTP 客户端能力（含 Range 请求与 HTTP/2）
- D-003：依赖 Python 3.10+ 运行时（由 PyInstaller 打包进安装包，用户无需单独安装）
- D-004：依赖抖音 Web API 的可访问性（API 不可用时核心功能无法使用）
- D-005：依赖用户提供有效的抖音 Cookie（无 Cookie 无法访问需要登录态的接口）

## 3. 具体需求

### 3.1 功能需求

#### 3.1.1 链接解析（FR-001 ~ FR-010）

---

**FR-001 单链接解析**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-001 |
| 需求描述 | 系统应支持用户输入单个抖音视频/图文/主页链接，自动识别并解析出链接类型与关键标识 |
| 输入 | 用户粘贴的包含单个抖音链接的文本（可能含分享口令前后文案、短链、长链） |
| 输出 | 解析结果对象：`{type: 'video'\|'image_set'\|'long_video'\|'user_home', url, aweme_id\|sec_user_id}` |
| 优先级 | 高 |
| 验收标准 | 1. 粘贴标准抖音视频长链（含 `aweme_id`）能正确识别为视频类<br>2. 粘贴抖音主页链接（含 `sec_user_id` 或 `/user/`）能正确识别为主页类<br>3. 粘贴分享口令文本（如"5.68 复制打开抖音…"）能提取出其中的链接并解析<br>4. 解析耗时 < 5 秒（含短链重定向） |

---

**FR-002 批量链接粘贴解析**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-002 |
| 需求描述 | 系统应支持用户在多行文本框中粘贴多个抖音链接（每行一个），批量解析 |
| 输入 | 多行文本，每行一个抖音链接（可含分享口令） |
| 输出 | 解析结果列表，每项含类型与标识；无法识别的行单独标记 |
| 优先级 | 高 |
| 验收标准 | 1. 一次粘贴 10 个以上链接能全部解析<br>2. 混合视频链接与主页链接时分别识别<br>3. 部分行无法识别时不影响其他行的解析，且明确标记无法识别的行 |

---

**FR-003 短链重定向解析**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-003 |
| 需求描述 | 系统应支持抖音短链（`v.douyin.com/xxx`）的自动重定向，获取最终 URL 后再进行类型识别 |
| 输入 | 抖音短链 URL |
| 输出 | 重定向后的最终 URL 及其解析结果 |
| 优先级 | 高 |
| 验收标准 | 1. 输入 `https://v.douyin.com/xxxxxxx/` 能跟随重定向拿到含 `aweme_id` 的长链<br>2. 重定向过程对用户透明，用户仅需粘贴短链<br>3. 重定向失败时给出"网络连接失败，请检查网络后重试"的提示 |

---

**FR-004 主页链接识别**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-004 |
| 需求描述 | 系统应能识别抖音用户主页链接，提取 `sec_user_id`，并触发主页抓取流程 |
| 输入 | 抖音主页链接（含 `sec_user_id` 查询参数或 `/user/` 路径） |
| 输出 | 解析结果对象：`{type: 'user_home', url, sec_user_id}`；并在 UI 上展示主页抓取过滤栏 |
| 优先级 | 高 |
| 验收标准 | 1. 主页链接被正确识别为 `user_home` 类型<br>2. `sec_user_id` 被正确提取<br>3. UI 上自动展示类型/数量/时间段过滤栏 |

---

**FR-005 视频/图文/长视频类型识别**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-005 |
| 需求描述 | 系统应根据解析结果区分视频、图文（图集）、长视频三种作品类型 |
| 输入 | 含 `aweme_id` 的链接（解析前无法确定具体子类型） |
| 输出 | 作品类型标签：`'video'`、`'image_set'`、`'long_video'` |
| 优先级 | 高 |
| 验收标准 | 1. 视频链接解析后类型为 `video`<br>2. 图文链接解析后类型为 `image_set` 且返回图片数<br>3. 长视频链接解析后类型为 `long_video` 且返回时长 |

---

**FR-006 分享口令文本提取**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-006 |
| 需求描述 | 系统应能从抖音 App 分享出来的带口令文本（如"5.68 复制打开抖音…"）中提取出有效链接 |
| 输入 | 含分享口令的完整文本（口令前后可能含中文文案、表情） |
| 输出 | 提取出的抖音链接 URL |
| 优先级 | 高 |
| 验收标准 | 1. 粘贴完整分享口令文本能提取出短链<br>2. 文本前后含中文文案时不影响提取<br>3. 无法提取出链接时给出"无法识别该链接，请确认是抖音视频/主页链接"的提示 |

---

**FR-007 文件导入链接列表**

| 项 | 内容 |
|---|---|
| 需求编号 | FR-007 |
| 需求描述 | 系统应支持用户通过"导入文件"按钮选择一个文本文件，将文件中的链接（每行一个）批量导入解析 |

#### 3.3.1 外部接口概述

| 接口编号 | 接口名称 | 方向 | 说明 |
|---|---|---|---|

- HTTP 客户端使用 httpx.AsyncClient 单例，支持 HTTP/2
- 下载请求使用 `Range: bytes={downloaded_bytes}-` 头实现续传

### 3.4 数据需求

#### 3.4.1 数据概述

本系统使用 SQLite（WAL 模式）作为本地持久化存储，数据库文件位于 `%APPDATA%/DouyinCatcher/data.db`。详细表结构定义见《数据库设计文档》。

#### 3.4.2 数据实体

| 数据实体 | 用途 | 关键字段 |
|---|---|---|
| **tasks** | 下载任务（一次抓取/下载请求 = 一条记录） | id, source_type, source_url, status, total_items, completed_items, download_dir |
| **task_items** | 任务项（一个视频/图集 = 一条记录，断点续传核心） | id, task_id, aweme_id, url, type, status, downloaded_bytes, total_bytes, retry_count, fail_reason, local_path |
| **metadata** | 作品元数据（可选保存） | id, task_item_id, aweme_id, title, desc, author, publish_time, like_count, tags, raw_json |
| **cookies** | Cookie 池 | id, content, label, status, last_used, last_check, fail_count |
| **config** | 应用配置（键值对） | key, value |

#### 3.4.3 数据持久化约束

| 编号 | 约束 |
|---|---|
| DR-001 | 数据库开启 WAL 模式（`PRAGMA journal_mode=WAL`） |
| DR-002 | `task_items` 表通过 `task_id` 外键关联 `tasks` 表，`ON DELETE CASCADE` |
| DR-003 | `metadata` 表通过 `task_item_id` 外键关联 `task_items` 表，`ON DELETE CASCADE` |
| DR-004 | 时间字段使用 ISO8601 格式字符串 |
| DR-005 | `config` 表使用键值对结构，key 为主键 |
| DR-006 | `cookies.content` 字段存储 Cookie 字符串，不入库代码、不写入日志 |

#### 3.4.4 数据保留策略

- 任务与任务项记录：用户主动删除或"清空已完成"时移除
- Cookie 记录：用户主动删除时移除
- 元数据：随任务项级联删除
- 日志：按天滚动，保留 7 天

## 4. 附录

### 附录 A 错误码对照表

系统将错误分为 8 类，每类含触发场景、用户可见信息、处理方式与用户操作建议。

| 错误码 | 错误类型 | 触发场景 | 用户可见信息 | 系统处理 | 用户该做什么 |
|---|---|---|---|---|---|
| **E-001** | Cookie 无效/过期 | 签名请求返回 461/412，或"测试 Cookie"失败 | "Cookie 已失效，抖音需要重新登录验证" | 任务项标记失败；Cookie `fail_count += 1`；连续 3 次置 `invalid`；自动切换或全部失效时暂停所有任务 | 跳转 Cookie 配置页，按教程重新获取 |
| **E-002** | 网络连接失败 | httpx 连接超时/DNS 失败 | "网络连接失败，请检查网络后重试" | 触发重试（指数退避）；达到 3 次后标记失败 | 检查网络，点"重试" |
| **E-003** | 视频不存在/已删除 | aweme/detail 返回 `status_code` 非 0 | "该作品已被删除或设为私密，无法下载" | 任务项标记失败，不重试 | 跳过该项 |
| **E-004** | 触发验证 | 响应含滑动验证 HTML | "抖音要求安全验证，暂时无法下载此作品" | 任务项标记失败，不重试 | 稍后重试，或更新 Cookie |
| **E-005** | 下载失败（3 次重试后） | 重试耗尽 | "下载失败：{具体原因}（已重试 3 次）" | 任务项标记失败，`fail_reason` 记录原因 | 检查原因后可手动重新加入队列 |
| **E-006** | 磁盘空间不足 | 写入 `.part` 文件时 `OSError` | "磁盘空间不足，无法保存到 {目录}" | 任务项标记失败；弹窗提示 | 更换下载目录或清理磁盘 |
| **E-007** | 链接格式错误 | URLParser 无法识别 | "无法识别该链接，请确认是抖音视频/主页链接" | 输入框下方红字提示，不弹窗 | 检查链接格式 |
| **E-008** | 未知错误 | 未预期的异常 | "发生未知错误：{简短描述}" | 记录完整异常栈到日志；UI 仅展示简短描述 | 可点"复制详情"反馈给开发者 |

**错误展示位置**：

- 任务项级错误（E-001~E-005 单项）：显示在该任务行下方（红色小字），不打断其他任务
- 全局错误（E-001 全部 Cookie 失效、E-006 磁盘满）：弹窗提示 + 提供操作按钮
- 输入错误（E-007）：输入框下方红字提示，不弹窗

**爬虫层异常类型映射**：

| 异常类型 | 触发条件 | 系统行为 |
|---|---|---|
| `CookieInvalidError` | Cookie 失效或被限流 | 跳转 Cookie 配置页 |
| `RateLimitedError` | 被风控限流 | 该项标记失败，原因提示等待 |
| `VideoNotFoundError` | 作品已删除/私密 | 标记该项失败，原因写明 |
| `NetworkError` | 网络异常 | 交给下载引擎的重试逻辑 |

| 前置条件 | 已完成首次引导；Cookie 池中至少有一条有效 Cookie |
| 主流程 | 1. 用户在链接抓取页粘贴链接或导入文件<br>2. 系统解析链接，展示结果列表<br>3. 用户勾选要下载的作品<br>4. 用户选择下载目录<br>5. 用户点击"开始下载"<br>6. 系统创建任务与任务项记录<br>7. 系统将任务项加入下载队列<br>8. 系统按并发数下载，实时更新进度<br>9. 下载完成后 `.part` 重命名为最终文件 |
| 备选流程 | 4a. 主页链接时展示过滤栏，用户配置类型/数量/时间段<br>6a. 重复 `aweme_id` 跳过<br>8a. Cookie 失效自动切换<br>8b. 网络异常触发重试<br>8c. 用户暂停任务 |
| 后置条件 | 任务项状态为 `completed` 或 `failed`；本地文件存在（成功时） |

**UC-012 断点续传**

| 项 | 内容 |
|---|---|
| 用例名称 | 断点续传 |
| 参与者 | 系统 |
| 前置条件 | 应用异常退出或正常关闭，存在未完成任务 |
| 主流程 | 1. 应用启动<br>2. 系统扫描 `tasks` 与 `task_items`<br>3. 系统筛选 `status IN ('pending','downloading','paused')` 的记录<br>4. 系统将 `downloading` 重置为 `paused`<br>5. 系统重建下载队列<br>6. 用户点"开始"或自动继续<br>7. 系统读取 `.part` 文件与 `downloaded_bytes`<br>8. 系统发起 Range 请求从断点续传 |
| 后置条件 | 未完成任务从断点继续下载 |

#### B.3 状态图描述

**任务项状态转换**：

```
pending ──开始下载──> downloading ──完成──> completed
   │                      │
   │                      ├──暂停──> paused ──恢复──> downloading
   │                      │
   │                      ├──失败(重试<3)──> downloading (指数退避后)
   │                      │
   │                      ├──失败(重试=3)──> failed ──手动重试──> pending
   │                      │
   │                      └──应用退出──> (重启后) paused
   │
   └──应用退出──> (重启后) pending
```

**Cookie 状态转换**：

```
untested ──测试──> valid ──连续3次失败──> invalid
                       │                        │
                       ├──成功响应──> valid      └──重新测试通过──> valid
                       │
                       └──单次失败──> valid (fail_count += 1)
```
