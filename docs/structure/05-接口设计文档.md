## 2. 接口设计概述

### 2.1 接口分类

本项目接口按用途分为两大类：

| 类别 | 范围 | 文档章节 |
|---|---|---|
| **内部编程接口** | UI 层、工作线程、下载引擎、爬虫组件层、数据层之间的 Python 调用接口 | 第 3、4、5、6 节 |
| **抖音 Web API 调用接口** | 调用抖音官方 Web API（`aweme/v1/web/aweme/detail` 等）的请求规范与响应契约 | 第 7 节 |

**内部编程接口按所在层划分**：

| 层 | 模块 | 主要接口类 | 文档章节 |
|---|---|---|---|
| 爬虫组件层 | `crawlers/` | `URLParser`、`Signer`、`VideoParser`、`UserHomeCrawler`、`HttpClient`、`exceptions` | 第 3 节 |
| 下载引擎层 | `downloader/` | `Scheduler`、`Downloader`、`ProgressReporter` | 第 4 节 |
| 工作线程桥接层 | `worker/` | `AsyncWorker`、Qt 信号清单 | 第 5 节 |
| 数据层 | `app/` | `Database`、`TaskRepository`、`TaskItemRepository`、`CookieRepository`、`ConfigRepository`、`MetadataRepository` | 第 6 节 |

### 2.2 设计原则

| 原则 | 说明 | 落地方式 |
|---|---|---|
| **单一职责** | 每个接口类/模块只负责一类明确职责 | `Signer` 只签名，`VideoParser` 只解析视频，`HttpClient` 只发请求；职责不交叉 |
| **单向依赖** | 依赖方向严格自上而下：UI → worker → {downloader, crawlers} → models → database | 下层模块不得 import 上层模块；通过依赖注入（构造函数传入）解耦，避免循环依赖 |
| **接口与实现分离** | 接口签名稳定，实现可替换 | 关键接口（如 `Signer`）通过抽象基类定义契约，子类可替换算法实现而不影响调用方 |
| **显式异常** | 不使用裸 `Exception`，所有可预期错误抛出明确异常子类 | 异常类层次结构见 3.6 节 |
| **线程安全** | 跨线程通信只走 Qt 信号/槽，不直接共享可变状态 | 工作线程通过 `AsyncWorker` 桥接，进度回传走 `pyqtSignal` |
| **类型完整** | 所有公共接口方法用 Python 类型提示标注参数与返回值 | 使用 `from __future__ import annotations` 启用 PEP 604 联合类型语法 |
| **不可变数据结构** | 跨层传递的数据用 `dataclass(frozen=True)` | 见附录 A 数据结构汇总 |

## 3. 爬虫组件层接口

爬虫组件层位于 `crawlers/` 目录，承载链接解析、签名算法、视频解析、主页抓取、HTTP 客户端等核心能力。所有接口在工作线程（asyncio 事件循环）中调用。

### 3.1 URLParser 接口

**职责**：从用户输入的文本中提取抖音链接，识别链接类型，解析出 `aweme_id` 或 `sec_user_id`。

**所在文件**：`crawlers/url_parser.py`

**接口签名**：

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import Literal

LinkType = Literal["video", "image_set", "long_video", "user_home"]


@dataclass(frozen=True)
class ParsedURL:
    """URL 解析结果。

    type 为 'video' | 'image_set' | 'long_video' 时，aweme_id 必填、sec_user_id 为 None。
    type 为 'user_home' 时，sec_user_id 必填、aweme_id 为 None。
    注：image_set 与 long_video 的最终判定依赖 VideoParser 调用 detail 接口后的结果，
        URLParser 仅在能从 URL 直接判断时给出预判，否则默认归为 'video'。
    """
    type: LinkType
    url: str                       # 规范化后的最终 URL（跟随重定向后）
    aweme_id: str | None           # 视频/图文/长视频作品 ID
    sec_user_id: str | None        # 用户主页 sec_user_id
    original_text: str             # 用户输入的原始文本（调试用）


class URLParser:
    """链接解析器。

    纯逻辑组件，不持有网络连接；如需跟随短链重定向，通过注入的 HttpClient 完成。
    """

    def __init__(self, http_client: "HttpClient") -> None: ...

    def parse(self, text: str) -> ParsedURL:
        """解析用户粘贴的链接文本。

        流程：extract_url → 跟随重定向（如需）→ identify_type → 构造 ParsedURL。

        参数:
            text: 用户粘贴的原始文本，可能含分享口令、短链、长链。

        返回:
            ParsedURL 数据结构。

        异常:
            InvalidURLFormatError: 文本中无可识别的抖音链接。
        """
        ...

    def extract_url(self, text: str) -> str | None:
        """从任意文本中提取第一个抖音链接 URL。

        支持识别：
            - 抖音短链：https://v.douyin.com/xxxxx/
            - 抖音长链：https://www.douyin.com/video/{aweme_id}
            - 主页链接：https://www.douyin.com/user/{sec_user_id}
            - 分享口令中嵌入的链接

        参数:
            text: 原始文本。

        返回:
            提取到的 URL 字符串；未找到返回 None。
        """
        ...

    def identify_type(self, url: str) -> LinkType:
        """根据 URL 路径与查询参数识别链接类型。

        识别规则:
            - 含 `aweme_id` 查询参数 或 路径含 `/video/` → 'video'（具体类型由 VideoParser 最终判定）
            - 含 `sec_user_id` 查询参数 或 路径含 `/user/` → 'user_home'
            - 抖音短链需先跟随重定向后再判断

        参数:
            url: 已规范化的 URL。

        返回:
            LinkType 枚举值。
        """
        ...
```

### 3.2 Signer 接口

**职责**：为抖音 Web API 请求生成 X-Bogus、A_Bogus、msToken、verify_fp 等签名参数。算法失效时只需修改本模块，不影响其他组件。

**所在文件**：`crawlers/signer/__init__.py`（聚合入口）及子模块 `xbogus.py`、`abogus.py`、`mstoken.py`、`verify_fp.py`。

**接口签名**：

```python
from __future__ import annotations
from typing import Protocol


class Signer(Protocol):
    """签名算法模块协议。

    实现方需提供以下方法。具体实现位于 crawlers/signer/ 子包，
    内部组合 xbogus / abogus / mstoken / verify_fp 四个子算法。
    """

    def sign(self, url: str, params: dict) -> dict:
        """为请求生成完整的签名参数集合。

        参数:
            url: 请求 URL（不含查询参数）。
            params: 业务请求参数（query / form 数据）。

        返回:
            需要追加到请求中的签名参数字典，至少包含:
            {
                'X-Bogus': str,
                'a_bogus': str,
                'msToken': str,
                'verifyFp': str,
            }
            调用方将这些参数合并到原 params 后发起请求。
        """
        ...

    def generate_ms_token(self) -> str:
        """生成 msToken 参数值（随机 base64 字符串，128 位）。"""
        ...

    def generate_verify_fp(self) -> str:
        """生成 verify_fp / s_v_web_id 参数值。"""
        ...


# ---- 子模块接口（各为独立纯函数模块）----

class XBogusSigner:
    """X-Bogus 签名算法。

    输入：规范化后的请求 URL（含查询参数）+ User-Agent。
    输出：X-Bogus 签名字符串。
    """
    def sign(self, url: str, user_agent: str) -> str: ...


class ABogusSigner:
    """A_Bogus 签名算法（较新版本的签名参数）。

    输入：请求参数字典 + User-Agent + 设备信息。
    输出：a_bogus 签名字符串。
    """
    def sign(self, params: dict, user_agent: str) -> str: ...


class MsTokenGenerator:
    """msToken 生成器。

    msToken 为随机生成的 base64 字符串，无需服务端校验输入，
    但长度与字符集需符合抖音前端规律。
    """
    def generate(self) -> str: ...


class VerifyFpGenerator:
    """verify_fp / s_v_web_id 生成器。

    按抖音前端算法生成，格式形如 'verify_xxxxx'。
    """
    def generate(self) -> str: ...
```

> **维护策略**：签名算法是项目中最易失效的部分。`Signer` 作为聚合入口对外暴露稳定接口，内部子算法可独立更新。算法失效时仅需替换对应子模块实现，调用方代码不变。

### 3.3 VideoParser 接口

**职责**：根据 `aweme_id` 调用抖音 `aweme/v1/web/aweme/detail` 接口，解析出无水印直链、封面、作者、时长等元数据。

**所在文件**：`crawlers/video_parser.py`

**接口签名**：

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import Literal

VideoType = Literal["video", "image_set", "long_video"]


@dataclass(frozen=True)
class VideoInfo:
    """视频/图集解析结果。

    type 为 'video' 或 'long_video' 时，no_watermark_url 必填、image_urls 为空列表。
    type 为 'image_set' 时，image_urls 必填（至少 1 条）、no_watermark_url 为 None。
    """
    aweme_id: str
    type: VideoType
    title: str                          # 作品标题（无标题时为空字符串）
    author: str                         # 作者昵称
    author_sec_id: str                  # 作者 sec_user_id
    duration: str | None                # 时长展示文本，如 '15s' / '12:30'；图集为 None
    cover_url: str                      # 封面图 URL（列表缩略图用）
    no_watermark_url: str | None        # 无水印视频直链（图集为 None）
    image_urls: list[str]               # 图集原图直链列表（视频为空列表）
    publish_time: str | None            # 发布时间 ISO8601
    raw_json: dict                      # 原始 API 响应（调试/扩展用）


class VideoParser:
    """视频解析器。

    依赖 HttpClient（注入签名与 Cookie）调用抖音 detail 接口，
    从响应中提取无水印直链与元数据。
    """

    def __init__(self, http_client: "HttpClient", signer: "Signer") -> None: ...

    async def parse_video(self, aweme_id: str, cookie: str) -> VideoInfo:
        """解析单个作品信息。

        参数:
            aweme_id: 抖音作品 ID。
            cookie: 调用本次请求所用的 Cookie 字符串。

        返回:
            VideoInfo 数据结构。

        异常:
            VideoNotFoundError: 作品已删除/设为私密。
            CookieInvalidError: Cookie 失效（HTTP 461/412）。
            RateLimitedError: 触发限流。
            NetworkError: 网络异常。
        """
        ...
```

### 3.4 UserHomeCrawler 接口

**职责**：根据 `sec_user_id` 分页拉取用户主页作品列表，按过滤条件筛选后产出 `PostItem` 流。

**所在文件**：`crawlers/user_home_crawler.py`

**接口签名**：

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import AsyncIterator, Literal

HomeFilterType = Literal["all", "video", "image_set", "long_video"]


@dataclass(frozen=True)
class HomeFilters:
    """主页抓取过滤条件。

    count_limit 为 None 表示不设上限，拉取到无更多作品为止。
    date_from / date_to 为 None 表示不限制该端。
    """
    type_filter: HomeFilterType = "all"
    count_limit: int | None = None      # 数量上限，None 表示不限
    date_from: str | None = None        # 起始日期 ISO8601（含），如 '2026-01-01'
    date_to: str | None = None          # 结束日期 ISO8601（含）


@dataclass(frozen=True)
class PostItem:
    """主页作品列表项（轻量信息，供 UI 勾选）。

    与 VideoInfo 不同，PostItem 不含无水印直链——直链在用户勾选后
    由 VideoParser 二次调用 detail 接口获取。
    """
    aweme_id: str
    title: str
    author: str
    author_sec_id: str
    cover_url: str
    type: str                           # 'video' | 'image_set' | 'long_video'（基于 aweme_type 预判）
    create_time: str                    # ISO8601 发布时间
    duration: str | None                # 时长展示文本
    image_count: int | None             # 图集图片数


class UserHomeCrawler:
    """用户主页抓取器。

    调用 aweme/v1/web/aweme/post 接口分页拉取，使用 max_cursor 翻页。
    """

    def __init__(self, http_client: "HttpClient", signer: "Signer") -> None: ...

    async def fetch_user_posts(
        self,
        sec_user_id: str,
        cookie: str,
        filters: HomeFilters,
    ) -> AsyncIterator[PostItem]:
        """异步迭代产出符合过滤条件的作品。

        参数:
            sec_user_id: 用户主页 sec_user_id。
            cookie: 调用本次请求所用的 Cookie 字符串。
            filters: 过滤条件（类型/数量/时间段）。

        返回:
            异步迭代器，逐个 yield PostItem。调用方可用 `async for item in ...` 消费。

        异常:
            CookieInvalidError: Cookie 失效。
            RateLimitedError: 触发限流。
            NetworkError: 网络异常。
            UserNotFoundError: 用户不存在或主页不可见。
        """
        ...
        yield  # 仅占位表示生成器
```

### 3.5 HttpClient 接口

**职责**：封装 `httpx.AsyncClient` 单例，统一注入 Cookie、User-Agent、Referer、签名参数；管理 Cookie 池轮换与健康检查。

**所在文件**：`crawlers/http_client.py`

**接口签名**：

```python
from __future__ import annotations
from dataclasses import dataclass
import httpx
from typing import Literal

CookieStatus = Literal["valid", "invalid", "untested"]


@dataclass(frozen=True)
class CookieRecord:
    """Cookie 池中一条记录的内存表示。

    与 cookies 表一行对应，用于在爬虫层与数据层之间传递 Cookie 状态。
    """
    id: int
    content: str                        # Cookie 字符串
    label: str | None                   # 用户自定义标签
    status: CookieStatus
    last_used: str | None               # ISO8601
    last_check: str | None
    fail_count: int
    created_at: str


class HttpClient:
    """HTTP 客户端。

    封装 httpx.AsyncClient，提供统一请求入口与 Cookie 池管理。
    通过依赖注入接收 CookieRepository 以操作 Cookie 池。
    """

    def __init__(
        self,
        cookie_repository: "CookieRepository",
        signer: "Signer",
        timeout_connect: float = 10.0,
        timeout_read: float = 30.0,
    ) -> None: ...

    async def get(
        self,
        url: str,
        params: dict | None = None,
        use_cookie_pool: bool = True,
        cookie: str | None = None,
    ) -> httpx.Response:
        """发起 GET 请求，自动注入签名、Cookie、统一 Headers。

        参数:
            url: 请求 URL（不含查询参数）。
            params: 业务请求参数；本方法会自动追加签名参数。
            use_cookie_pool: 是否从 Cookie 池自动取 Cookie（默认 True）。
                为 False 时需提供 cookie 参数，或显式不带 Cookie 请求。
            cookie: 显式指定 Cookie（优先级高于池）。

        返回:
            httpx.Response。

        异常:
            CookieInvalidError: 池中所有 Cookie 均失效。
            NetworkError: 连接超时/DNS 失败等网络异常。
            RateLimitedError: HTTP 461/412 风控响应。
        """
        ...

    def get_cookie_from_pool(self) -> CookieRecord:
        """从 Cookie 池中按"最久未用优先"策略取一条 valid Cookie。

        策略:
            - 仅取 status='valid' 的记录
            - 按 last_used 升序，取最早使用的一条
            - 取到后立即更新 last_used 为当前时间

        异常:
            CookieInvalidError: 池中无可用 Cookie（全部 invalid 或池空）。
        """
        ...

    def report_cookie_fail(self, cookie_id: int) -> None:
        """上报某条 Cookie 请求失败。

        策略:
            - 该 Cookie fail_count += 1
            - 若 fail_count >= 3，置 status='invalid'
            - 连续失败计数：下次成功需显式调用 report_cookie_success 重置

        参数:
            cookie_id: 失败的 Cookie 记录 ID。
        """
        ...

    def report_cookie_success(self, cookie_id: int) -> None:
        """上报某条 Cookie 请求成功，重置 fail_count。

        参数:
            cookie_id: 成功的 Cookie 记录 ID。
        """
        ...
```

### 3.6 异常类层次结构

**所在文件**：`crawlers/exceptions.py`

**继承关系**：

```
BaseException
└── Exception
    └── DouyinCatcherError                    # 项目所有自定义异常的根
        ├── CrawlerError                      # 爬虫层异常基类
        │   ├── InvalidURLFormatError         # 链接格式无法识别
        │   ├── CookieInvalidError            # Cookie 失效或被风控
        │   ├── RateLimitedError              # 触发限流（HTTP 461/412）
        │   ├── VideoNotFoundError            # 作品已删除/私密
        │   ├── UserNotFoundError             # 用户主页不存在
        │   ├── VerifyRequiredError           # 触发滑块验证
        │   └── NetworkError                  # 网络异常（连接超时/DNS 失败）
        └── DownloaderError                   # 下载引擎异常基类
            ├── DownloadFailedError           # 下载失败（重试耗尽）
            ├── DiskFullError                 # 磁盘空间不足
            └── FileIOError                   # 文件读写错误
```

**接口签名**：

```python
from __future__ import annotations


class DouyinCatcherError(Exception):
    """项目所有自定义异常的根基类。

    所有自定义异常均继承自此，便于上层 `except DouyinCatcherError` 统一兜底。
    """
    pass


class CrawlerError(DouyinCatcherError):
    """爬虫层异常基类。"""
    pass


class InvalidURLFormatError(CrawlerError):
    """链接格式无法识别。

    触发场景: URLParser.extract_url 未找到 URL，或 identify_type 无法判断类型。
    用户提示: "无法识别该链接，请确认是抖音视频/主页链接"。
    """
    pass


class CookieInvalidError(CrawlerError):
    """Cookie 失效或被风控。

    触发场景:
        - HTTP 461/412 响应
        - Cookie 池无可用 Cookie
        - "测试 Cookie" 返回非 0 status_code
    用户提示: "Cookie 已失效，抖音需要重新登录验证"。
    上层行为: 跳转 Cookie 配置页。
    """
    pass


class RateLimitedError(CrawlerError):
    """触发抖音限流。

    触发场景: HTTP 429 或风控限流响应。
    用户提示: "请求过于频繁，请稍后重试"。
```

## 4. 下载引擎接口

下载引擎位于 `downloader/` 目录，负责并发下载、分块续传、失败重试、进度汇报。所有接口在工作线程（asyncio 事件循环）中调用。

### 4.1 Scheduler 接口

**职责**：维护待下载任务项队列，控制并发数（`asyncio.Semaphore`），处理暂停/恢复/批量操作。

**所在文件**：`downloader/scheduler.py`

**接口签名**：

### 4.2 Downloader 接口

**职责**：执行单个任务项的下载流程，包括 httpx Range 分块请求、写入 `.part` 文件、失败重试（指数退避）、完成重命名。

**所在文件**：`downloader/downloader.py`

**接口签名**：

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import Literal

DownloadResultStatus = Literal["completed", "failed", "paused"]


@dataclass(frozen=True)
class DownloadResult:
    """单项下载结果。

    status 为 'completed' 时 local_path 必填。
    status 为 'failed' 时 fail_reason 必填。
    status 为 'paused' 时表示被用户暂停（非异常）。
    """
    task_item_id: int
    status: DownloadResultStatus
    downloaded_bytes: int
    total_bytes: int
    local_path: str | None               # 完成后的本地文件路径
    fail_reason: str | None              # 失败原因
    retry_count: int                     # 最终重试次数


@dataclass(frozen=True)
class ProgressInfo:
    """单项下载进度信息。"""
    task_item_id: int
    downloaded_bytes: int
    total_bytes: int                     # 0 表示未知，此时百分比无法计算
    speed_bytes_per_sec: float           # 实时下载速度
    retry_count: int


class Downloader:
    """单项下载器。

    每个任务项对应一次 download 调用。图集类型在内部并发拉取多张图片，
    但对外仍呈现为单个 DownloadResult。
    """

    def __init__(
        self,
        http_client: "HttpClient",
        progress_reporter: "ProgressReporter",
        chunk_size: int = 1024 * 1024,   # 默认 1MB 分块
        max_retry: int = 3,
    ) -> None: ...

    async def download(self, task_item: "TaskItemRef") -> DownloadResult:
        """下载单个任务项。

        流程:
            1. 检查本地 .part 文件是否存在 → 读取已下载字节数
            2. 用 httpx 发 Range: bytes={downloaded_bytes}- 请求
            3. 流式接收，每收到 64KB 追加写入 .part 文件
            4. 每 5 秒或每 1MB 持久化一次 downloaded_bytes
            5. 完成后 .part 重命名为最终文件
            6. 失败时按 2^retry_count 秒指数退避重试，最多 3 次

        参数:
            task_item: 任务项引用。

        返回:
            DownloadResult。

        异常:
            DiskFullError: 磁盘空间不足。
            FileIOError: 文件读写错误。
            DownloadFailedError: 重试耗尽（被 Scheduler 捕获并记录 fail_reason）。
        """
        ...

    def get_progress(self, task_item_id: int) -> ProgressInfo:
        """查询指定任务项的实时进度。

        参数:
            task_item_id: 任务项 ID。

        返回:
            ProgressInfo。

        异常:
            KeyError: 该任务项不在当前下载池中。
        """
        ...
```

### 4.3 ProgressReporter 接口

**职责**：进度信号节流。下载引擎内部用 `asyncio.Queue` 缓存进度更新，专门协程每 500ms 批量发送一次 `progress_updated` 信号，避免高频信号淹没 UI 线程。

**所在文件**：`downloader/progress_reporter.py`

**接口签名**：

```python

    """

    def __init__(self, flush_interval_ms: int = 500) -> None: ...

        """
        ...

    def flush(self) -> None:
        """强制立即发送当前积累的所有进度更新，不等待节流周期。

        调用时机:

            - 应用即将退出时
            - 用户手动触发"刷新进度"
        """
        ...

    async def run(self) -> None:
        """内部节流协程主循环。

        每 flush_interval_ms 毫秒从 Queue 取最新值，批量发 Qt 信号。
        由 Scheduler.start() 启动，Scheduler.stop() 取消。
        """
        ...
```

## 5. 工作线程桥接接口

工作线程桥接层位于 `worker/` 目录，负责在 Qt 主线程与 asyncio 工作线程之间传递调用与信号。所有 UI 与后台的交互均通过本层完成，**禁止 UI 直接调用爬虫层/下载引擎的方法**。

### 5.1 AsyncWorker 类

**职责**：在后台线程中运行 asyncio 事件循环，将 UI 线程的同步调用桥接为异步任务，将工作线程的异步事件桥接为 Qt 信号。

**所在文件**：`worker/async_worker.py`

**接口签名**：

```python
from __future__ import annotations
import asyncio
import concurrent.futures
from typing import Coroutine, TypeVar
from PySide6.QtCore import QObject

T = TypeVar("T")


class AsyncWorker(QObject):
    """后台工作线程桥接器。

    内部维护:
        - 一个 asyncio 事件循环（跑在独立线程）
        - 所有 Qt 信号定义（见 5.2）
        - Scheduler / VideoParser / UserHomeCrawler 等组件的实例

    UI 线程通过 submit() 提交协程，通过 Qt 信号接收结果。
    """

    def __init__(self) -> None: ...

    def start(self) -> None:
        """启动后台工作线程与 asyncio 事件循环。

        行为:
            - 创建并启动后台线程
            - 在后台线程中创建 asyncio 事件循环
            - 初始化 Scheduler、爬虫组件等
            - 调用 Scheduler.start()

        调用时机: 应用启动后，主窗口显示前。
        """
        ...

    def stop(self) -> None:
        """停止后台工作线程。

        行为:
            - 调用 Scheduler.stop()
            - 取消所有未完成的 asyncio.Task
            - 停止事件循环
            - 等待后台线程退出

        调用时机: 应用退出时（QApplication.aboutToQuit 信号）。
        """
        ...

    def submit(self, coro: Coroutine[..., ..., T]) -> concurrent.futures.Future:
        """提交协程到工作线程的事件循环。

        参数:
            coro: 待执行的协程对象。

        返回:
            concurrent.futures.Future，UI 线程可据此同步等待结果或添加回调。
            通常 UI 不直接 await Future，而是通过 Qt 信号接收异步结果。

        说明:
            本方法是线程安全的，可从 UI 线程调用。
            内部使用 asyncio.run_coroutine_threadsafe。
        """
        ...
```

### 5.2 信号定义

所有信号定义在 `AsyncWorker` 类上（作为类属性）。信号分两个方向：

#### 5.2.1 工作线程 → UI 方向（结果回传）

| 信号名称 | 参数类型 | 触发时机 | 接收方 |
|---|---|---|---|
| `progress_updated` | `(int, int, int)` — `(task_item_id, downloaded_bytes, total_bytes)` | 下载进度更新（节流后批量发送） | 下载任务页：更新进度条 |
| `item_completed` | `(int,)` — `(task_item_id,)` | 单个任务项下载完成 | 下载任务页：行状态置为完成（绿色） |
| `item_failed` | `(int, str)` — `(task_item_id, fail_reason)` | 单个任务项下载失败 | 下载任务页：行状态置为失败（红色），行下方显示失败原因 |
| `cookie_invalid` | `(int,)` — `(cookie_id,)` | 某条 Cookie 被标记为失效 | Cookie 配置页：状态指示灯变红；若池空则弹窗提示 |
| `task_completed` | `(int,)` — `(task_id,)` | 整个任务（含所有子项）完成 | 下载任务页：底部状态栏更新计数 |
| `parse_progress` | `(int, int)` — `(parsed_count, total_count)` | 链接抓取页解析进度（已解析数/总数） | 链接抓取页：更新解析进度条 |
| `parse_completed` | `(list,)` — `(post_items,)` | 链接抓取页解析完成 | 链接抓取页：渲染解析结果列表 |
| `parse_failed` | `(str,)` — `(error_message,)` | 链接抓取页解析失败 | 链接抓取页：显示错误提示 |

**PySide6 信号声明形式**：

```python
from PySide6.QtCore import Signal

class AsyncWorker(QObject):
    # ---- 工作线程 → UI 方向 ----
    progress_updated = Signal(int, int, int)   # task_item_id, downloaded_bytes, total_bytes
    item_completed = Signal(int)               # task_item_id
    item_failed = Signal(int, str)             # task_item_id, fail_reason
    cookie_invalid = Signal(int)               # cookie_id
    task_completed = Signal(int)               # task_id
    parse_progress = Signal(int, int)          # parsed_count, total_count
    parse_completed = Signal(list)             # list[PostItem]
    parse_failed = Signal(str)                 # error_message
    ...
```

#### 5.2.2 UI → 工作线程方向（操作指令）

| 信号名称 | 参数类型 | 触发时机 | 接收方（工作线程内处理） |
|---|---|---|---|
| `start_download` | `(list,)` — `(task_items,)` | 用户在链接抓取页点"开始下载"，解析结果勾选完成 | 工作线程：创建 task + task_items 记录，加入 Scheduler 队列 |
| `pause_download` | `(int,)` — `(task_item_id,)` | 用户点任务行"暂停"按钮 | Scheduler.pause(task_item_id) |
| `resume_download` | `(int,)` — `(task_item_id,)` | 用户点任务行"开始"按钮（暂停态） | Scheduler.resume(task_item_id) |
| `pause_all` | `()` | 用户点顶部"全部暂停" | Scheduler.pause_all() |
| `resume_all` | `()` | 用户点顶部"全部开始" | Scheduler.resume_all() |
| `start_parse` | `(list,)` — `(urls,)` | 用户在链接抓取页点"开始解析" | 工作线程：调用 URLParser + VideoParser/UserHomeCrawler |
| `cancel_parse` | `()` | 用户点解析中的"取消"按钮 | 工作线程：取消正在进行的解析 asyncio.Task |

**PySide6 信号声明形式**：

```python
class AsyncWorker(QObject):
    # ---- UI → 工作线程方向 ----
    start_download = Signal(list)              # list[TaskItemRef]
    pause_download = Signal(int)               # task_item_id
    resume_download = Signal(int)              # task_item_id
    pause_all = Signal()
    resume_all = Signal()
    start_parse = Signal(list)                 # list[str] 待解析的 URL 文本列表
    cancel_parse = Signal()
    ...
```

> **信号绑定约定**：
> - UI 线程发信号 → 工作线程：`worker_signal.connect(worker._on_xxx)`，槽函数在工作线程执行（需通过 `submit` 桥接到 asyncio loop）。
> - 工作线程发信号 → UI 线程：`worker.xxx_signal.connect(ui_handler)`，Qt 自动跨线程派发到 UI 线程执行。
> - 所有信号传递的参数类型必须为 Qt 元类型兼容类型（int、str、list、tuple），**禁止直接传递 Python 自定义对象**（如需传递复杂对象，序列化为 dict 后用 `Signal(list)` 或 `Signal(dict)`）。

## 7. 抖音 Web API 调用规范

本章定义本项目调用抖音 Web API 时的请求/响应契约。所有调用经 `HttpClient` 发起，签名参数由 `Signer` 生成。

### 7.1 aweme/v1/web/aweme/detail 接口

**用途**：根据 `aweme_id` 获取单个作品详情（视频/图集/长视频通用）。

**调用方**：`VideoParser.parse_video()`

**请求规范**：

| 项目 | 内容 |
|---|---|
| 请求方法 | GET |
| URL | `https://www.douyin.com/aweme/v1/web/aweme/detail/` |
| 协议 | HTTPS |
| HTTP 版本 | HTTP/2（httpx[http2]） |

**必需请求头**：

| Header | 值 |
|---|---|
| User-Agent | Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ... Chrome/xxx Safari/537.36 |
| Referer | https://www.douyin.com/ |
| Cookie | 由 HttpClient 从 Cookie 池注入 |
| Accept | application/json, text/plain, */* |

**必需查询参数**：

| 参数 | 必需 | 说明 |
|---|---|---|
| `aweme_id` | 是 | 抖音作品 ID |
| `aid` | 是 | 固定值 `6383` |
| `device_platform` | 是 | 固定值 `webapp` |
| `channel` | 是 | 固定值 `channel_pc_web` |
| `version_code` | 是 | 固定值 `170400` |
| `Cookie` | 是 | 通过 Header 传递（非 query 参数） |

**签名要求**：

| 签名参数 | 生成方 | 说明 |
|---|---|---|
| `X-Bogus` | `XBogusSigner.sign(url, user_agent)` | 基于 URL + UA 计算 |
| `a_bogus` | `ABogusSigner.sign(params, user_agent)` | 基于参数 + UA 计算 |
| `msToken` | `MsTokenGenerator.generate()` | 随机 base64 |
| `verifyFp` | `VerifyFpGenerator.generate()` | 形如 `verify_xxxxx` |

签名参数由 `Signer.sign()` 聚合生成后追加到查询参数中。

**Cookie 要求**：
- 必须包含有效的 `ttwid`、`msToken`、`passport_csrf_token` 等字段
- Cookie 失效时返回 HTTP 461/412，由 HttpClient 上报 `CookieInvalidError`

**响应结构**（JSON，关键字段路径）：

```jsonc
{
  "status_code": 0,                      // 0 表示成功，非 0 表示 API 层错误
  "status_msg": "...",
  "aweme_detail": {
    "aweme_id": "7xxxxxxxxxxxxxx",
    "desc": "作品标题/文案",
    "create_time": 1700000000,           // Unix 时间戳
    "duration": 15000,                   // 毫秒，图集为 0
    "aweme_type": 0,                     // 0=视频，68/150=图集，其他类型见映射表
    "author": {
      "nickname": "作者昵称",
      "sec_uid": "作者 sec_user_id",
      "uid": "作者 uid"
    },
    "video": {
      "play_addr": {
        "url_list": [                    // 无水印视频直链（取首个）
          "https://..."
        ],
        "duration": 15000
      },
      "cover": {
        "url_list": [                    // 封面图 URL（取首个）
          "https://..."
        ]
      },
      "duration": 15000
    },
    "images": [                          // 图集类型才有此字段
      {
        "url_list": [                    // 原图直链（取首个）
          "https://..."
        ]
      }
      // ... 多张图片
    ],
    "statistics": {
      "digg_count": 1234,                // 点赞数
      "comment_count": 56,
      "share_count": 78,
      "collect_count": 90
    },
    "text_extra": [                      // 标签信息
      { "hashtag_name": "旅行" }
    ]
  }
}
```

**字段提取规则**：

| VideoInfo 字段 | 响应路径 | 转换规则 |
|---|---|---|
| `aweme_id` | `aweme_detail.aweme_id` | 直接取 |
| `type` | `aweme_detail.aweme_type` + `aweme_detail.images` | aweme_type=0 且无 images → 'video'；有 images → 'image_set'；duration > 60000 → 'long_video' |
| `title` | `aweme_detail.desc` | 直接取，无值时为空字符串 |
| `author` | `aweme_detail.author.nickname` | 直接取 |
| `author_sec_id` | `aweme_detail.author.sec_uid` | 直接取 |
| `duration` | `aweme_detail.video.duration` | 毫秒转 'MM:SS' 或 'Xs' |
| `cover_url` | `aweme_detail.video.cover.url_list[0]` | 取首个 |
| `no_watermark_url` | `aweme_detail.video.play_addr.url_list[0]` | 取首个；或替换 `playwm` → `play` |
| `image_urls` | `aweme_detail.images[*].url_list[0]` | 取每张图的首个 URL，组成列表 |
| `publish_time` | `aweme_detail.create_time` | Unix 时间戳转 ISO8601 |

**错误响应处理**：

| 响应特征 | 判断 | 抛出异常 |
|---|---|---|
| HTTP 461 / 412 | Cookie 失效或被限流 | `CookieInvalidError` |
| HTTP 429 | 限流 | `RateLimitedError` |
| HTTP 200 + `status_code != 0` 且错误码表明作品不存在 | 作品已删除/私密 | `VideoNotFoundError` |
| HTTP 200 + 响应含滑动验证 HTML | 触发验证 | `VerifyRequiredError` |
| 网络超时/DNS 失败 | 网络异常 | `NetworkError` |

```jsonc
      "aweme_type": 0,                   // 0=视频，68/150=图集
      "author": {
        "nickname": "作者昵称",
        "sec_uid": "作者 sec_user_id"
      },
      "video": {
        "cover": {

        },
        "duration": 15000
      },
```

**字段提取规则（PostItem）**：

| PostItem 字段 | 响应路径 | 转换规则 |
|---|---|---|
| `aweme_id` | `aweme_list[i].aweme_id` | 直接取 |
| `title` | `aweme_list[i].desc` | 直接取 |
| `author` | `aweme_list[i].author.nickname` | 直接取 |

## 8. 接口版本管理

### 8.1 接口变更原则

| 原则 | 说明 |
|---|---|
| **签名稳定性** | 已发布的公共接口签名（方法名、参数名、参数顺序、返回类型）不得在不兼容方式下变更 |
| **新增优先** | 需扩展功能时优先新增方法/参数（带默认值），而非修改已有签名 |
| **废弃流程** | 旧接口标记 `@deprecated` 并在文档注明，保留至少一个版本周期后再移除 |
| **文档同步** | 任何接口变更必须同步更新本文档及对应章节的修订记录 |
| **测试守护** | 接口变更必须附带对应测试更新，确保 CI 通过 |

### 8.2 向后兼容策略

| 变更类型 | 兼容性 | 处理策略 |
|---|---|---|
| 新增接口方法 | 兼容 | 直接新增，无需迁移 |
| 新增可选参数（带默认值） | 兼容 | 直接新增，旧调用方无需修改 |
| 新增返回字段（dataclass 字段） | 兼容 | 直接新增，旧消费方忽略新字段 |
| 修改参数类型 | **不兼容** | 必须新增新方法（如 `parse_v2`），旧方法保留并标记废弃 |
| 修改返回类型 | **不兼容** | 同上，新增新方法 |
| 删除接口方法 | **不兼容** | 先标记废弃，下一个大版本移除 |
| 修改信号参数 | **不兼容** | 新增信号（如 `progress_updated_v2`），旧信号保留 |
| 数据库 schema 变更 | 通过迁移 | `Database.migrate()` 逐步迁移，保留旧数据 |

**版本号规则**：
- 本文档版本号 `v1.0` 对应应用首版
- 接口不兼容变更时，文档主版本号 +1（如 `v2.0`）
- 接口兼容扩展时，文档次版本号 +1（如 `v1.1`）
- 数据库 schema 版本独立维护，记录在 `config` 表 `schema_version` 键

**异常分类与处理策略汇总表**：

| 异常类型 | 产生层 | 是否重试 | 最终处理 | UI 展示位置 | 用户提示 |
|---|---|---|---|---|---|
| `InvalidURLFormatError` | URLParser | 否 | 标记解析失败 | 输入框下方红字 | 无法识别该链接 |
| `CookieInvalidError` | HttpClient | 否 | 标记失败 + 切换 Cookie | Cookie 配置页 + 弹窗 | Cookie 失效，需更新 |
| `RateLimitedError` | HttpClient | 否 | 标记失败 | 任务行下方 | 请求频繁，稍后重试 |
| `VideoNotFoundError` | VideoParser | 否 | 标记失败 | 任务行下方 | 作品已删除/私密 |
| `UserNotFoundError` | UserHomeCrawler | 否 | 标记解析失败 | 解析结果区 | 用户主页不存在 |
| `VerifyRequiredError` | HttpClient | 否 | 标记失败 | 任务行下方 | 触发安全验证 |
| `NetworkError` | HttpClient | 是（≤3 次） | 重试或标记失败 | 任务行下方 | 网络连接失败 |
| `DownloadFailedError` | Downloader | 否（已耗尽） | 标记失败 | 任务行下方 | 下载失败，已重试 3 次 |
| `DiskFullError` | Downloader | 否 | 暂停所有任务 | 全局弹窗 | 磁盘空间不足 |
| `FileIOError` | Downloader | 否 | 标记失败 | 任务行下方 | 文件读写失败 |
