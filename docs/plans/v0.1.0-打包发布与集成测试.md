## 4. 设计依据与技术约束

### 4.1 打包配置依据（设计文档 8.4 节）

PyInstaller `--onedir` 模式（启动快于 onefile）：

```
PyInstaller --onedir --windowed --name DouyinCatcher
            --icon assets/icon.ico
            --add-data "ui/assets;ui/assets"
            --add-data "assets;assets"
            main.py
```

产物：`dist/DouyinCatcher/` 目录（含 exe + 依赖），用 Inno Setup 打成安装包。

### 4.2 运行时数据位置依据（设计文档 2.5 节）

- 程序目录只放代码和资源
- 用户数据放 `%APPDATA%/DouyinCatcher/`：
  - `data.db` — SQLite 数据库
  - `logs/app.log` — 日志（按天滚动，保留 7 天）
- **卸载/重装不丢用户数据**（安装脚本需保证 `%APPDATA%` 不被清理）

### 4.3 测试 Cookie 使用规范依据（设计文档 9.1 节、规范文档 6.1 节）

- 测试所需 Cookie **由用户提供，不硬编码、不提交到仓库**
- 测试用 Cookie 存放在本地 `.env` 文件（已加入 `.gitignore`）
- **测试全流程完成后必须清除**：测试脚本结束前主动删除 Cookie 痕迹
- VCR.py 录制的响应 fixture 在提交前需人工核对，确保不含敏感 Cookie 字段

### 4.4 覆盖率要求依据（设计文档 9.2 节、规范文档 6.2 节）

| 指标 | 要求 |
|---|---|
| 全局代码行覆盖率 | **≥ 80%** |
| 全局方法覆盖率 | **≥ 30%** |
| 签名算法模块 `crawlers/signer/` | 行覆盖率 **≥ 90%** |
| 下载引擎 `downloader/` | 行覆盖率 **≥ 80%** |
| 爬虫层 `crawlers/` | 行覆盖率 **≥ 75%** |
| 数据层 `app/` | 行覆盖率 **≥ 80%** |
| 工作线程 `worker/` | 行覆盖率 **≥ 80%** |
| UI 层 `ui/` | **不强制**（Qt 组件难单测，重点靠手动验收） |

覆盖率工具：`pytest-cov`，配置在 `pyproject.toml`：

```toml
[tool.pytest.ini_options]
addopts = "--cov=. --cov-report=term-missing --cov-report=html --cov-fail-under=80"
```

### 4.5 版本号规范依据（规范文档 8.3 节）

- 本里程碑版本号：**0.1.0**（开发阶段，主版本号 0 表示不稳定）
- 版本号需在以下位置同步更新：
  - `pyproject.toml` 的 `version` 字段
  - `installer.iss` 的 `AppVersion` 字段
  - 应用"关于"页面显示
  - Git tag `v0.1.0`

### 4.6 Inno Setup 安装脚本依据（规范文档 8.2 节、附录 E）

- 完整脚本草案见规范文档附录 E，本里程碑给出关键配置项并完成定制
- `AppId` 为固定 GUID，发布后不可更改（影响升级识别）
- 卸载时不删除 `%APPDATA%/DouyinCatcher/`（用户数据保留）
- 中文语言包需 Inno Setup 安装时勾选

### 4.7 发布检查清单依据（规范文档 8.4 节）

发布检查分为三个阶段：
1. 打包前检查：测试通过、代码检查、覆盖率、安全扫描、版本号
2. 打包后检查：产物可启动、资源加载、数据库/日志路径正确
3. 发布前检查：干净环境测试、Release Notes、附件齐全

### 任务 1：PyInstaller 打包配置

#### 1.1 目标

创建 `.spec` 文件管理 PyInstaller 打包配置，便于版本控制与复杂配置。打包后产物为 `dist/DouyinCatcher/` 目录，含 `DouyinCatcher.exe` + 依赖 DLL + 资源文件。严格遵循设计文档 8.4 节与规范文档 8.1 节。

#### 1.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `DouyinCatcher.spec` | 新建 | PyInstaller 打包配置文件（.spec） |
| `pyproject.toml` | 修改 | 确认 `version = "0.1.0"` |
| `assets/icon.ico` | 确认就位 | 应用图标（前序里程碑已创建，确认非占位） |

#### 1.3 .spec 文件配置项

**`[Setup]` 段关键配置**（严格按规范文档 8.1.2 节）：

| 配置项 | 值 | 说明 |
|---|---|---|
| `Analysis.scripts` | `['main.py']` | 入口脚本 |
| `Analysis.datas` | `[('ui/assets', 'ui/assets'), ('assets', 'assets')]` | 附加资源：UI 资源目录与应用图标目录 |
| `Analysis.hiddenimports` | 见 1.4 节 | 隐式导入模块列表 |
| `Analysis.excludes` | 见 1.5 节 | 排除的模块列表（减小体积） |
| `EXE.name` | `'DouyinCatcher'` | 产物名称 |
| `EXE.console` | `False` | 无控制台窗口（`--windowed`） |
| `EXE.icon` | `'assets/icon.ico'` | 应用图标 |
| `EXE.upx` | `True` | 启用 UPX 压缩（减小体积） |
| `COLLECT.name` | `'DouyinCatcher'` | onedir 模式目录名 |

#### 1.4 hiddenimports 清单

PyInstaller 静态分析可能漏掉的动态导入模块，需显式声明：

| 模块 | 说明 |
|---|---|
| `PySide6.QtWidgets` | Qt 控件模块 |
| `PySide6.QtCore` | Qt 核心模块（信号/槽、事件循环） |
| `PySide6.QtGui` | Qt GUI 模块（图标、字体、画布） |
| `httpx` | HTTP 客户端主模块 |
| `httpx._core` | httpx 内部核心（如有） |
| `h2` | httpx[http2] 的 HTTP/2 依赖 |
| `hpack` | h2 的 HPACK 头部压缩依赖 |
| `hyperframe` | h2 的帧处理依赖 |

> **说明**：PySide6 与 httpx 的子模块由 PyInstaller 的内置 hook 自动处理大部分，但 http2 相关依赖（h2/hpack/hyperframe）需显式声明，避免运行时 ImportError。

#### 1.5 excludes 清单（排除不必要的大依赖）

排除测试专用依赖与未使用的模块，减小安装包体积：

| 排除模块 | 说明 |
|---|---|
| `pytest` | 测试框架（运行时不需要） |
| `pytest_asyncio` | 异步测试插件 |
| `pytest_cov` | 覆盖率插件 |
| `vcrpy` | VCR.py 录制工具 |
| `respx` | httpx mock 工具 |
| `ruff` | Lint 工具 |
| `black` | 格式化工具 |
| `mypy` | 类型检查工具（如安装） |
| `pip` | 包管理器（运行时不需要） |
| `setuptools` | 构建工具（运行时不需要） |
| `wheel` | 构建工具 |

#### 1.6 打包执行步骤

1. **确认前置条件**：
   - `main.py` 可正常 `python main.py` 启动
   - `assets/icon.ico` 存在且为有效 ico 文件
   - `ui/assets/style.qss` 存在
   - `ui/assets/cookie_tutorial/step1.png ~ step7.png` 存在
   - `pyproject.toml` 版本号为 `0.1.0`

2. **安装 PyInstaller**：
   - 命令：`pip install pyinstaller`

3. **执行打包**：
   - 命令：`pyinstaller DouyinCatcher.spec --noconfirm`
   - `--noconfirm`：覆盖上次构建产物

4. **验证产物**：
   - 检查 `dist/DouyinCatcher/DouyinCatcher.exe` 存在
   - 检查 `dist/DouyinCatcher/_internal/ui/assets/style.qss` 存在（资源打包成功）
   - 检查 `dist/DouyinCatcher/_internal/ui/assets/cookie_tutorial/step1.png` 存在
   - 检查 `dist/DouyinCatcher/_internal/assets/icon.ico` 存在
   - 双击 `DouyinCatcher.exe` 能正常启动应用

5. **体积检查**：
   - 查看 `dist/DouyinCatcher/` 目录总大小
   - 目标：60-80MB（设计文档 2.1 节）
   - 若超出 100MB，需审查 excludes 是否遗漏，或用 UPX 压缩

#### 1.7 常见问题排查

| 问题 | 排查方向 |
|---|---|
| 启动报 `ModuleNotFoundError: No module named 'xxx'` | 将 xxx 加入 `hiddenimports` |
| QSS 样式未加载 | 检查 `datas` 中 `ui/assets` 路径，确认运行时路径解析正确（`sys._MEIPASS` 或 `_internal`） |
| Cookie 教程图片不显示 | 检查 `ui/assets/cookie_tutorial/` 是否打包进 `datas` |
| 图标不显示 | 检查 `assets/icon.ico` 是否打包，EXE.icon 路径是否正确 |
| 体积过大 | 检查 `excludes` 是否生效，用 UPX 压缩，审查是否有未使用的大依赖被拉入 |

### 任务 5：性能测试

#### 5.1 目标

验证应用在并发下载、大量任务、长时间运行、高频进度更新等场景下的性能表现，确保 UI 不卡顿、内存无泄漏。性能测试不设硬性阈值，但需记录数据并确保无严重问题。

#### 5.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `tests/test_e2e/test_performance.py` | 新建 | 性能测试用例 |

#### 5.3 测试场景

##### 场景 1：并发下载性能

**测试函数**：`test_concurrency_performance`

**测试步骤**：
1. 准备 N 个单视频链接（可用 mock 直链，避免真实 API 限流）
2. 分别测试并发数 = 3 / 5 / 10
3. 对每个并发数：
   - 配置 `Scheduler(max_concurrent=N)`
   - 入队 N 个任务项（mock httpx 返回固定大小数据流）
   - 记录总下载时间
   - 记录峰值内存占用
4. 输出对比数据：
   - 并发 3：总耗时 Xs，峰值内存 Y MB
   - 并发 5：总耗时 Xs，峰值内存 Y MB
   - 并发 10：总耗时 Xs，峰值内存 Y MB
5. 验证：
   - 并发数越高，总耗时越短（但有边际递减）
   - 峰值内存不超过合理范围（如 < 500MB）
   - 无死锁、无崩溃

##### 场景 2：大量任务列表渲染性能

**测试函数**：`test_large_task_list_performance`

**测试步骤**：
1. 在 SQLite 中插入 100 个 `task_items` 记录（mock 数据，不同状态）
2. 启动应用，切换到下载任务页
3. 测量列表渲染时间（从加载到 UI 响应）
4. 验证：
   - 渲染时间 < 2 秒（可接受范围）
   - 滚动流畅（无明显卡顿）
   - 进度条更新不阻塞 UI
5. 如使用 `QListView` + 模型/视图架构，验证只刷新可见行

##### 场景 3：长时间运行内存占用

**测试函数**：`test_long_run_memory_growth`

**测试步骤**：
1. 启动应用，记录初始内存占用（`psutil.Process().memory_info().rss`）
2. 持续运行 1 小时，期间：
   - 每 5 分钟提交一批下载任务（mock）
   - 每 5 分钟执行一次链接解析
   - 每 5 分钟切换页面
3. 每 10 分钟记录内存占用
4. 1 小时后：
   - 记录最终内存占用
   - 计算内存增长率
5. 验证：
   - 内存增长 < 50MB（无严重泄漏）
   - 若增长明显，需排查是否有引用未释放
6. **注意**：此测试耗时长，标记 `@pytest.mark.slow`

##### 场景 4：高频进度更新 UI 响应

**测试函数**：`test_high_frequency_progress_ui_response`

**测试步骤**：
1. 启动应用，切换到下载任务页，入队 5 个下载任务
2. 用 mock httpx 高速返回数据流（模拟高速下载）
3. 测量：
   - 进度更新频率（`ProgressReporter` 节流后实际 UI 更新频率）
   - UI 响应延迟（鼠标点击到响应的时间）
4. 验证：
   - `ProgressReporter` 节流生效（500ms 批量更新，而非每 64KB 更新）
   - UI 响应延迟 < 200ms（无明显卡顿）
   - 进度条动画流畅

#### 5.4 性能测试约束

- **mock 优先**：性能测试尽量用 mock httpx 响应，避免真实 API 限流影响数据
- **可重复**：测试环境尽量一致（关闭其他大型程序）
- **记录数据**：性能数据记录到测试报告，供后续版本对比
- **无硬性阈值**：本里程碑性能测试以"无严重问题"为目标，不阻断发布（除非有明显卡顿或泄漏）

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 签名算法可能已失效 | 端到端测试与签名验证失败，无法下载 | 1. 用真实 Cookie 验证签名有效性（任务 3.6）；2. 若失效，启动应急更新流程（规范文档 10.3 节）；3. 失效不阻断 v0.1.0 发布，但在 Release Notes 中标注已知限制 |
| PyInstaller 打包遇到 hidden imports 问题 | 打包后启动报 `ModuleNotFoundError` | 1. .spec 文件中显式声明 hiddenimports（PySide6、httpx、h2 等）；2. 启动失败时根据报错逐步补充；3. 参考 PyInstaller 官方 hook 配置 |
| 端到端测试依赖真实抖音 API，可能遇到风控 | 测试失败或测试账号被封 | 1. 测试用 Cookie 由开发者个人账号提供，不用生产账号；2. 控制请求频率，避免高频触发风控；3. 测试后立即清除 Cookie；4. 风控导致的测试失败不阻断发布 |
| 安装包体积偏大 | 超出 60-80MB 目标，用户体验差 | 1. .spec 文件 excludes 排除测试依赖（pytest/vcrpy/respx 等）；2. 启用 UPX 压缩；3. 审查是否有未使用的大依赖被拉入；4. 必要时用 `pyinstaller --exclude-module` 逐个排查 |
| Inno Setup 中文语言包缺失 | 安装向导显示英文 | 1. Inno Setup 安装时勾选 Chinese Simplified；2. 或手动下载 `ChineseSimplified.isl` 放入 `compiler:Languages\` |
| PySide6 打包后 Qt 插件缺失 | UI 样式异常或图片格式不支持 | 1. 确认 PyInstaller 的 PySide6 hook 正确处理 Qt 插件；2. 必要时手动添加 Qt 插件到 `binaries` |
| 干净虚拟机缺少 Visual C++ 运行时 | 应用启动报 DLL 缺失 | 1. PyInstaller 通常会打包所需 VC 运行时；2. 若缺失，在 Release Notes 中提示安装 VC Redistributable；3. 或在安装包中集成 VC 运行时 |

### 8.2 实现注意事项

1. **版本号一致性**：`pyproject.toml`、`installer.iss`、应用"关于"页面的版本号必须一致（0.1.0）
2. **资源路径**：打包后资源位于 `sys._MEIPASS`（onedir 模式为 `_internal`），代码中需用 `Path(__file__).parent` 或 `sys._MEIPASS` 正确解析资源路径，避免硬编码相对路径
3. **.env 排除**：`.env` 文件含真实 Cookie，**必须确认**不在 `datas` 中、不被打包进安装包
4. **AppId 固定**：Inno Setup 的 `AppId` 生成后**不可更改**，否则系统无法识别为升级（影响后续版本）
5. **用户数据保留**：卸载只清理 `{app}`（Program Files），**不清理** `%APPDATA%/DouyinCatcher/`，需在卸载测试中显式验证
6. **Cookie 清除**：端到端测试结束后**必须清除**所有 Cookie 痕迹（`.env`、临时数据库、临时文件）
7. **签名算法验证**：若签名算法失效，**不强制阻断 v0.1.0 发布**，但需在 Release Notes 中诚实标注已知限制
8. **性能测试数据**：性能数据应记录到测试报告，供后续版本对比，但不作为发布阻断条件
