## 1. 里程碑信息

### 1.1 目标

实现爬虫组件层的「链接解析」与「HTTP 客户端」两大基础组件，并打通 Cookie 池轮询与风控响应处理链路，为后续 v0.0.4 的视频解析器、主页抓取器提供统一的请求出口与链接解析能力。

### 1.2 范围边界

| 类别 | 内容 |
|---|---|
| **本里程碑交付** | URLParser、HttpClient、Cookie 池管理逻辑、风控响应处理、对应单元测试与 fixture |
| **不属于本里程碑** | VideoParser、UserHomeCrawler（v0.0.4）；下载引擎（v0.0.5）；UI 层；签名算法本身（v0.0.2 已完成）；数据层本身（v0.0.1 已完成） |
| **复用前置成果** | `CookieRepository`、`Cookie` 数据模型（v0.0.1）；`Signer.sign()` 接口（v0.0.2） |

### 1.3 关键设计约束

- **不依赖真实抖音 API**：所有测试用 mock（respx）与录制回放（VCR.py），不硬编码 Cookie。
- **接口签名稳定性**：URLParser、HttpClient 的公开方法签名必须与 `05-接口设计文档.md` 第 3.1、3.5 节保持一致，便于 v0.0.4 直接接入。
- **单向依赖**：`crawlers/` 仅依赖 `app/`（数据层）与 `crawlers/signer/`（签名层），不得反向依赖 `downloader/`、`worker/`、`ui/`。
- **HTTP/2**：HttpClient 必须启用 httpx 的 HTTP/2 支持（`httpx.AsyncClient(http2=True)`）。

## 2. 任务清单

### 任务 1：链接解析器（`crawlers/url_parser.py`）

**目标**：实现 `URLParser` 类与 `ParsedURL` dataclass，从用户粘贴的分享文本中提取抖音链接、跟随短链重定向、识别链接类型。

#### 1.1 `ParsedURL` dataclass

- **定义位置**：`crawlers/url_parser.py` 顶部
- **字段**（与接口文档 3.1 节一致）：
  - `type: LinkType` — `'video' | 'image_set' | 'long_video' | 'user_home'`
  - `url: str` — 规范化后的最终 URL（跟随重定向后）
  - `aweme_id: str | None` — 视频/图文/长视频作品 ID
  - `sec_user_id: str | None` — 用户主页 sec_user_id
  - `original_text: str` — 用户输入的原始文本（调试用）
- **约束**：使用 `@dataclass(frozen=True)`，跨层传递不可变。

#### 1.2 `LinkType` 类型别名

- 定义 `LinkType = Literal["video", "image_set", "long_video", "user_home"]`。
- 注：`image_set` 与 `long_video` 的最终判定依赖 v0.0.4 的 VideoParser 调用 detail 接口；URLParser 仅在能从 URL 直接判断时给出预判，否则默认归为 `'video'`。

#### 1.3 `URLParser` 类

**构造函数**：
- `__init__(self, http_client: "HttpClient") -> None`
  - 注入 HttpClient 用于跟随短链重定向。
  - 纯逻辑组件，不持有网络连接自身。

**方法 1：`parse(text: str) -> ParsedURL`**
- 完整解析流程的编排方法。
- 流程：
  1. 调用 `extract_url(text)` 提取 URL；若返回 None，抛 `InvalidURLFormatError`。
  2. 若 URL 为 `v.douyin.com` 短链，调用 `follow_redirect(url)` 获取最终 URL。
  3. 调用 `identify_type(final_url)` 识别类型。
  4. 根据类型从 URL 中解析 `aweme_id` 或 `sec_user_id`（用 `urllib.parse` 解析 query 与 path）。
  5. 构造并返回 `ParsedURL`。
- **异常**：`InvalidURLFormatError`（文本无可识别链接）。

**方法 2：`extract_url(text: str) -> str | None`**
- 纯函数，从任意文本中提取第一个抖音链接。
- 支持识别的输入格式：
  - 抖音短链：`https://v.douyin.com/xxxxx/`
  - 抖音长链（视频）：`https://www.douyin.com/video/{aweme_id}`
  - 抖音长链（主页）：`https://www.douyin.com/user/{sec_user_id}`
  - 分享口令（含中文描述，如「xx.xx 复制打开抖音...https://v.douyin.com/xxx/」）
  - 多链接文本（取第一个）
- 实现方式：预编译正则 `re.Pattern`，匹配 `https?://[^\s，。、]+` 后过滤 douyin 域名。
- **返回**：URL 字符串；未找到返回 `None`。

**方法 3：`identify_type(url: str) -> LinkType`**
- 根据 URL 路径与查询参数识别类型。
- 识别规则（按优先级）：
  1. 路径含 `/user/` 或查询参数含 `sec_user_id` → `'user_home'`
  2. 路径含 `/video/` 或查询参数含 `aweme_id` → `'video'`（具体子类型由 VideoParser 最终判定）
  3. 其他情况 → 抛 `InvalidURLFormatError`
- 注：本里程碑不区分 `image_set` / `long_video`，统一归 `'video'`，留给 v0.0.4 的 VideoParser 在拿到 detail 响应后细化。

**方法 4：`follow_redirect(short_url: str) -> str`**
- 跟随 `v.douyin.com/xxx` 短链重定向，返回最终落地 URL。
- 实现：调用注入的 `HttpClient.get(short_url, use_cookie_pool=False)`，从 `httpx.Response.url` 取最终 URL。
- 不带 Cookie 与签名（短链重定向不需要）。
- **异常**：`NetworkError`（重定向失败/超时）。

#### 1.4 模块级常量

- 预编译正则常量（模块级，避免每次调用重新编译）：
  - `_URL_PATTERN`：通用 URL 提取正则
  - `_DOUYIN_DOMAIN`：域名判断常量（`v.douyin.com`、`www.douyin.com`、`douyin.com`）
- 固定 User-Agent 常量（短链重定向用，与 HttpClient 一致）。

### 任务 2：HTTP 客户端基础（`crawlers/http_client.py`）

**目标**：封装 `httpx.AsyncClient` 单例，统一注入签名、Cookie、Headers，提供异步 GET 请求入口。

#### 2.1 `CookieRecord` dataclass

- **定义位置**：`crawlers/http_client.py` 顶部（与接口文档 3.5 节一致）。
- **字段**：`id`、`content`、`label`、`status`、`last_used`、`last_check`、`fail_count`、`created_at`。
- **用途**：在爬虫层与数据层之间传递 Cookie 状态的内存表示。
- **与 `app/models.py` 的 `Cookie` 的关系**：HttpClient 从 `CookieRepository.get_valid()` 拿到 `Cookie` 后，转换为 `CookieRecord` 使用；或直接复用 `Cookie`（实现时二选一，推荐复用 `Cookie` 避免重复定义，但接口文档明确列出 `CookieRecord`，需对齐）。**决策**：本里程碑在 `http_client.py` 中定义 `CookieRecord`，并提供 `_cookie_to_record()` 私有转换函数，保持接口文档一致性。

#### 2.2 `HttpClient` 类

**构造函数**：
- `__init__(self, cookie_repository: "CookieRepository", signer: "Signer", timeout_connect: float = 10.0, timeout_read: float = 30.0) -> None`
  - 注入 `CookieRepository`（v0.0.1 提供）操作 Cookie 池。
  - 注入 `Signer`（v0.0.2 提供）生成签名。
  - 创建 `httpx.AsyncClient` 单例：
    - `http2=True` 启用 HTTP/2
    - `timeout=httpx.Timeout(connect=timeout_connect, read=timeout_read, write=10.0, pool=5.0)`
    - `follow_redirects=False`（短链重定向由 URLParser 主动调用，避免签名请求被自动重定向导致签名失效）
  - 统一请求头常量（模块级）：
    - `User-Agent`：Chrome Windows 桌面 UA
    - `Referer`：`https://www.douyin.com/`
    - `Accept`：`application/json, text/plain, */*`
    - `Accept-Language`：`zh-CN,zh;q=0.9`

**方法 1：`get(url, params, use_cookie_pool, cookie) -> httpx.Response`**（async）
- 签名：`async def get(self, url: str, params: dict | None = None, use_cookie_pool: bool = True, cookie: str | None = None) -> httpx.Response`
- 流程：
  1. **签名注入**：调用 `signer.sign(url, params or {})` 得到签名参数 dict，合并到 `params`。
  2. **Cookie 注入**：
     - 若 `cookie` 显式提供 → 直接用该 Cookie。
     - 否则若 `use_cookie_pool=True` → 调用 `get_cookie_from_pool()` 取 valid Cookie。
     - 否则（`use_cookie_pool=False` 且 `cookie=None`）→ 不带 Cookie 请求（用于短链重定向等）。
  3. 构造请求 headers，注入 Cookie 头。
  4. 调用 `self._client.get(url, params=params, headers=headers)`。
  5. 调用 `_handle_response(response, cookie_id)` 进行风控响应分类（任务 4）。
  6. 记录请求/响应摘要日志。
  7. 返回 `httpx.Response`。
- **异常**：`CookieInvalidError`、`RateLimitedError`、`VerifyRequiredError`、`NetworkError`（由 `_handle_response` 与 httpx 异常转换）。
- **Cookie 自动切换**：若 `_handle_response` 抛 `CookieInvalidError` 且 `use_cookie_pool=True`，在内部捕获后重试一次（取下一条 valid Cookie）；仍失败则向上抛异常。

**方法 2：`close() -> None`**（async）
- 关闭内部 `httpx.AsyncClient`，释放连接池。
- 调用时机：应用退出时（`AsyncWorker.stop`）。

#### 2.3 模块级常量

- `DEFAULT_USER_AGENT`：Chrome Windows UA 字符串。
- `DEFAULT_HEADERS`：默认请求头 dict。
- `RISK_STATUS_CODES`：风控 HTTP 状态码集合（`{461, 412}`）。
- `VERIFY_HTML_MARKERS`：滑动验证 HTML 特征字符串列表（如 `"captcha_verify"`、`"verify_type"`）。
- `MAX_FAIL_COUNT`：Cookie 连续失败上限（`3`）。

### 任务 3：Cookie 池管理逻辑（`crawlers/http_client.py` 内）

**目标**：实现 Cookie 池的轮询取用、失败上报、成功上报、全池失效检测，遵循设计文档 4.3 节策略。

#### 3.1 `get_cookie_from_pool() -> CookieRecord`

- 策略：
  1. 调用 `cookie_repository.get_valid()` 取所有 `status='valid'` 的 Cookie，按 `last_used` 升序。
  2. 若列表为空 → 调用 `check_all_cookies_invalid()` 确认后抛 `CookieInvalidError("Cookie 池无可用 Cookie")`。
  3. 取首条（最久未用优先），调用 `cookie_repository.update_last_used(cookie.id)` 更新 `last_used`。
  4. 转换为 `CookieRecord` 返回。
- **设计要点**：「最久未用优先」实现负载均衡，避免单条 Cookie 被高频使用而触发风控。

#### 3.2 `report_cookie_fail(cookie_id: int) -> None`

- 策略：
  1. 从 `cookie_repository.get_by_id(cookie_id)` 取当前 `fail_count`。
  2. `new_fail_count = fail_count + 1`。
  3. 调用 `cookie_repository.update_fail_count(cookie_id, new_fail_count)`。
  4. 若 `new_fail_count >= MAX_FAIL_COUNT`（3）：
     - 调用 `cookie_repository.update_status(cookie_id, 'invalid')`。
     - 记录日志：`Cookie {cookie_id} 连续失败 {new_fail_count} 次，标记为 invalid`。
- **连续失败语义**：仅在连续失败累计达 3 次时置 invalid；成功时由 `report_cookie_success` 重置计数。

#### 3.3 `report_cookie_success(cookie_id: int) -> None`

- 策略：
  1. 调用 `cookie_repository.update_fail_count(cookie_id, 0)` 重置 `fail_count`。
  2. 调用 `cookie_repository.update_last_used(cookie_id)` 更新 `last_used`。
  3. （可选）若该 Cookie 当前状态为 `untested`，置为 `valid`。

#### 3.4 `check_all_cookies_invalid() -> bool`

- 策略：
  1. 调用 `cookie_repository.get_valid()` 取 valid Cookie 列表。
  2. 返回 `len(list) == 0`。
- **调用时机**：`get_cookie_from_pool` 取不到 Cookie 时；上层（Scheduler/AsyncWorker）据此决定是否暂停所有任务并弹窗提示。

#### 3.5 Cookie 自动切换编排

- 在 `get()` 方法内部实现（任务 2.2 步骤 5-6 的扩展）：
  - 首次请求取 Cookie A，若响应判定 Cookie 失效（461/412）：
    1. 调用 `report_cookie_fail(A.id)`。
    2. 若 A 已被置 invalid 且池中仍有 valid Cookie → 取 Cookie B 重试一次。
    3. 若池中已无 valid Cookie → 抛 `CookieInvalidError`。
  - 重试上限：1 次（避免无限循环）；仍失败抛异常。
- **不打断下载**：上层 Scheduler 收到 `CookieInvalidError` 后，由 v0.0.5 的下载引擎决定是否暂停该任务项。

### 任务 4：风控响应处理（`crawlers/http_client.py` 内）

**目标**：对 httpx 响应进行风控分类，转换为对应异常，并记录日志。

#### 4.1 `_handle_response(response: httpx.Response, cookie_id: int | None) -> httpx.Response`（私有方法）

- 分类逻辑（按顺序判断）：

  | 优先级 | 条件 | 处理 | 异常 |
  |---|---|---|---|
  | 1 | `response.status_code in {461, 412}` | 调用 `report_cookie_fail(cookie_id)`（若 cookie_id 非 None） | 抛 `CookieInvalidError`（或 `RateLimitedError`，按设计文档 6.3 节，461/412 统一视为 Cookie 失效/限流，本里程碑统一抛 `CookieInvalidError`，`RateLimitedError` 保留给 429） |
  | 2 | `response.status_code == 429` | 调用 `report_cookie_fail(cookie_id)` | 抛 `RateLimitedError` |
  | 3 | HTTP 200 + 响应体含验证 HTML 特征（`_is_verify_html(response.text)`） | 调用 `report_cookie_fail(cookie_id)` | 抛 `VerifyRequiredError` |
  | 4 | HTTP 200 + JSON 响应 `status_code != 0` | 不上报 Cookie 失败（API 层面拒绝，非 Cookie 问题） | 返回 response，由上层 VideoParser/UserHomeCrawler 根据 `status_code` 具体值抛 `VideoNotFoundError` / `UserNotFoundError` |
  | 5 | HTTP 200 + 正常数据 | 调用 `report_cookie_success(cookie_id)`（若 cookie_id 非 None） | 返回 response |
  | 6 | 其他 4xx（非 461/412/429） | 不重试 | 抛 `NetworkError`（或自定义异常，本里程碑归为 `NetworkError`） |
  | 7 | 其他 5xx | 可重试 | 抛 `NetworkError` |

- **返回值**：成功时返回原 `httpx.Response`，供上层解析。
- **设计要点**：`status_code != 0` 的情况不在 HttpClient 抛异常，而是把响应原样返回，让上层（v0.0.4 VideoParser）根据业务错误码判断是「作品不存在」还是「其他 API 错误」。这样 HttpClient 保持通用性。

#### 4.2 `_is_verify_html(text: str) -> bool`（私有方法）

- 检测响应文本是否含滑动验证特征。
- 实现：遍历 `VERIFY_HTML_MARKERS`，任一命中即返回 True。
- 性能：仅在 `response` 的 `Content-Type` 为 `text/html` 或非 JSON 时检测，避免对大 JSON 响应做全文扫描。

#### 4.3 httpx 异常转换

- 在 `get()` 方法外层 try/except 捕获 httpx 网络异常并转换：
  - `httpx.ConnectTimeout` / `httpx.ConnectError` / `httpx.ReadTimeout` / `httpx.RemoteProtocolError` → 抛 `NetworkError`，保留原异常作为 `__cause__`。
  - 其他 `httpx.HTTPError` → 抛 `NetworkError`。

#### 4.4 日志记录

- 请求前：`DEBUG` 级别记录 `Method URL params_summary cookie_id`。
- 响应后：`DEBUG` 级别记录 `status_code response_size`；`WARNING` 级别记录风控响应；`ERROR` 级别记录网络异常。
- **不记录**：完整 Cookie 字符串、完整响应体（仅记录摘要与 status_code）。
- 使用 `app/logger.py`（v0.0.1 提供）配置的 logger，模块名 `crawlers.http_client`。

class ParsedURL:

    type: LinkType
    url: str                       # 规范化后的最终 URL（跟随重定向后）
    aweme_id: str | None           # 视频/图文/长视频作品 ID
    sec_user_id: str | None        # 用户主页 sec_user_id

        异常:

            NetworkError: 短链重定向失败。
        """
        ...

    def extract_url(self, text: str) -> str | None:
        """从任意文本中提取第一个抖音链接 URL。

        返回:
            提取到的 URL 字符串；未找到返回 None。
        """
        ...

    def identify_type(self, url: str) -> LinkType:
        """根据 URL 路径与查询参数识别链接类型。

            InvalidURLFormatError: 无法识别类型。
        """
        ...

### 4.2 `crawlers/http_client.py`

```python
from __future__ import annotations
from dataclasses import dataclass
import httpx
from typing import Literal

CookieStatus = Literal["valid", "invalid", "untested"]


@dataclass(frozen=True)
class CookieRecord:
    """Cookie 池中一条记录的内存表示。

    与 cookies 表一行对应，用于在爬虫层与数据层之间传递 Cookie 状态。
    """
    id: int
    content: str                        # Cookie 字符串
    label: str | None                   # 用户自定义标签
    status: CookieStatus
    last_used: str | None               # ISO8601
    last_check: str | None
    fail_count: int
    created_at: str


class HttpClient:
    """HTTP 客户端。

    封装 httpx.AsyncClient，提供统一请求入口与 Cookie 池管理。
    通过依赖注入接收 CookieRepository 以操作 Cookie 池。
    """

    def __init__(
        self,
        cookie_repository: "CookieRepository",
        signer: "Signer",
        timeout_connect: float = 10.0,
        timeout_read: float = 30.0,
    ) -> None: ...

    async def get(
        self,
        url: str,
        params: dict | None = None,
        use_cookie_pool: bool = True,
        cookie: str | None = None,
    ) -> httpx.Response:
        """发起 GET 请求，自动注入签名、Cookie、统一 Headers。

        参数:
            url: 请求 URL（不含查询参数）。
            params: 业务请求参数；本方法会自动追加签名参数。
            use_cookie_pool: 是否从 Cookie 池自动取 Cookie（默认 True）。
            cookie: 显式指定 Cookie（优先级高于池）。

        异常:
            CookieInvalidError: 池中所有 Cookie 均失效或 461/412 响应。
            RateLimitedError: HTTP 429 限流响应。
            VerifyRequiredError: 响应含滑动验证 HTML。
            NetworkError: 网络异常或 5xx 响应。
        """
        ...

    def get_cookie_from_pool(self) -> CookieRecord:
        """从 Cookie 池中按"最久未用优先"策略取一条 valid Cookie。

        异常:
            CookieInvalidError: 池中无可用 Cookie。
        """
        ...

    def report_cookie_fail(self, cookie_id: int) -> None:
        """上报某条 Cookie 请求失败。fail_count += 1；连续 3 次置 invalid。"""
        ...

    def report_cookie_success(self, cookie_id: int) -> None:
        """上报某条 Cookie 请求成功，重置 fail_count = 0，更新 last_used。"""
        ...

    def check_all_cookies_invalid(self) -> bool:
        """检查池里是否所有 Cookie 都失效（无 valid 记录）。"""
        ...

    async def close(self) -> None:
        """关闭内部 httpx.AsyncClient，释放连接池。"""
        ...
```

| httpx HTTP/2 在某些网络环境下握手失败 | 低 | 低 | 暂不降级 fallback；如 v0.0.4 联调发现问题，再加 `http2=False` 开关 |
| Cookie 池并发取用竞态（多协程同时取到同一条） | 低 | 中 | 本里程碑单协程测试不涉及；v0.0.5 下载引擎接入时再加锁（`asyncio.Lock`） |
| `CookieRecord` 与 `Cookie` 双重定义导致维护负担 | 低 | 低 | 提供 `_cookie_to_record()` 转换函数隔离；如后续发现冗余，统一为复用 `Cookie` |

## 8. 下一里程碑衔接

### 8.1 衔接 v0.0.4：视频解析器与主页抓取器

本里程碑为 v0.0.4 提供以下能力：

| 能力 | 提供方 | v0.0.4 消费方 |
|---|---|---|
| 统一 HTTP 请求出口（带签名/Cookie/风控处理） | `HttpClient.get()` | `VideoParser.parse_video()`、`UserHomeCrawler.fetch_user_posts()` |
| Cookie 池自动管理 | `get_cookie_from_pool()` 等方法 | HttpClient 内部自动调用，v0.0.4 无需直接操作 |
| 链接解析 | `URLParser.parse()` | UI 链接抓取页 → worker → URLParser → VideoParser/UserHomeCrawler |
| 异常体系 | `CookieInvalidError` 等 | v0.0.4 的 VideoParser 透传异常，下载引擎据此重试/标记失败 |

### 8.2 待 v0.0.4 确认的接口契约

- **HttpClient.get 返回的 response 是否包含原始 JSON**：是。v0.0.4 的 VideoParser 从 `response.json()` 取 `aweme_detail`。
- **status_code 非 0 的响应处理**：HttpClient 原样返回 response，v0.0.4 的 VideoParser 负责根据 `status_code` 具体值抛 `VideoNotFoundError` 或其他业务异常。
- **URLParser 的 type 预判**：统一归 `'video'`，v0.0.4 的 VideoParser 在拿到 detail 响应后细化 `aweme_type` → `image_set` / `long_video`。

### 8.3 遗留项（不在本里程碑处理）

- **Cookie 池并发安全**：v0.0.5 下载引擎多协程并发取用时需加 `asyncio.Lock`，本里程碑仅保证单协程正确性。
- **Cookie 自动定时刷新**：设计文档未要求，YAGNI。
- **签名参数与业务 params 同名冲突策略**：本里程碑约定签名参数覆盖业务 params（签名必须存在）；如 v0.0.4 发现业务参数被覆盖导致问题，再调整为业务参数优先。
- **真实抖音 API 联调**：本里程碑全部用 mock，真实联调留待 v0.0.4 完成后整体集成测试。
