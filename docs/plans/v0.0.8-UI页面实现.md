## 2. 里程碑概述

### 2.1 里程碑定位

本里程碑是 10 个里程碑中的**第 8 个**，实现 4 个业务页面与 3 个可复用行组件，是用户直接可见、直接操作的功能层。本里程碑在前置 UI 框架（主窗口、导航栏、QSS 全局样式）之上，填充页面内容与组件逻辑，并完成与工作线程桥接（Bridge）信号的连接。

```
里程碑序列（10 个）：
  v0.0.1 数据层           ✅ 前置依赖（已完成）
  v0.0.2 ~ v0.0.5 ...     （签名/解析/下载引擎）
  v0.0.6 工作线程桥接     ✅ 前置依赖（提供 Bridge 信号）
  v0.0.7 UI 框架与导航    ✅ 前置依赖（提供主窗口/导航/QSS）
  v0.0.8 UI 页面实现      ◄── 本里程碑
  v0.0.9 打包与发布
  v1.0.0 正式发布
```

### 2.2 前置依赖

| 依赖项 | 来源 | 说明 |
|---|---|---|
| 数据层 v0.0.1 | `app/` | 提供 `Task`、`TaskItem`、`Cookie`、`Config` dataclass 与 5 个 Repository（`app/models.py`、Repository CRUD） |
| 工作线程桥接 v0.0.6 | `worker/` | 提供 Bridge 对象及其 Qt 信号：`progress_updated`、`item_completed`、`item_failed`、`parse_completed`、`parse_failed`、`home_fetch_progress`、`home_fetch_completed`、`home_fetch_failed`、`cookie_test_result`，以及供 UI 调用的请求方法（暂停/恢复/重试/解析/抓取/下载/添加 Cookie/测试 Cookie/保存配置等） |
| UI 框架与导航 v0.0.7 | `ui/main_window.py`、`ui/assets/style.qss` | 提供主窗口（导航栏 + 内容区 QStackedWidget）、4 个页面的占位注册、全局 QSS 样式表、图标资源、Toast 组件、确认弹窗组件、页面基类约定 |
| PySide6 | 第三方库 | Qt 6.6+，提供 QWidget/QLayout/QLabel/QProgressBar/QScrollArea 等基础组件 |

**关键约束**：UI 页面层**只依赖数据层与 Bridge**，不直接 import `downloader/` 或 `crawlers/`。所有后台操作通过 Bridge 发起的信号/方法完成，UI 只负责"显示 + 收集用户操作 + 发信号"（设计文档 8.2 节分层职责边界）。

## 4. 设计依据与技术约束

### 4.1 UI 界面设计依据（设计文档 3 节）

- 四个页面布局：左侧导航栏 + 右侧内容区（v0.0.7 已实现框架）

- 链接抓取页（3.1 节）：多行输入 + 导入文件 + 解析结果 + 主页过滤栏 + 全选 + 下载目录
- Cookie 配置页（3.1 节）：列表 + 添加弹窗 + 教程折叠 + 状态指示灯三色
- 设置页（3.1 节）：下载目录 + 滑块 + 下拉 + 重试固定 + 元数据格式 + 导出日志 + 关于
- 视觉风格（3.2 节）：简洁现代扁平化，品牌紫进度、绿色完成、红色失败

### 4.2 错误处理与用户体验依据（设计文档 7 节）

- 核心原则（7.1 节）：绝不让用户看到原始异常栈，每个错误都有人话解释 + 下一步建议
- 错误展示位置（7.3 节）：
  - 任务项级错误：显示在该任务行下方红色小字，不打断其他任务
  - 全局错误：弹窗提示 + 操作按钮（由 v0.0.7 提供确认弹窗组件）
  - 输入错误：输入框下方红字提示，不弹窗
- 操作反馈（7.6 节）：耗时操作显示 loading + 可取消；批量操作立即响应不阻塞；状态变化有视觉反馈
- 空状态（7.6 节 + 规范 6.3 节）：无任务/Cookie/结果时显示引导文字 + 操作按钮
- 错误文案规范（规范 6.4.3 节）：用"人话"，包含"发生了什么 + 用户该做什么"两部分

### 4.3 组件规范依据（UIUX 规范 4 节）

- 任务行（4.5.1 节）：高 72px（默认）/96px（失败态），缩略图 64x64，进度条宽 200px 高 6px

### 4.9 缩略图异步加载约束

- 缩略图从 `cover_url`（网络 URL）加载，**必须异步**，不得在主线程发同步 HTTP 请求阻塞 UI
- 实现方式：用 `QThread`/`QThreadPool`+`QRunnable` 或 QtNetwork `QNetworkAccessManager` 异步下载图片，下载完成通过信号回传 QPixmap
- 加载中显示占位图（灰色 #E5E7EB），加载失败显示占位图不报错
- 同一 widget 多次更新时取消未完成的旧请求，避免错乱

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 缩略图同步加载阻塞 UI | 界面卡顿 | 必须 QThread/QNetworkAccessManager 异步加载，加载中显示占位图 |
| Bridge 信号签名与预期不符 | 信号连接失败 | 本里程碑实现时核对 v0.0.6 Bridge 实际签名，按实际适配；本文档 4.8 节签名为推断约定 |
| QSS setProperty 切换状态不生效 | 进度条/状态灯颜色不变 | setProperty 后必须 `style().unpolish(widget)` + `polish(widget)` 刷新，或直接 setStyleSheet |
| Qt 主线程与 Bridge 线程信号连接类型 | 信号跨线程报错 | 使用 `Qt.QueuedConnection`（PySide6 默认跨线程自动 Queued），确保 Bridge 信号在主线程更新 UI |
| 缩略图加载请求错乱（widget 复用） | 显示错误图片 | widget 更新时取消旧请求，用标志位或请求 ID 匹配 |
| 弹窗模态层级错误 | 弹窗被主窗口遮挡 | AddCookieDialog 用 `setWindowModality(Qt.ApplicationModal)` 并 setParent |
| 教程截图资源缺失 | 教程显示空白 | 加载截图 try/except，缺失时显示占位框"截图待补充" |

### 8.2 实现注意事项

1. **职责边界**：UI 只显示与收集操作，不实现业务逻辑；写操作经 Bridge 转发，读操作可直接调 Repository（刷新场景）
2. **信号转发链**：组件信号 → 页面信号 → 主窗口 → Bridge；避免组件直接调 Bridge
3. **线程安全**：Bridge 信号来自工作线程，UI 槽函数通过 QueuedConnection 在主线程执行，槽内只做 UI 更新
4. **QSS 状态切换**：进度条/状态灯/任务行背景色通过 `setProperty` + `unpolish/polish` 切换，不直接 setStyleSheet（保持全局 QSS 一致）
5. **空状态切换**：列表有内容时隐藏空状态 widget，无内容时显示；避免两者同时可见
6. **动画节制**：遵循规范 6.5 节，总时长 ≤ 300ms，同一时间不超过 2 个动画并行
7. **错误文案**：所有错误提示用"人话"，包含"发生了什么 + 用户该做什么"，不显示原始异常（设计文档 7.1 节）
8. **快捷键**：实现规范 6.6 节的关键快捷键（Ctrl+P/S 全部暂停/开始、Delete 删除、Ctrl+A 全选等），按钮 tooltip 标注快捷键
9. **资源路径**：教程截图、图标等资源用 Qt 资源系统或相对路径，打包后路径正确（`:/` 前缀或 `os.path` 相对 APP_DATA_DIR）
10. **DPI 适配**：所有尺寸用 px，Qt 自动按 DPI 缩放；测试 125%/150% 缩放下布局不溢出

### 8.3 与后续里程碑的接口约定

| 接口 | 本里程碑提供 | 后续里程碑消费 |
|---|---|---|
| 4 个页面类（DownloadPage/FetchPage/CookiePage/SettingsPage） | 页面 widget | v0.0.7 主窗口 QStackedWidget 添加页面（若 v0.0.7 已占位则替换占位） |
| 页面信号（pause_all_clicked 等） | 信号签名 | 主窗口连接信号转 Bridge |
| TaskItemWidget/CookieItemWidget/FilterBar | 组件 widget | 页面内部使用，无外部消费 |
