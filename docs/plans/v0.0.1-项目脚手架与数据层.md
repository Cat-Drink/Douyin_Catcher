     - 调用 `config.ensure_app_dirs()` 确保 `LOG_DIR` 存在
     - 创建 `logging.handlers.TimedRotatingFileHandler`：

### 任务 5：数据库管理模块 (app/database.py)

**任务描述**：实现 SQLite 连接管理、表初始化（5 张业务表 + 1 张 schema_version 表）、6 个索引创建、默认配置插入、基于 schema_version 的迁移框架。

**涉及文件**：`app/database.py`

**实现要点**：

1. **连接管理**
   - `def get_connection(db_path: Path | str | None = None) -> sqlite3.Connection`
     - 默认 `db_path = config.DB_PATH`，调用 `config.ensure_app_dirs()` 确保父目录存在
     - `sqlite3.connect(db_path, check_same_thread=False)`（允许跨线程使用，由调用方保证线程安全）
     - 开启 WAL：`conn.execute("PRAGMA journal_mode=WAL")`
     - 开启外键：`conn.execute("PRAGMA foreign_keys=ON")`
     - `conn.row_factory = sqlite3.Row`（返回字典式行，便于 Repository 映射）
     - 返回连接
   - 线程安全考量：SQLite 连接不跨线程共享，每个工作线程自行调用 `get_connection()`。本里程碑在测试中验证连接可用，并发场景在后续里程碑的 worker 层处理。

2. **Schema 常量**
   - `SCHEMA_VERSION = 1`（当前 schema 版本）
   - `CREATE_TASKS_SQL`、`CREATE_TASK_ITEMS_SQL`、`CREATE_METADATA_SQL`、`CREATE_COOKIES_SQL`、`CREATE_CONFIG_SQL`、`CREATE_SCHEMA_VERSION_SQL` — 6 个建表 SQL 字符串常量，DDL 与设计文档 4.1 节完全一致
   - `CREATE_INDEXES_SQL` — 6 个索引的 SQL 列表：
     1. `CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status)`
     2. `CREATE INDEX IF NOT EXISTS idx_task_items_task_id ON task_items(task_id)`
     3. `CREATE INDEX IF NOT EXISTS idx_task_items_status ON task_items(status)`
     4. `CREATE INDEX IF NOT EXISTS idx_task_items_aweme_id ON task_items(aweme_id)`（去重查询）
     5. `CREATE INDEX IF NOT EXISTS idx_cookies_status ON cookies(status)`
     6. `CREATE INDEX IF NOT EXISTS idx_metadata_task_item_id ON metadata(task_item_id)`

3. **初始化函数**
   - `def init_db(conn: sqlite3.Connection) -> None`
     - 执行 6 个建表 SQL（`CREATE TABLE IF NOT EXISTS`）
     - 执行 6 个索引 SQL（`CREATE INDEX IF NOT EXISTS`）
     - 创建 `schema_version` 表：`CREATE TABLE IF NOT EXISTS schema_version (version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL)`
     - 插入默认配置：遍历 `config.DEFAULT_CONFIGS`，`INSERT OR IGNORE INTO config(key, value) VALUES(?, ?)`（已存在则跳过，保证幂等）
     - 若 `schema_version` 表无记录，插入 `(SCHEMA_VERSION, now_iso)`
     - 全部在一个事务中执行（`with conn:`），失败回滚

4. **迁移框架**
   - `def migrate(conn: sqlite3.Connection) -> None`
     - 读取 `schema_version` 表当前版本
     - 若当前版本 < `SCHEMA_VERSION`，依次执行迁移函数（本里程碑只有 v1，无实际迁移逻辑，但预留框架）
     - 迁移函数注册用字典：`MIGRATIONS: dict[int, Callable[[sqlite3.Connection], None]] = {}`（v1 为空，后续版本追加）
     - 每个迁移函数负责版本 N-1 → N 的 DDL，执行后更新 `schema_version`
   - 设计意图：后续里程碑若改表结构，只需新增迁移函数，不改 `init_db`，保证已部署用户的数据库可平滑升级

5. **便捷初始化入口**
   - `def init_default_db() -> sqlite3.Connection` — 调用 `get_connection()` + `init_db()` + `migrate()`，返回就绪连接。应用启动时调用一次。

6. **测试辅助**
   - `def get_memory_connection() -> sqlite3.Connection` — 返回 `sqlite3.connect(":memory:")` 连接并执行 `init_db()`，供测试使用（内存数据库快且自动清理）

**验收标准**：
- [ ] `init_db()` 后，`sqlite_master` 表中存在 6 张表（tasks, task_items, metadata, cookies, config, schema_version）
- [ ] `sqlite_master` 中存在 6 个索引
- [ ] `PRAGMA journal_mode` 返回 `wal`（文件数据库）
- [ ] `PRAGMA foreign_keys` 返回 1
- [ ] `config` 表含 6 条默认配置
- [ ] 重复调用 `init_db()` 幂等，不报错不重复插入
- [ ] `get_memory_connection()` 返回的连接可直接用于 Repository 操作

### 任务 7：Repository 层

**任务描述**：实现 5 个 Repository 类，封装对 5 张表的 CRUD 操作。每个 Repository 接收 `sqlite3.Connection`，方法返回 dataclass 实例。所有写操作在事务中执行。

**涉及文件**：`app/repositories.py`（单文件含 5 个类，避免文件碎片化）

**实现要点**：

#### 7.1 TaskRepository

```python
class TaskRepository:
    def __init__(self, conn: sqlite3.Connection): ...
    def create(self, task: Task) -> int: ...
    def get(self, task_id: int) -> Task | None: ...
    def get_by_status(self, status: str) -> list[Task]: ...
    def update_status(self, task_id: int, status: str) -> None: ...
    def update_progress(self, task_id: int, completed_items: int, total_items: int | None = None) -> None: ...
    def delete(self, task_id: int) -> None: ...
    def get_pending_for_resume(self) -> list[Task]: ...
```

- `create`：插入任务，`created_at`/`updated_at` 若空则用 `now_iso()`，返回 `cursor.lastrowid`
- `get`：`SELECT * FROM tasks WHERE id=?`，无结果返回 `None`，否则映射为 `Task`
- `get_by_status`：`SELECT * FROM tasks WHERE status=? ORDER BY created_at`
- `update_status`：`UPDATE tasks SET status=?, updated_at=? WHERE id=?`
- `update_progress`：`UPDATE tasks SET completed_items=?, total_items=COALESCE(?, total_items), updated_at=? WHERE id=?`（`total_items` 为 `None` 时不更新）
- `delete`：`DELETE FROM tasks WHERE id=?`（外键 `ON DELETE CASCADE` 会级联删除 `task_items` 和 `metadata`）
- `get_pending_for_resume`：`SELECT * FROM tasks WHERE status IN ('pending','downloading','paused') ORDER BY created_at`（断点续传：应用启动时扫描可恢复任务）

#### 7.2 TaskItemRepository

```python
class TaskItemRepository:
    def __init__(self, conn: sqlite3.Connection): ...
    def create(self, item: TaskItem) -> int: ...
    def get(self, item_id: int) -> TaskItem | None: ...
    def get_by_task(self, task_id: int) -> list[TaskItem]: ...
    def get_by_status(self, status: str) -> list[TaskItem]: ...
    def update_status(self, item_id: int, status: str, fail_reason: str | None = None) -> None: ...
    def update_bytes(self, item_id: int, downloaded_bytes: int, total_bytes: int | None = None) -> None: ...
    def update_retry(self, item_id: int, retry_count: int) -> None: ...
    def delete(self, item_id: int) -> None: ...
    def get_by_aweme_id(self, aweme_id: str) -> TaskItem | None: ...

```

- `create`：插入，返回 `lastrowid`
- `get` / `get_by_task` / `get_by_status`：查询并映射为 `TaskItem`
- `update_status`：更新状态，`fail_reason` 非 `None` 时一并更新（失败时记录原因），同步 `updated_at`
- `update_bytes`：`UPDATE task_items SET downloaded_bytes=?, total_bytes=COALESCE(?, total_bytes), updated_at=? WHERE id=?`（分块续传进度持久化）
- `update_retry`：`UPDATE task_items SET retry_count=?, updated_at=? WHERE id=?`
- `get_by_aweme_id`：`SELECT * FROM task_items WHERE aweme_id=? ORDER BY id DESC LIMIT 1`（去重查询：进队列前查是否已存在）
- `reset_downloading_to_paused`：`UPDATE task_items SET status='paused', updated_at=? WHERE status='downloading'`，返回 `cursor.rowcount`（应用启动时把中断的下载项重置为 paused，对应设计文档 4.2 节）

#### 通用实现约定

- **行映射**：私有方法 `_row_to_task(row: sqlite3.Row) -> Task` 等，将 `sqlite3.Row` 按 dataclass 字段顺序映射
- **事务**：所有写操作用 `with conn:` 自动提交/回滚
- **类型安全**：方法签名用 `str` 而非枚举（调用方可传枚举或字符串，`str` 枚举兼容），返回 dataclass
- **错误处理**：不捕获 `sqlite3.Error`，向上抛出由调用方处理（数据层不吞异常）

## 风险与注意事项

### 技术风险

1. **SQLite 跨线程使用**
   - 风险：`sqlite3.connect` 默认 `check_same_thread=True`，跨线程访问会抛异常
   - 应对：`get_connection` 设 `check_same_thread=False`，但约定每个工作线程自行获取连接，不共享连接实例。本里程碑不实现并发，仅预留接口；并发场景在 worker 里程碑验证。

2. **WAL 模式在内存数据库无效**
   - 风险：`:memory:` 数据库不支持 WAL（`PRAGMA journal_mode=WAL` 返回 `memory`）
   - 应对：`test_wal_mode_enabled` 用 `tmp_path` 文件数据库测试，不用内存数据库。其他测试用内存数据库不受影响。

3. **`last_used IS NULL` 排序语义**
   - 风险：SQLite 中 `NULL` 在 `ORDER BY last_used ASC` 时排最前还是最后取决于实现
   - 应对：用 `ORDER BY last_used IS NULL DESC, last_used ASC` 显式让 NULL 排最前（最久未用），测试用例显式覆盖此场景。

4. **外键级联删除需手动开启**
   - 风险：SQLite 默认不开启外键约束，`ON DELETE CASCADE` 不生效
   - 应对：`get_connection` 必须执行 `PRAGMA foreign_keys=ON`。测试 `test_cascade_delete` 显式验证。

### 工程注意事项

1. **绝不硬编码 Cookie**
   - `.env` 已在 `.gitignore`，`.env.example` 只放占位符
   - 本里程碑不涉及实际 Cookie 使用，但预置规范

2. **覆盖率统计范围**
   - `pyproject.toml` 的 `--cov=.` 会统计所有目录，但 `app/` 外的目录本里程碑为空，不影响覆盖率
   - 若 UI/爬虫等空目录的 `__init__.py` 拉低覆盖率，需在 `[tool.coverage.run]` 用 `omit` 排除非本里程碑目录

3. **dataclass 与 Row 映射**
   - `sqlite3.Row` 支持按列名访问，映射时用 `row["column_name"]` 而非索引，避免列顺序变化导致错误
   - `id` 字段插入时为 `None`，查询时为 `int`，dataclass 用 `int | None` 兼容

4. **时间戳一致性**
   - 所有 `created_at`/`updated_at` 用 `now_iso()` 生成 ISO8601 字符串，统一格式
   - 不用 SQLite 的 `CURRENT_TIMESTAMP`（格式不可控且为 UTC）

5. **迁移框架前瞻**
   - 本里程碑 `MIGRATIONS` 字典为空（v1 由 `init_db` 直接建表），但框架已就绪
   - 后续里程碑修改表结构时，新增 `MIGRATIONS[2] = migrate_v1_to_v2`，不改 `init_db`

## 下一里程碑衔接

本里程碑（v0.0.1）完成后，如何衔接 **v0.0.2**（预计：爬虫组件层 - 链接解析与签名算法）：

### 数据层已就绪的接口

- `CookieRepository` 可供 v0.0.2 的 `HttpClient` 注入 Cookie（`get_valid` 取 Cookie，`update_last_used` 更新使用时间，`update_fail_count`/`update_status` 处理失效）
- `TaskRepository` / `TaskItemRepository` 可供 v0.0.2 的 `VideoParser` 写入解析结果（`TaskItemRepository.create` 插入解析出的无水印直链）
- `ConfigRepository` 可读取配置（如并发数，虽然 v0.0.2 暂不使用）
- `MetadataRepository` 可供 v0.0.2 保存视频元数据

### v0.0.2 需要补充的依赖

- `crawlers/exceptions.py` — 异常类型定义（`CookieInvalidError`、`RateLimitedError`、`VideoNotFoundError`、`NetworkError`）
- `crawlers/http_client.py` — httpx 封装，依赖 `CookieRepository`
- `crawlers/url_parser.py` — 链接解析器（纯函数，不依赖数据层）
- `crawlers/signer/` — 签名算法模块（纯函数，不依赖数据层）

### 数据层无需改动

- 本里程碑设计的 Repository 接口已前瞻性覆盖爬虫层需求，v0.0.2 无需修改 `app/` 目录任何文件
- 若 v0.0.2 发现数据层接口不足（如需要批量插入 task_items），走迁移框架新增方法，不改现有接口

### 验收衔接点

- v0.0.2 的爬虫测试可复用本里程碑的 `tests/conftest.py` fixtures（内存数据库 + Repository）
- v0.0.2 的 VCR.py 录制文件放 `tests/fixtures/`（本里程碑已创建空目录）
