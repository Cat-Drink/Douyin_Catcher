## 2. 里程碑概述

### 2.1 里程碑定位

本里程碑是 10 个里程碑中的**第 7 个**，也是 UI 实现的**第一个里程碑**。目标是搭建应用入口、全局 QSS 样式表、主窗口框架（左侧导航栏 + 右侧内容区 + 底部状态栏）、4 个页面占位骨架，以及 UI 与工作线程之间的 Bridge 连接层。本里程碑交付一个可启动、可导航切换、视觉风格符合设计规范的应用骨架，但各页面的具体功能（任务列表、链接解析、Cookie 管理、设置项）在 v0.0.8 实现。

```
里程碑序列（10 个）：
  v0.0.1 数据层        ✅ 前置依赖（已完成）
  v0.0.2 ~ v0.0.5      （中间里程碑）
  v0.0.6 工作线程桥接  ✅ 前置依赖（已完成）
  v0.0.7 UI 框架与导航 ◄── 本里程碑
  v0.0.8 各页面功能实现
  v0.0.9 打包与发布
  v1.0.0 正式发布
```

### 2.2 前置依赖

| 依赖项 | 来源 | 说明 |
|---|---|---|
| 数据层 v0.0.1 | `app/` | 提供 `database.init_db`、`database.init_default_db`、`ConfigRepository.get_onboarding_done`，用于应用启动初始化与引导判断 |
| 工作线程桥接 v0.0.6 | `worker/` | 提供 `AsyncWorker`（后台 asyncio 线程）、`DownloadBridge`（下载控制与进度信号）、`CrawlerBridge`（解析/抓取/Cookie 测试信号），本里程碑负责将其信号连接到 UI |
| PySide6 | 第三方库 | Qt 6.6+，QApplication / QMainWindow / QSS 样式支持（`requirements.txt` 已声明） |
| pytest-qt | 开发依赖（可选） | UI 冒烟测试，需在 `requirements-dev.txt` 追加声明 |

**关键约束**：UI 层通过 Bridge 信号/槽与工作线程通信，不直接调用爬虫/下载引擎的内部方法，遵循设计文档第 8.2 节"依赖方向单向：UI → worker → {downloader, crawlers} → models → database"。

### 2.3 交付目标

| 目标 | 衡量指标 |
|---|---|
| 应用入口可用 | `python main.py` 能启动、初始化数据库与 AsyncWorker、显示主窗口或引导页 |

| 主窗口框架可用 | 左侧导航栏 4 项 + 右侧 QStackedWidget + 底部状态栏布局正确 |
| 导航切换可用 | 点击导航项切换右侧内容区，选中项高亮（品牌紫左边框） |

## 4. 设计依据与技术约束

### 4.1 UI 界面设计依据（设计文档 3 节）

应用采用**左侧导航栏 + 右侧内容区**布局，包含四个页面（设计文档 3.1 节）：

| 页面 | 名称 | 导航图标 | 功能（v0.0.8 实现） |
|---|---|---|---|
| 页面 1 | 下载任务页 | download | 任务列表、批量操作、进度条、状态栏 |
| 页面 2 | 链接抓取页 | link | 链接输入、解析、结果列表、过滤栏、下载 |
| 页面 3 | Cookie 配置页 | key | Cookie 池列表、添加/测试/删除、教程 |
| 页面 4 | 设置页 | settings | 下载目录、并发数、分块大小、元数据格式 |

视觉风格（设计文档 3.2 节）：
- 简洁现代，QSS 扁平化设计
- 左侧导航栏固定，右侧内容区随导航切换
- 进度条用品牌色（紫），完成用绿色，失败用红色
- 窗口可缩放，任务列表区域可滚动

### 4.5 线程模型依据（设计文档 2.3 节）

- Qt 主线程：跑 UI，响应用户操作
- 后台工作线程：跑 asyncio 事件循环，承载爬虫调用和下载任务
- 通信方式：Qt 信号/槽（`pyqtSignal`/`Signal`）线程安全通信
- UI 层通过 Bridge（v0.0.6 提供）的信号接收工作线程通知，通过 Bridge 的控制方法发送指令

### 4.7 测试约束（设计文档 9.2 节、9.5 节）

- UI 层不强制覆盖率（Qt 组件难单测，重点靠手动验收）
- 可选冒烟测试用 pytest-qt
- ruff / black --check 无报错

### 任务 1：应用入口（`main.py`）

#### 1.1 目标

实现应用入口，完成 QApplication 创建、全局 QSS 加载、数据库初始化、AsyncWorker 与 Bridge 初始化、断点续传恢复、引导/主窗口显示、退出清理。严格遵循设计文档第 2.3 节（线程模型）与 7.4 节（首次引导）。

#### 1.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `main.py` | 新建 | 应用入口，`main()` 函数与 `if __name__ == "__main__"` 入口 |
| `requirements-dev.txt` | 修改 | 追加 `pytest-qt`（可选冒烟测试依赖） |

#### 1.3 模块级常量

| 常量 | 值 | 说明 |
|---|---|---|
| `APP_NAME` | `"抖音抓取器"` | 应用显示名称（窗口标题） |
| `APP_VERSION` | `"v0.0.7"` | 应用版本号（状态栏显示） |
| `QSS_PATH` | `Path(__file__).parent / "ui" / "assets" / "style.qss"` | 全局 QSS 样式表路径 |

#### 1.4 函数清单

**`main()` 函数（应用入口主流程）**

| 步骤 | 行为描述 |
|---|---|
| 1. 日志初始化 | 调用 `app.logger.setup_logger()` 配置按天滚动日志 |
| 2. 目录确保 | 调用 `app.config.ensure_app_dirs()` 确保 APPDATA 目录与日志目录存在 |
| 3. QApplication 创建 | 创建 `QApplication(sys.argv)`，设置应用名称、版本号 |
| 4. QSS 加载 | 调用 `_load_qss(app)` 加载全局样式表 |
| 5. 应用图标 | 设置 `app.setWindowIcon(QIcon(str(ICON_PATH)))`（图标文件存在时） |
| 6. 数据库初始化 | 调用 `app.database.init_default_db()` 获取 SQLite 连接（WAL 模式 + 外键 + 表结构） |
| 7. AsyncWorker 初始化 | 创建 `AsyncWorker()` 实例，调用 `start()` 启动后台 asyncio 线程 |
| 8. Bridge 初始化 | 创建 `DownloadBridge(async_worker)` 与 `CrawlerBridge(async_worker)` 实例 |
| 9. 断点续传恢复 | 调用 `download_bridge.restore_pending_tasks()`（通过 worker 提交到 asyncio 线程执行） |
| 10. 引导判断 | 创建 `ConfigRepository(conn)`，调用 `get_onboarding_done()` 判断是否已完成引导 |
| 11. 窗口显示 | 若 `onboarding_done` 为 True → 创建并显示 `MainWindow`；否则创建并显示 `OnboardingPage`（占位，v0.0.8 实现完整流程，本里程碑可临时直接显示主窗口或简单引导占位） |
| 12. 事件循环 | `sys.exit(app.exec())` 进入 Qt 事件循环 |
| 13. 退出清理 | 事件循环结束后调用 `_cleanup(async_worker, conn)` 清理资源 |

**`_load_qss(app: QApplication) -> None` 辅助函数**

| 行为描述 |
|---|
| 读取 `QSS_PATH` 文件内容（UTF-8 编码），调用 `app.setStyleSheet(qss_text)` 应用全局样式；文件不存在时记录警告日志但不阻断启动 |

**`_cleanup(async_worker: AsyncWorker, conn: sqlite3.Connection) -> None` 辅助函数**

| 步骤 | 行为描述 |
|---|---|
| 1. 停止 AsyncWorker | 调用 `async_worker.stop()`（停止 asyncio 事件循环、等待后台线程退出） |
| 2. 关闭数据库连接 | 调用 `conn.close()` 关闭 SQLite 连接 |
| 3. 日志记录 | 记录"应用退出清理完成"日志 |

**`if __name__ == "__main__"` 入口**

| 行为描述 |
|---|
| 调用 `main()`，捕获未处理异常记录日志后 `sys.exit(1)` |

#### 1.5 启动流程图

```
main()
  │
  ├─► setup_logger()
  ├─► ensure_app_dirs()
  ├─► QApplication(sys.argv)
  ├─► _load_qss(app)
  ├─► setWindowIcon(...)
  ├─► conn = init_default_db()
  ├─► async_worker = AsyncWorker(); async_worker.start()
  ├─► download_bridge = DownloadBridge(async_worker)
  ├─► crawler_bridge = CrawlerBridge(async_worker)
  ├─► download_bridge.restore_pending_tasks()  # 断点续传
  ├─► config_repo = ConfigRepository(conn)
  ├─► if config_repo.get_onboarding_done():
  │       main_window = MainWindow(conn, download_bridge, crawler_bridge)
  │       main_window.show()
  │   else:
  │       onboarding = OnboardingPage(...)  # v0.0.8 完整实现
  │       onboarding.show()
  ├─► exit_code = app.exec()
  ├─► _cleanup(async_worker, conn)
  └─► sys.exit(exit_code)
```

#### 1.6 关键约束

- **异常处理**：启动过程中任一步骤失败应记录日志并显示人话错误提示（设计文档 7.1 节），不暴露原始异常栈
- **资源释放**：确保退出时 AsyncWorker 停止、数据库连接关闭，避免资源泄漏
- **单实例约束**：本里程碑不实现单实例检测（后续里程碑考虑），但 `QApplication` 创建一次

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| v0.0.6 的 Bridge 信号签名与本计划假设不符 | 信号连接失败，编译/运行报错 | 以 v0.0.6 实际实现为准调整 `BridgeConnections` 连接代码；本计划标注"以 v0.0.6 实际实现为准" |
| QSS 属性选择器（`[state="completed"]`）在 Qt 中刷新机制复杂 | 进度条状态颜色切换不生效 | 使用 `setProperty` + `style().unpolish(widget)` + `polish(widget)` 刷新；或代码中 `setStyleSheet` 动态切换；本里程碑进度条占位，v0.0.8 验证 |
| 导航图标 SVG 资源暂缺 | NavBar 无图标，仅文字 | 可先用无图标按钮运行，记录 TODO 待设计提供；规范附录 B 已定义图标清单 |
| pytest-qt 在 CI 环境（Linux 无显示）运行失败 | 冒烟测试无法在 CI 执行 | CI 用 `xvfb-run` 或标记 UI 测试为可选跳过；手动验收为主 |
| PySide6 与 Python 版本兼容性 | import 失败 | `requirements.txt` 已声明 `PySide6>=6.6`，需 Python 3.11+ |
| 应用退出时 AsyncWorker 停止阻塞 | 退出卡死 | `_cleanup` 中 `async_worker.stop()` 应有超时机制（v0.0.6 实现）；本里程碑假设 v0.0.6 已处理 |
| 引导页占位实现不完整影响首次启动体验 | 首次用户看到空白或异常 | 本里程碑 `onboarding_done` 为 False 时可临时直接显示主窗口（记录 TODO），引导页完整流程在 v0.0.8 |

### 8.2 实现注意事项

1. **QSS 文件编码**：`style.qss` 用 UTF-8 编码，`main.py` 读取时指定 `encoding="utf-8"`，避免中文注释乱码
2. **objectName 严格匹配**：所有 QSS 选择器依赖 `objectName`（如 `navBar`、`navItem`、`pageTitle`、`primaryBtn`），代码中 `setObjectName` 必须与 QSS 中 `#` 后的名称完全一致
3. **NavBar 互斥选中**：用 `QButtonGroup.setExclusive(True)` 确保同时只有一个导航项 checked，避免多个项高亮
4. **Page 的 refresh() 接口**：4 个 Page 必须都有 `refresh()` 方法，即使占位为空，保证 MainWindow 切换时统一调用不报错
5. **Bridge 信号线程安全**：Qt 的 `Signal` 机制自动跨线程投递，槽函数在接收方线程（主线程）执行，可安全操作 UI；但不要在槽函数中直接调用 Bridge 的控制方法（需通过线程安全接口）
6. **退出清理顺序**：先停止 AsyncWorker（等待后台线程退出），再关闭数据库连接，避免后台线程访问已关闭的连接
7. **窗口关闭确认**：`closeEvent` 中弹窗确认，避免用户误关闭中断下载；确认后 `event.accept()`，主事件循环退出后执行 `_cleanup`
8. **图标路径兼容**：图标路径用 `Path(__file__).parent` 相对定位，确保打包后（PyInstaller `--add-data`）路径正确；本里程碑可暂用绝对路径或占位
9. **ruff/black 范围**：UI 代码同样需通过 ruff/black 检查，注意 PySide6 的 `Signal`/`Slot` 装饰器导入规范
10. **覆盖率 omit**：`pyproject.toml` 的 `[tool.coverage.run] omit` 必须含 `ui/*`，避免 UI 代码拉低整体覆盖率（设计文档 9.2 节 UI 不强制覆盖率）

### 8.3 与 UI/UX 规范的合规性

- **色彩**：QSS 中所有颜色值必须严格使用规范 3.1 节定义的 HEX 值，不自创颜色
- **字体**：QSS 全局 `font-family` 必须含 `"Microsoft YaHei UI"`（规范 3.2.1 节）
- **间距**：所有 `padding`/`margin` 必须是 4 的倍数（规范 3.3 节 8px 网格）
- **圆角**：按钮 4px、卡片 8px、弹窗 12px（规范 3.4 节），不自调整
- **组件状态**：按钮的 hover/pressed/disabled 颜色必须与规范 4.2 节表格一致
- **导航栏**：宽 200px 固定，选中项 3px 品牌紫左边框 + `#F5F0FF` 底色（规范 4.1 节）
