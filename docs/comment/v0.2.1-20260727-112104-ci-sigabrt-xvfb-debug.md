# v0.2.1 CI pytest-qt SIGABRT（Qt 无显示服务器）debug 记录

**时间**: 2026-07-27 11:21:04
**触发**: v0.2.1 CI/CD libEGL 修复推送后，CI 第三次运行失败
**状态**: 已修复

## 问题描述

CI workflow 的 `单元测试` 步骤在第一个使用 `qapp` fixture 的测试处崩溃，报 `Fatal Python error: Aborted`，退出码 134（SIGABRT）：

```
Fatal Python error: Aborted

Current thread 0x00007f04be465b80 (most recent call first):
  File ".../pytestqt/plugin.py", line 76 in qapp
  File ".../pytest/fixtures.py", line 1005 in call_fixture_func
  ...
tests/test_async_worker.py ..
Aborted (core dumped) pytest ...
Error: Process completed with exit code 134.
```

## 根因分析

### 1. libEGL 修复后 pytest 能启动，但 qapp fixture 仍崩溃

上一轮修复了 `libEGL.so.1` 缺失，pytest-qt 的 `pytest_configure` 阶段（import QtGui）通过了。但问题转移到 **运行时**——当第一个测试请求 `qapp` fixture 时，pytest-qt 尝试创建真实的 `QApplication` 实例，需要在 Linux 上初始化 Qt GUI 后端，此时需要 **X11 显示服务器**。

### 2. GitHub Actions ubuntu-latest 无 X11 显示服务

```
ubuntu-latest 默认没有安装 X11 / Xvfb 虚拟显示服务
QApplication 初始化时找不到 DISPLAY 环境变量
Qt 无法连接显示服务器，调用 abort() 终止进程
```

### 3. 为什么本地 Windows 正常

Qt for Windows 自带窗口系统集成，不依赖 X11，本地开发环境无此问题。

### 4. 涉及范围

所有依赖 `qapp` fixture 的测试文件都会被影响（共 16 个文件），包括：
- `tests/conftest.py`（`async_worker` fixture 依赖 `qapp`）
- `tests/test_async_worker.py`
- `tests/test_crawler_bridge.py`
- `tests/test_download_bridge.py`
- `tests/test_fetch_page.py`
- `tests/test_mock_integration.py`（本次新增的 CI 可跑集成测试）
- 其他 UI 组件测试

## 修复方案

Linux 无头环境运行 Qt 程序的标准方案：**Xvfb（X Virtual Framebuffer）**。

在 CI 中：
1. 安装 `xvfb` 包（提供 Xvfb 虚拟显示服务）
2. 启动 Xvfb 虚拟显示（分配虚拟 DISPLAY）
3. 用 `xvfb-run` 包装 pytest 命令，自动设置 DISPLAY 环境变量

```yaml
- name: 安装 Qt 系统依赖与 Xvfb
  run: |
    sudo apt-get update
    sudo apt-get install -y libegl1 libgl1 libglib2.0-0 xvfb

- name: 单元测试（排除 e2e）
  run: |
    xvfb-run pytest tests/ --ignore=tests/test_e2e \
      -o addopts="" \
      --cov=. --cov-report=xml --cov-report=term-missing
```

### 备选方案（未采用）

1. **`QT_QPA_PLATFORM=offscreen`**：让 Qt 使用 offscreen 平台插件，不依赖 X11。这是最轻量的方案，但某些 Qt 测试（依赖窗口大小、像素操作等）可能行为异常。本次保留 env 设置作为双保险。
2. **改用 windows-latest runner**：能彻底避免 X11 问题，但消耗更多 CI 额度。

## 验证

本地为 Windows 环境，无法直接复现 Linux X11 缺失问题。修复后通过以下方式验证：
- 本地 `pytest` 仍通过（确认未引入回归）
- 本地 `ruff` + `black` 通过
- 推送后 CI 运行确认 xvfb-run 下 Qt 测试通过

## 后续建议

Xvfb 是 Linux CI 跑 Qt 测试的事实标准方案，稳定可靠。若未来 GitHub Actions 的 ubuntu 镜像变更导致 xvfb 包名变化，需同步更新。
