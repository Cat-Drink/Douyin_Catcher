# v0.2.1 CI pytest-qt libEGL.so.1 缺失 debug 记录

**时间**: 2026-07-27 10:48:27
**触发**: v0.2.1 CI/CD UP042 修复推送后，CI 再次运行失败
**状态**: 已修复

## 问题描述

CI workflow 的 `单元测试（排除 e2e）` 步骤在 `pytest_configure` 阶段崩溃，报 `INTERNALERROR`：

```
INTERNALERROR>   File ".../pytestqt/plugin.py", line 241, in pytest_configure
INTERNALERROR>     qt_api.set_qt_api(config.getini("qt_api"))
INTERNALERROR>   File ".../pytestqt/qt_compat.py", line 108, in set_qt_api
INTERNALERROR>     self.QtGui = _import_module("QtGui")
INTERNALERROR> ImportError: libEGL.so.1: cannot open shared object file: No such file or directory
Error: Process completed with exit code 3.
```

## 根因分析

### 1. pytest-qt 在配置阶段强制加载 Qt

`pytestqt` 插件在 `pytest_configure`（pytest 启动最早期阶段）就调用 `qt_api.set_qt_api()` 尝试 `import PySide6.QtGui`。这意味着**即使测试用例不使用 `qapp` fixture，只要安装了 pytest-qt，import 失败就会导致整个 pytest 崩溃**。

### 2. PySide6.QtGui 依赖 OpenGL 系统库

PySide6 的 QtGui 模块在 Linux 上动态链接 `libEGL.so.1`（OpenGL EGL 库），而 `ubuntu-latest` runner 默认未预装此库。

### 3. 影响范围

共 16 个测试文件依赖 `qapp`（pytest-qt）fixture：

```
tests/conftest.py
tests/test_async_worker.py
tests/test_crawler_bridge.py
tests/test_download_bridge.py
tests/test_fetch_page.py
tests/test_mock_integration.py
tests/test_preview_flow.py
tests/test_task_item_widget.py
tests/test_ui_smoke.py
tests/test_e2e/*.py（已被 --ignore 排除）
```

这些测试覆盖了 AsyncWorker、Bridge、UI 组件、mock 集成等核心模块，**无法简单跳过**。

### 4. 平台差异

本项目是 PySide6 (Qt) GUI 桌面应用，本地开发环境为 Windows（PySide6 在 Windows 上自带所有 OpenGL 依赖，无需额外安装）。CI 选用 `ubuntu-latest` 是因为更快更省额度，但需要补装 Linux 下的 Qt 运行时系统依赖。

## 修复方案

在 CI workflow 的 `安装依赖` 步骤前，新增系统依赖安装步骤：

```yaml
- name: 安装 Qt 系统依赖（Linux）
  # PySide6 QtGui 依赖 libEGL.so.1 等 OpenGL 库，ubuntu-latest 默认未预装
  # 缺失会导致 pytest-qt 在 pytest_configure 阶段 import QtGui 失败
  run: |
    sudo apt-get update
    sudo apt-get install -y libegl1 libgl1 libglib2.0-0
```

依赖说明：
- `libegl1`：提供 `libEGL.so.1`（EGL 原生平台图形接口，报错直接缺失的库）
- `libgl1`：提供 `libGL.so.1`（OpenGL 库，QtGui 后续可能依赖）
- `libglib2.0-0`：提供 `libglib-2.0.so.0`（GLib，PySide6 运行时依赖）

### 备选方案（未采用）

1. **改用 windows-latest runner**：能避免系统库问题，但 Windows runner 消耗额度更多、速度更慢。仅在 Linux 方案失败时回退。
2. **设置 `QT_QPA_PLATFORM=offscreen`**：让 Qt 使用离屏渲染平台，不依赖真实显示设备。这是 Linux CI 跑 Qt 测试的常见做法，本次与系统库安装一并配置作为双保险。

## 验证

本地为 Windows 环境，无法直接复现 Linux 缺库问题。修复后通过以下方式验证：
- 本地 `pytest` 仍通过（确认未引入回归）
- 推送后 CI 运行确认 Linux 环境下 pytest-qt 能正常加载 QtGui

## 后续建议

1. **release.yml 无需此修复**：Release workflow 只做 PyInstaller 打包，不跑 pytest-qt，windows-latest 上无此问题。
2. **考虑固定系统依赖版本**：若未来 Ubuntu 镜像升级导致包名变化，需同步更新。
