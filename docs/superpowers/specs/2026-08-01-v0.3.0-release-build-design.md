# v0.3.0 重新打包与 GitHub Release 设计文档

## 1. 目标

基于当前 `master` 最新提交（`035bc9d` docs & fix: v0.3.0 合规与归属更新），重新打包一版 **v0.3.0** 的 Windows 桌面安装包，并同步发布到 GitHub Releases，保持版本号与当前代码一致。

## 2. 约束

- 版本号保持 **0.3.0**，不升级。
- 所有操作在 `build/v0.3.0` 分支上进行，包括本文档。
- 不直接手动上传产物，优先利用现有 CI/CD 流程（`.github/workflows/release.yml`）自动构建并发布 Release。
- 本地先完整验证构建通过，再推 tag 触发 CI。

## 3. 方案

采用「**本地构建验证 → 推送分支 → 打 tag 触发 Release CI**」方案。

理由：
- 项目已有 `.github/workflows/release.yml`，tag 触发可复现构建环境。
- 本地先验证能提前发现 sidecar 或前端构建问题，避免 tag 打错后反复删除重写。
- 与 README 中声明的构建流程一致，产物命名统一。

## 4. 执行步骤

### 4.1 准备分支

```bash
git checkout -b build/v0.3.0
```

确认版本号已是 0.3.0：
- `frontend/src-tauri/tauri.conf.json` 第 4 行
- `frontend/package.json` 第 4 行

### 4.2 本地构建验证

1. 清理旧产物
2. PyInstaller 打包 Python sidecar
3. 重命名为 Tauri 要求的 triple 后缀
4. 前端安装依赖并构建 NSIS 安装包

关键命令与 CI 保持一致：

```bash
# sidecar
pyinstaller --onefile --name backend-sidecar \
  --distpath frontend/src-tauri/binaries \
  --add-data "backend;backend" \
  --add-data "app;app" \
  --add-data "crawlers;crawlers" \
  --add-data "downloader;downloader" \
  --hidden-import uvicorn.logging \
  --hidden-import uvicorn.loops.auto \
  --hidden-import uvicorn.loops.asyncio \
  --hidden-import uvicorn.protocols.http.auto \
  --hidden-import uvicorn.protocols.http.h11_impl \
  --hidden-import uvicorn.protocols.websockets.auto \
  --hidden-import uvicorn.protocols.websockets.wsproto_impl \
  --hidden-import uvicorn.lifespan.on \
  --hidden-import starlette.middleware.cors \
  --hidden-import databases \
  --hidden-import sqlalchemy \
  --hidden-import httpx \
  --hidden-import httpcore \
  --hidden-import anyio \
  --hidden-import sniffio \
  --exclude-module tkinter \
  --exclude-module PyQt5 \
  --exclude-module PySide6 \
  --exclude-module matplotlib \
  --exclude-module numpy \
  --exclude-module pandas \
  --exclude-module PIL \
  --console sidecar_launcher.py

# 重命名
mv frontend/src-tauri/binaries/backend-sidecar.exe \
   frontend/src-tauri/binaries/backend-sidecar-x86_64-pc-windows-msvc.exe

# 前端构建
cd frontend
npm ci
npm run tauri build -- --bundles nsis
```

预期产物：
- `frontend/src-tauri/target/release/bundle/nsis/撷风拾影_0.3.0_x64-setup.exe`
- `frontend/src-tauri/binaries/backend-sidecar-x86_64-pc-windows-msvc.exe`

### 4.3 提交设计文档

将本文档提交到 `build/v0.3.0` 分支。

### 4.4 推送分支与 tag

```bash
git push -u origin build/v0.3.0
git tag -a v0.3.0 -m "Release v0.3.0"
git push origin v0.3.0
```

### 4.5 验证 Release

- 在 GitHub Actions 中查看 `Release` workflow 运行状态。
- 确认 Release 页面出现 `v0.3.0`，并包含安装包与 sidecar。

## 5. 回滚与风险

- 若 tag 已存在，需先删除本地/远端 tag 再重建。当前检查无 `v0.3.0` tag，风险低。
- 若 CI 构建失败，修复问题后可删除 tag 重新推送（GitHub Release 草稿/已发布需手动清理）。
- 本地构建产物目录（`build/`、`frontend/src-tauri/target/`、`frontend/src-tauri/binaries/`）不提交到 git，避免仓库污染。
