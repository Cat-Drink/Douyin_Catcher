## 一、背景与目标

### 1.1 背景

v0.1.0 首版发布后，用户提出 14 项改进需求（见 `docs/comment/Douyin接下来的开发方向.md`），涵盖 UI 微调、布局重构、配置整合、链接解析增强、下载页信息展示、抓取页交互优化、图文类型下载流程等 7 个主题。

### 1.2 目标

将 14 项需求拆解为 v0.1.1~v0.2.0 共 10 个迭代里程碑，按"主题内聚型"策略组织，确保：
- 每个里程碑内高耦合需求一起做，内聚性强、改动局部化、回滚容易
- 简单先做建立信心，底层先于上层，最复杂的需求（#7 图文流程）最后做
- 3 个收尾里程碑（集成测试、打包、发布）确保质量与发布

### 1.3 14 项需求清单

| 编号 | 需求 | 主题 |
|---|---|---|
| #1 | 从分享文本提取短链接并下载 | 链接解析增强 |
| #2 | 下载页显示视频标题 | 下载页信息展示 |
| #3 | 下载对象图标用视频封面 | 下载页信息展示 |

## 二、拆解策略

### 2.1 策略选择

**主题内聚型**：按主题聚合，每个里程碑内高耦合需求一起做，最后 3 个里程碑为测试/打包/发布。

**选择理由**：
1. 内聚性强，改动局部化，回滚容易
2. 简单先做建立信心，底层先于上层
3. 最复杂的需求（#7）能利用前面所有基础

### 2.2 收尾里程碑

3 个收尾里程碑：
- v0.1.8 集成测试与回归
- v0.1.9 打包与预发布验证
- v0.2.0 正式发布

### 2.3 #7 独立里程碑

最复杂的需求 #7（图文类型下载选择流程）独立占据 v0.1.7，需要同时实现"抓取预览（图片+视频+标题+封面先展示）"与"用户勾选后下载"两个子能力。

## 五、各里程碑详细范围

### 5.1 v0.1.1 - UI 微调与版本号一致性

**涉及需求**：#5（侧边栏文字蓝色边框）、#11（版本号同步）、#13（移除非客户区标题栏）

**核心任务**：
- 移除非客户区标题栏（保留窗口拖动与系统按钮）
- 修复侧边栏选中态蓝边框（移除 outline/border，仅保留底色变化）
- 版本号统一管理（抽取 `_APP_VERSION` 常量，三处同步为 0.1.1）

**关键决策**：
- 标题栏移除采用"保留系统标题栏仅隐藏文字"方案（低风险），不使用 `Qt.FramelessWindowHint`
- 版本号常量 `_APP_VERSION` 定义在 `ui/main_window.py` 顶部，供其他 UI 模块引用

**详细计划**：`docs/plans/v0.1.1-UI微调与版本号一致性.md`

### 5.2 v0.1.2 - 下载页布局重构

**涉及需求**：#10（开始下载按钮位置）、#14（底部边栏固定到侧边栏底部）

**核心任务**：
- 开始下载按钮移位至"开始解析"右侧末端，与右边界保持 24px 距离
- 底部状态栏（总数/下载中/已完成/失败）从下载页移到侧边栏底部固定区域
- 4 个操作页面底部边栏全部移除

**关键决策**：
- 状态栏数据通过 Bridge 信号全局刷新，不依赖页面切换
- `_refresh_nav_status` 需加 300ms 防抖避免高频刷新
- 抓取页下载目录显示暂保留，v0.1.3 再移除

**详细计划**：`docs/plans/v0.1.2-下载页布局重构.md`

### 5.3 v0.1.3 - 配置整合

**涉及需求**：#9（下载目录仅在设置页）、#12（长视频定义 ≥30 分钟）

**核心任务**：
- 抓取页移除下载目录输入框与浏览按钮（统一从设置页读取）
- 新增 `LONG_VIDEO_DURATION_THRESHOLD = 1800`（30 分钟，秒）常量
- 类型判定改为按时长：`duration >= 1800` -> `long_video`
- 图集判定优先（`image_count > 0` 先判定）

**关键决策**：
- 长视频阈值常量定义在 `downloader/constants.py`（新建），单一来源
- 图集判定优先，避免图集被误判为长视频
- 阈值边界：`>=` 表示 30 分钟整也算长视频

**详细计划**：`docs/plans/v0.1.3-配置整合.md`

### 5.4 v0.1.4 - 下载页信息展示

**涉及需求**：#2（下载页显示标题）、#3（下载对象图标用视频封面）

**核心任务**：
- 确认/补充 `TaskItem` 的 `title`、`cover_url` 字段（可能需 DB schema 迁移）
- 解析阶段写入 `title`、`cover_url` 到 DB
- 任务行显示标题（超长省略，空则显示"未命名"）
- 缩略图改用视频封面（异步加载，失败静默降级）

**关键决策**：
- 若 `TaskItem` 缺少字段需 DB 迁移，已有记录字段为空，UI 显示"未命名"与占位图
- 封面 URL 失效时静默降级，不弹窗不报错
- 标题为空时显示"未命名 (aweme_id)"，而非空 aweme_id

**详细计划**：`docs/plans/v0.1.4-下载页信息展示.md`

### 5.5 v0.1.5 - 链接解析增强

**涉及需求**：#1（从分享文本提取短链接）、#8（抓取时解析图文/视频类型并显示）

**核心任务**：
- `URLParser.parse()` 支持完整分享文本输入，正则提取 `https://v.douyin.com/xxx/` 短链接
- 多行输入逐行解析，跳过空行与无法匹配的行（不抛异常）
- 确认 `type` 字段三态（video/image_set/long_video）
- Bridge 透传 `type` 字段到 result dict
- 抓取结果项右侧显示类型标签（视频紫/图文蓝/长视频橙）

**关键决策**：
- 短链接正则保守匹配：`r'https?://v\.douyin\.com/[A-Za-z0-9]+/?'`，宁可漏匹配也不要误匹配
- `parse()` 改为批量返回 `list[ParsedURL]`，或新增 `parse_batch()` 方法避免破坏调用方

**详细计划**：`docs/plans/v0.1.5-链接解析增强.md`

---

### 5.6 v0.1.6 - 抓取页交互优化

**涉及需求**：#4（全选联动）、#6（提交后清理抓取页内容）

**核心任务**：
- 全选联动逻辑：手动勾选全部 N 项时，全选复选框自动同步
- 三态全选复选框：未选（Qt.Unchecked）/ 部分选（Qt.PartiallyChecked）/ 全选（Qt.Checked）
- 提交下载后清理：清空输入框、结果列表、过滤栏，Toast 提示"已加入下载队列"
- 取消解析时清理：保留输入文本，清空部分结果

**关键决策**：
- 使用三态全选复选框（用户确认），`setTristate(True)` 启用
- 提交清理时机严格在 Bridge 返回 `download_started` 信号后，失败时不清理
- 全选联动用标志位 `_syncing_select_all` 防止递归

**详细计划**：`docs/plans/v0.1.6-抓取页交互优化.md`

### 5.7 v0.1.7 - 图文类型下载流程

**涉及需求**：#7（图文类型提供下载选择，先抓取标题/封面/图片/视频给用户选择，选中后再下载）

**这是本轮最复杂的里程碑**，涉及爬虫层、数据层、UI 层三层的协同改动。

**核心流程变更**：
- 当前流程：用户输入链接 -> 解析 -> 直接入队下载（全量下载）
- 新流程：用户输入链接 -> 解析 -> 抓取预览数据 -> 展示预览给用户选择 -> 用户勾选 -> 入队下载（仅勾选项）

**核心任务**：
- 新增 `PreviewItem` dataclass（`app/preview_models.py`）
- DB schema 变更：`task_items` 表新增 `selected_image_indices` 字段（JSON 数组）
- Bridge 新增 `parse_for_preview()` 方法与 `preview_completed`/`preview_failed` 信号
- 抓取页预览模式：PreviewItemWidget 含标题/封面/类型/图片数，图集可展开预览图片
- 图片级勾选：图集展开后可单独勾选某几张图片
- 下载入队改造：`add_task_items()` 支持图片级勾选，仅下载勾选图片
- 图片直链时效性处理：下载前若直链失效，调用 `VideoParser.parse()` 重新获取
- 任务行图片数进度：图集任务行显示"已下载 M/N 张"

**关键决策**：
- 需要 DB schema 变更（用户确认）：`selected_image_indices` 字段持久化图片级勾选状态
- 图片直链时效性：下载操作必要则重新解析（用户确认）
- `parse_for_preview` 与 `parse_links` 并存，不破坏原流程
- 图集任务行进度显示"已下载 M/N 张"而非字节数

**详细计划**：`docs/plans/v0.1.7-图文类型下载流程.md`

## 七、风险与缓解

### 7.1 整体风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| v0.1.7 图文流程复杂度高 | 开发周期长 | 独立里程碑，资源充分；依赖 v0.1.4/v0.1.5/v0.1.6 基础 |
| DB schema 变更影响已有任务 | 已有记录字段为空 | DEFAULT '' 表示全选；UI 显示进度时处理空值 |
| 图片直链时效性 | 下载阶段直链失效 | 下载前校验，失效时重新解析；重新解析失败标记任务失败 |
| 打包阻塞（icon.ico/截图缺失） | 无法打包 | v0.1.9 必须补齐；可生成占位图 |
| 真实 API 风控 | 集成测试间歇性失败 | 签名被服务端接受（`status_code==0`）即视为通过 |
| 干净 VM 缺 VC 运行时 | 应用启动报错 | PyInstaller 通常打包 VC 运行时；Release Notes 提示 |

## 九、实施约束

### 9.1 沿用 v0.1.0 的全局约束

- 核心功能不能完全依赖开源项目
- 代码覆盖率 ≥ 80%
- 不修改 `docs/structure/` 文档
- CI/CD 暂不实现
- 测试不依赖真实网络请求（集成测试骨架除外，需真实 Cookie 才运行）
- UI 层不强制覆盖率但需通过 ruff/black
- PowerShell 不支持 heredoc，需用多个 `-m` 参数进行 git commit

### 9.2 本轮新增约束

- 所有新 e2e 测试必须自带 `pytestmark = pytest.mark.integration`（修复 v0.1.0 教训）
- DB schema 变更必须幂等（检查列是否存在）
- 图片直链失效时重新解析，不直接标记失败
- 预览模式与原 `parse_links` 并存，不破坏原流程
