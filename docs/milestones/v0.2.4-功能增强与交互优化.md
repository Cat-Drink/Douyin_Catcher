## 4. 任务清单

### 任务 1：保存文件命名规则（#4）

#### 1.1 目标

实现新的文件保存命名规则：本地保存文件标题采用"作者名 + 源媒体标题"的采集前若干字作为文件名；图文类型保存为同名文件夹，内部文件加 `-1`、`-2` 后缀；视频类型直接使用该标题作为文件名。

#### 1.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `download_engine/`（下载器相关） | 修改 | 文件命名逻辑 |
| `ui/pages/settings_page.py` | 修改 | 增加命名规则设置项（可选） |
| 配置相关 | 修改 | 保存命名截取字数配置 |

#### 1.3 设计要点

1. **命名规则**：
   - 格式：`{作者名}_{源媒体标题前N个字}`
   - N 默认值：20 个字符（中文算 1 个字，不是 2 个字节）
   - 示例：作者"旅行者"，标题"美丽的海边日落风景欣赏" → `旅行者_美丽的海边日落风景欣赏`
   - 如果标题长度不足 N 个字，取全部

2. **图文文件夹结构**：
   ```
   旅行者_美丽的海边日落风景欣赏/
   ├── 旅行者_美丽的海边日落风景欣赏-1.jpg
   ├── 旅行者_美丽的海边日落风景欣赏-2.jpg
   └── ...
   ```
   - 文件夹名 = 命名规则结果
   - 内部文件名 = 命名规则结果 + `-{序号}` + 扩展名
   - 序号从 1 开始

3. **视频文件**：
   - `旅行者_美丽的海边日落风景欣赏.mp4`
   - 直接使用命名规则结果作为文件名

4. **配置项**（可选，可放在设置页）：
   - 截取字数 N（默认 20，范围 10-50）
   - 开关：是否启用作者名前缀

5. **兼容性**：
   - 已有文件的命名规则保持不变（不回溯修改已下载文件）
   - 文件名中的非法字符（`\ / : * ? " < > |`）需替换为下划线 `_`
   - 文件名长度不超过 Windows 260 字符限制

#### 1.4 验证点

- 视频下载后文件名 = `作者名_标题前N字.mp4`
- 图文下载后文件夹名 = `作者名_标题前N字`，内部文件 = `作者名_标题前N字-1.jpg`
- 标题不足 N 字时取全部
- 非法字符被替换为下划线
- 文件名总长度不超过 260 字符
- 原有已下载文件不受影响

### 任务 2：图文下载中失效处理（#9）

#### 2.1 目标

明确处理图文下载中途资源失效（403/404/连接超时等）的策略，为用户提供清晰的反馈和重试机制。

#### 2.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `download_engine/` | 修改 | 图片下载失败处理逻辑 |
| `crawlers/video_parser.py` | 修改 | 图片直链失效时重新解析 |
| `ui/widgets/task_item_widget.py` | 修改 | 图集任务行的失败状态展示 |

#### 2.3 设计要点

1. **失效检测**：
   - HTTP 403/404 响应 → 图片直链失效
   - 连接超时 / DNS 解析失败 → 网络异常（可重试）
   - 服务器返回非图片内容（Content-Type 非 image/*）→ 资源异常

2. **分路下载与自动重试**（用户决策方案）：
   - **分路并发**：图文内各图片分路并发下载，彼此独立，某一张失败不阻塞其他图片
   - **失效图片单独重试**：某张图片失效（403/404/超时）时，仅对**该张**单独重试，最多重试 **3 次**
   - **其他图片继续**：重试期间，其他图片正常并发下载，不受影响
   - **3 次重试仍失败**：标记该张为失败，任务行显示"已完成 X/Y 张，1 张失败"
   - **全部图片均失败**：任务标记为失败，提示"图文资源已失效，请确认链接是否有效"

3. **手动重试（用户决策方案）**：
   - 任务列表中为图文任务保留**手动重试按钮**（类似"刷新一下"）
   - 点击后对该图文重新执行一次完整的**解析 + 下载**新流程
   - 新流程获取最新的 `image_urls` 直链，并重新下载
   - 适用于自动重试 3 次仍失败后，或用户怀疑链接失效想重新拉取的场景

4. **用户提示**：
   - 任务行进度条变为红色（部分失败），显示"X/Y 张，N 张失败"
   - 任务行下方显示失败原因："图片 xxx 下载失败（404）"
   - 失败状态的任务行显示手动重试按钮

5. **与现有架构的兼容**：
   - 复用 `_should_retry` 机制，对 4xx 区分处理（图片直链失效 vs 其他错误）
   - 复用 `_download_image_set` 中的并发下载逻辑，改为分路独立重试
   - 手动重试按钮复用现有的 `parse_video` + 下载入队链路

#### 2.4 验证点

- 图文分路并发下载，各图片独立
- 单张图片失效时，仅对该张重试，最多 3 次
- 重试期间其他图片正常下载
- 3 次重试仍失败，标记该张失败，不影响其他图片
- 全部图片均失败时，任务标记为失败并提示
- 任务行显示"M/N 张 + 失败张数"
- 失败任务行有手动重试按钮
- 手动重试触发完整的解析 + 下载新流程，获取最新直链

### 任务 3：Cookie 测试提示位置优化（#11）

#### 3.1 目标

优化手动点击 Cookie 测试按钮时的结果反馈方式，将弹窗提示改为在 Cookie 列表行内即时显示测试结果（用户决策方案）。

#### 3.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/pages/cookie_page.py` | 修改 | Cookie 测试结果展示方式 |
| `ui/widgets/cookie_item_widget.py` | 修改 | 行内测试状态展示 |

#### 3.3 设计要点

1. **方案 A：行内即时反馈（推荐）**
   - 点击"测试"按钮后，该 Cookie 行的状态文字区域直接显示测试结果
   - 测试中：状态灯变为黄色闪烁 + 文字"测试中..."
   - 测试通过：状态灯变为绿色 + 文字"有效 ✓"
   - 测试失败：状态灯变为红色 + 文字"失效 ✗" + 行内显示失败原因（小字）
   - 无需弹窗，减少用户操作中断

2. **方案 B：居中弹窗（备选）**
   - 点击"测试"后，在页面正中央显示模态弹窗
   - 弹窗内容：测试中动画 → 测试结果（有效/失效 + 原因）
   - 弹窗尺寸：较小（320x200），轻量级
   - 自动关闭（2 秒后）或点击关闭

3. **推荐方案 A** 的理由：
   - 减少弹窗干扰，符合"非技术用户"的简洁体验
   - 与"全部测试"功能的行为一致（全部测试时也是逐行更新状态）
   - 用户可同时测试多个 Cookie，不受弹窗阻挡

#### 3.4 验证点

- 点击测试按钮后，行内即时显示测试状态
- 测试中/有效/失效三种状态视觉区分清晰
- 状态灯颜色同步更新
- 失效原因在行内显示，不弹窗

### 任务 4：页面拆分 — 批量抓取与主页抓取（#13）

#### 4.1 目标

将当前链接抓取页拆分为"批量抓取"和"主页抓取"两个独立页面，各自职责单一，减少用户认知负担。

#### 4.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/pages/fetch_page.py` | 拆分 | 拆分为批量抓取和主页抓取两个页面 |
| `ui/pages/batch_fetch_page.py` | 新建 | 批量抓取页面（原单链接/批量链接解析功能） |
| `ui/pages/profile_fetch_page.py` | 新建 | 主页抓取页面（原用户主页抓取功能） |
| `ui/widgets/nav_bar.py` | 修改 | 导航栏增加一个页面入口 |
| `main.py` | 修改 | 注册新页面到导航系统 |
| `style.qss` | 修改 | 新页面的样式补充 |

#### 4.3 设计要点

1. **页面职责划分**：

   **批量抓取页（Batch Fetch）**：
   - 输入框：粘贴多个抖音链接（视频/图文/长视频）
   - 操作：导入文件、开始解析
   - 结果列表：展示解析结果，勾选后下载
   - 适用场景：用户同时有多个链接需要下载

   **主页抓取页（Profile Fetch）**：
   - 输入框：粘贴单个用户主页链接
   - 过滤栏：类型（全部/视频/图文/长视频）、数量上限、时间段
   - 操作：开始抓取（带进度指示）
   - 结果列表：展示主页作品，勾选后下载
   - 适用场景：用户想下载某个博主的所有/部分作品

2. **导航栏变更**：
   - 当前导航栏：下载任务 | 链接抓取 | Cookie 配置 | 设置
   - 新导航栏：下载任务 | 批量抓取 | 主页抓取 | Cookie 配置 | 设置
   - 图标：批量抓取用 `link` 图标，主页抓取用 `user` 图标

3. **代码复用**：
   - 共享的解析结果列表组件、缩略图加载器、勾选逻辑等提取为公共组件
   - 过滤栏组件（`filter_bar.py`）仅在主页抓取页使用
   - 输入框组件可复用但各有不同的 placeholder 文案

4. **过渡方案**：
   - 原 `fetch_page.py` 可保留为内部基类，或拆分为两个独立文件
   - 用户数据（Cookie、配置）不受影响

#### 4.4 验证点

- 批量抓取页：粘贴链接、解析、勾选、下载功能正常
- 主页抓取页：粘贴主页链接、设置过滤条件、抓取、勾选、下载功能正常
- 导航栏显示 5 个页面入口，图标正确
- 页面切换正常，无空白或报错
- 现有功能（Cookie 配置、设置、下载任务页）不受影响

## 7. 设计依据与决策记录

### 7.1 保存命名规则

| 决策项 | 决策 | 理由 |
|---|---|---|
| 命名格式 | `{作者名}_{标题前N字}` | 用户明确要求，且可避免文件名冲突 |
| 默认截取字数 | 20 字 | 兼顾文件名长度和可读性 |
| 图文文件夹 | 同名文件夹，内部 `-1`、`-2` 后缀 | 用户明确要求 |
| 非法字符处理 | 替换为下划线 `_` | Windows 文件系统限制 |
| 已有文件 | 不回溯修改 | 避免意外破坏已有数据 |

### 7.2 图文失效处理

| 决策项 | 决策 | 理由 |
|---|---|---|
| 下载模型 | 分路并发，各图片独立 | 用户明确要求，失效不影响其他图片 |
| 自动重试 | 仅对失效图片单独重试，最多 3 次 | 用户明确要求，避免频繁请求触发限流 |
| 全部失效 | 标记任务失败并提示 | 超过自动重试上限后明确告知用户 |
| 手动重试 | 任务列表保留按钮，触发完整解析+下载新流程 | 用户明确要求"类似刷新"，重新拉取最新直链 |

### 7.3 Cookie 测试反馈

| 决策项 | 决策 | 理由 |
|---|---|---|
| 反馈方式 | 行内即时反馈（方案 A） | 减少弹窗干扰，与全部测试行为一致 |
| 测试中状态 | 黄色闪烁灯 + "测试中..." | 符合现有状态灯设计规范 |
| 失败原因 | 行内小字显示 | 用户可即时看到失败原因 |

### 7.4 页面拆分

| 决策项 | 决策 | 理由 |
|---|---|---|
| 页面数量 | 5 个导航页 | 职责单一，但导航栏保持简洁 |
| 图标 | 批量抓取=link，主页抓取=user | 语义清晰，用户直观理解 |
| 代码复用 | 提取公共组件 | 避免重复代码，维护性更好 |

### 7.5 引导中文选项

| 决策项 | 决策 | 理由 |
|---|---|---|
| 语言选择入口 | 引导页面增加语言选择 | 用户明确要求，在引导第一步选择语言 |
| 默认语言 | 简体中文 | 目标用户为中文用户 |
| 安装向导语言 | 通过 `installer.iss` 的 `Languages` 段配置 | 与应用引导语言保持一致 |

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 页面拆分导致导航栏过长 | 小窗口下导航项拥挤 | 5 项导航在 200px 宽度下足够排列；必要时可折叠 |
| 图文失效处理重试触发限流 | 频繁请求导致 IP 被限 | 仅对失效图片单独重试最多 3 次；手动重试需用户主动触发，增加冷却时间 |
| 文件命名含非法字符 | 保存失败 | 预替换所有非法字符为下划线，并在保存前再次校验 |
| 页面拆分后原有用户数据迁移 | 数据丢失 | 仅拆分 UI，数据层（SQLite）不变，不影响已有数据 |

### 8.2 实现注意事项

1. **保存命名规则（任务 1）**：需在设置页增加"文件命名"配置项，允许用户自定义截取字数。同时需考虑文件名在 Windows 下的长度限制（260 字符），中文每个字算 1 个字符，但 UTF-8 编码下每个中文字符占 3 字节，需确保最终文件名总字节数不超过限制。

2. **图文失效处理（任务 2）**：参考 v0.1.7 中已实现的 `_download_image_set` 和 `_should_retry` 逻辑，复用现有的重试机制。注意区分"图片直链失效（需重新解析）"和"网络异常（可立即重试）"。

3. **Cookie 测试提示（任务 3）**：行内反馈需确保 `cookie_item_widget.py` 有足够的空间展示测试状态文字，必要时调整行高。

4. **页面拆分（任务 4）**：建议先完成代码分析，识别 `fetch_page.py` 中哪些逻辑是批量抓取专用的、哪些是主页抓取专用的、哪些是共享的。将共享逻辑提取为基类或工具函数后，再分别实现两个页面。

5. **引导中文选项（任务 5）**：检查 `onboarding_page.py` 中是否有遗漏的硬编码英文文案。安装向导的 `Languages` 配置需在 `installer.iss` 中确认。
