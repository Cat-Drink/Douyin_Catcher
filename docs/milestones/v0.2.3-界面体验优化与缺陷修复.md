## 2. 里程碑概述

### 2.1 里程碑定位

本里程碑是 v0.2.2 VM 验证发布后的首个体验优化里程碑，聚焦用户反馈中 11 项界面布局、视觉缺陷、焦点态等问题，以快速迭代方式修复，不引入新功能或架构调整。

```
里程碑序列：
  v0.2.2 正式发布                              ✅ 前置依赖（已完成）
  v0.2.3 界面体验优化与缺陷修复                  ◄── 本里程碑
```

### 任务 3：移除展开/收起蓝色边框 + 全局按钮焦点框（#3, #5）

#### 3.1 目标

移除展开/收起操作时文字周围的蓝色焦点框，以及全局所有按钮类型控件点击时出现的蓝色焦点框（outline）。

#### 3.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/assets/style.qss` | 修改 | 修改/移除 `QPushButton:focus` 的 outline 规则 |
| `ui/pages/fetch_page.py` | 修改 | 展开/收起控件的焦点处理 |

#### 3.3 实现要点

1. **全局按钮焦点框**：
   - 当前 `style.qss:544` 有 `QPushButton:focus { outline: 2px solid #B388FF; outline-offset: 2px; }`
   - 用户明确不想要蓝色框圈住文字，因此移除该全局 `outline` 规则
   - 替代方案：保留键盘焦点可见性，通过按钮背景色变化（如 hover 态 `#F3F4F6`）或内阴影来表达焦点状态，而非使用蓝色 outline
   - 检查所有按钮类型：`QPushButton`、`QPushButton#primaryBtn`、`QPushButton#secondaryBtn`、`QPushButton#dangerBtn`、`QPushButton#textBtn`、`QPushButton#navItem` 等

2. **展开/收起蓝色边框**：
   - 定位展开/收起控件（可能是 QPushButton 或 QLabel），移除其焦点 outline
   - 确保点击展开/收起时文字周围不出现蓝色轮廓

3. **键盘辅助功能保留**：
   - 不应因移除 outline 而完全丧失键盘焦点可感知性
   - 建议通过背景色（如 `background-color: #F3F4F6`）替代 outline 作为焦点指示

#### 3.4 验证点

- 所有按钮点击时无蓝色 outline 出现
- 展开/收起文字无蓝色边框
- Tab 键导航仍可感知焦点位置（通过背景色变化）
- 导航按钮选中态不受影响（左侧紫色指示条保持）

### 任务 6：修复进度条完成态颜色异常（#8）

#### 6.1 目标

修复成功下载完成后进度条有时未正确显示完成态颜色、而显示为灰色的缺陷。

**根因（代码核对确认）**：`task_item_widget.py:289` 调用 `setProperty("state", "completed")` 并执行 `unpolish/polish` 刷新，但 `style.qss` 中**仅有 `QProgressBar::chunk` 默认样式（`#7C3AED` 紫色），完全缺少 `QProgressBar[state="completed"]::chunk`、`[state="failed"]::chunk`、`[state="downloading"]::chunk`、`[state="paused"]::chunk` 的状态样式规则**。因此 `setProperty` 刷新后样式无变化，进度条 chunk 始终为默认紫色，在特定显示条件下被用户感知为"灰色"。

#### 6.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/assets/style.qss` | 修改 | 补充进度条各状态的 chunk 样式规则（当前仅 236-239 行有默认 chunk 样式） |
| `ui/widgets/task_item_widget.py` | 修改（可选） | 确认 `setProperty` 后 `unpolish/polish` 刷新逻辑正确 |

#### 6.3 实现要点

1. 在 `style.qss` 的 `QProgressBar::chunk` 默认样式之后，补充以下状态样式规则：
   ```css
   /* 下载中：保持主色紫色 */
   QProgressBar[state="downloading"]::chunk {
       background-color: #7C3AED;
   }
   /* 完成态：绿色 */
   QProgressBar[state="completed"]::chunk {
       background-color: #10B981;
   }
   /* 失败态：红色 */
   QProgressBar[state="failed"]::chunk {
       background-color: #EF4444;
   }
   /* 暂停态：灰色 */
   QProgressBar[state="paused"]::chunk {
       background-color: #9CA3AF;
   }
   ```
2. 确认 `task_item_widget.py` 的 `update_status` 方法中 `setProperty("state", ...)` 的 state 值与 QSS 选择器完全匹配（当前为 `completed`/`failed`/`downloading`/`paused`，见 286-289 行 `state_map`）
3. 确认 `_refresh_style` 方法（331 行附近）的 `unpolish/polish` 调用顺序正确

#### 6.4 验证点

- 下载完成后进度条稳定显示绿色（`#10B981`）
- 下载失败时进度条显示红色（`#EF4444`）
- 下载中进度条显示紫色（`#7C3AED`）
- 暂停时进度条显示灰色（`#9CA3AF`）
- 灰色异常态不再出现
- 多次下载完成验证，100% 复现绿色

### 任务 9：系统标题栏处理（#14）

#### 9.1 目标

完全移除系统原生标题栏，改为无边框窗口 + 自绘标题栏控件（含最小化/最大化/关闭按钮），满足用户问题 14 的明确要求。

**当前现状（代码核对确认）**：`main_window.py:157-165` 的 `_setup_window` 方法当前采用"低风险方案"，仅 `setWindowTitle("")` 移除标题栏文字，但**保留了系统标题栏**（含最小化/最大化/关闭系统按钮）。用户问题 14 明确指出"窗口完整保留了系统标题栏"，要求彻底移除。

#### 9.2 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/main_window.py` | 修改 | `_setup_window` 改为无边框窗口标志 |
| `ui/widgets/title_bar.py`（新建）或 `ui/main_window.py` 内嵌 | 新建 | 自绘标题栏组件 |

#### 9.3 实现要点

1. **窗口标志改造**：
   - 将 `_setup_window` 中的 `setWindowTitle("")` 替换为 `setWindowFlags(Qt.FramelessWindowHint)`
   - 保留 `setMinimumSize(*MIN_WINDOW_SIZE)` 和 `self.resize(*DEFAULT_WINDOW_SIZE)`

2. **自绘标题栏组件**（`TitleBar`）：
   - 左侧：应用图标 + 窗口标题"撷风拾影"
   - 右上角：最小化按钮、最大化/还原按钮、关闭按钮（使用 `QToolButton` + 图标）
   - 整个标题栏区域作为拖拽手柄：重写 `mousePressEvent`/`mouseMoveEvent`/`mouseReleaseEvent` 实现 `window.move()`
   - 双击标题栏切换最大化/还原：重写 `mouseDoubleClickEvent`

3. **窗口阴影**：
   - `FramelessWindowHint` 会丢失系统阴影，使用 `QGraphicsDropShadowEffect` 或 `setAttribute(Qt.WA_TranslucentBackground)` + 自绘阴影模拟

4. **窗口缩放**：
   - 无边框窗口默认不支持边缘缩放，需在主窗口重写 `nativeEvent` 处理 `WM_NCHITTEST` 实现原生边缘缩放（Windows 原生方案，体验最好）

5. **功能保留**：
   - 最小化/最大化/关闭功能正常
   - 拖拽移动窗口正常
   - 双击标题栏最大化/还原正常
   - 最小窗口尺寸约束（800x600）仍有效

## 7. 风险与注意事项

### 7.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 移除按钮 outline 导致键盘用户无法感知焦点 | 辅助功能降级 | 用背景色变化替代 outline，保留焦点可见性 |
| 无边框窗口改造影响窗口拖拽/缩放 | 窗口操作异常 | 参考 Qt 无边框窗口最佳实践，实现鼠标事件处理 |
| 进度条颜色状态切换不刷新 | 修复后仍异常 | 使用 `style().unpolish()/polish()` 强制刷新，或直接 `setStyleSheet` 切换 |
| 图文中失效处理未纳入本次范围 | 图文下载中途异常无处理 | 明确归入 v0.2.4 处理 |

### 7.2 实现注意事项

1. **按钮焦点框是全局最高频感知问题**，建议优先处理，改动集中在 `style.qss`，风险可控
2. **无边框窗口改造（任务 9）**：已确认采用完全无边框方案，需实现自绘标题栏（拖拽 + 双击最大化 + 最小化/最大化/关闭按钮）及窗口边缘缩放（`WM_NCHITTEST`）
3. **进度条修复（任务 8）**：需检查 `_download_image_set` 等异步回调中状态更新是否遗漏了 `polish()` 刷新
4. **解析后自动勾选（任务 7）**：检查 `PreviewItem` 的 `selected` 属性是否在创建时被错误初始化，或 `from_video_info` 中是否有默认值
5. **卸载显示名（任务 10）**：注意 `UninstallDisplayName` 仅在控制面板显示，不影响安装向导的 `AppName` 和 `AppVerName`
