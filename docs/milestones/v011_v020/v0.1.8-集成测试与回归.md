## 4. 设计依据与技术约束

### 4.1 测试标记规范依据（规范文档 6.3 节）

规范文档第 6.3 节明确：所有端到端测试用 `@pytest.mark.integration` 标记，CI 默认跳过。v0.1.0 的教训是 `conftest.py` 中的 `pytestmark` 不传播，必须在每个 `test_*.py` 文件顶部单独定义。

### 4.2 覆盖率要求依据（设计文档 9.2 节）

- 全局行覆盖率 ≥ 80%
- 维持 v0.1.0 的 96.69% 基线，不允许下降
- 新增代码覆盖率达标

### 4.3 Cookie 清理规范依据（设计文档 9.1 节）

测试后必须清除所有 Cookie 痕迹：`.env`/`.test_cookie.txt` 等文件中 Cookie 字段清空；临时数据库/文件清理。v0.1.0 临时禁用了 `cleanup_cookie_traces` fixture，本里程碑恢复。

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 真实 API 风控导致集成测试间歇性失败 | 测试不稳定 | 签名被服务端接受（`status_code==0`）即视为通过；风控失败不阻断 |
| 长视频阈值改动触发 v0.1.0 长视频集成测试断言失败 | 测试失败 | 同步更新断言 |
| 图集 aweme_id 资源未提供 | 图集测试 skip | 需用户提供；若未提供则跳过，不阻断 |
| 覆盖率下降 | 不达标 | 补充测试，维持 96%+ 基线 |
| `cleanup_cookie_traces` 恢复后误清理用户 Cookie | 用户数据丢失 | fixture 仅清理测试用 Cookie，不影响用户配置 |

### 8.2 实现注意事项
