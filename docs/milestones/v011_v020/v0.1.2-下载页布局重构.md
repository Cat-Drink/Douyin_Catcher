## 4. 设计依据与技术约束

### 4.1 按钮位置依据（用户反馈 #10）

用户反馈明确要求："将开始下载按钮移动到开始解析右侧末端，与边界保持一定距离"。

### 4.2 底部状态栏位置依据（用户反馈 #14）

用户反馈明确要求："将总数、下载中等提示信息的底部边栏固定到侧边栏底部，操作页面的底部不要再保留底部边栏"。

### 4.3 状态栏数据流依据（设计文档 8.2 节）

设计文档第 8.2 节分层职责边界规定：UI 通过 Bridge 发出的信号接收结果。状态栏数据来自 `TaskItemRepository.get_by_status()` 统计，需通过 Bridge 信号触发刷新。

### 4.4 全局状态栏刷新机制

底部状态栏移至侧边栏后，需在以下时机刷新：
- 应用启动时（从 DB 加载初始统计）
- Bridge 发出 `progress_updated`/`item_completed`/`item_failed` 信号时
- 任务入队/清空时

### 任务 1：开始下载按钮移位

#### 1.1 目标

将抓取页"开始下载"按钮从原底部操作栏位置移动到"开始解析"按钮右侧末端，与右边界保持 24px 距离。

#### 1.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `ui/pages/fetch_page.py` | 修改 | 按钮位置调整 |

#### 1.3 布局调整

**当前布局**（v0.1.1）：
```
[56px 标题区]
[输入区: QPlainTextEdit + 导入文件按钮]
[操作行: 开始解析按钮]
[过滤栏（条件显示）]
[列表头: 全选 + 已选计数]
[解析结果列表]
[56px 底部操作栏: 下载目录 + 浏览 + 开始下载(N)]  ← 当前位置
```

**目标布局**（v0.1.2）：
```
[56px 标题区]
[输入区: QPlainTextEdit + 导入文件按钮]
[操作行: 开始解析按钮          开始下载(N)]  ← 移至此处，右对齐，距右边界 24px
[过滤栏（条件显示）]
[列表头: 全选 + 已选计数]
[解析结果列表]
[56px 底部操作栏: 下载目录 + 浏览]  ← 仅保留下载目录（v0.1.3 移除）
```

#### 1.4 实现要点

1. 将 `_download_btn` 从底部操作栏布局移除
2. 在操作行布局（`_parse_btn` 所在行）右侧添加 `_download_btn`
3. 操作行布局改为 `QHBoxLayout`：左侧 `addWidget(_parse_btn)` + `addStretch()` + `addWidget(_download_btn)`
4. 设置 `_download_btn` 的右边距为 24px（`setContentsMargins` 或布局 `setSpacing`）
5. 底部操作栏仅保留下载目录输入框与浏览按钮（v0.1.3 移除）

#### 1.5 验证点

- "开始下载"按钮位于"开始解析"按钮右侧
- 按钮与窗口右边界保持 24px 距离
- 按钮文字"开始下载 (N)"正确显示已选数量
- N=0 时按钮禁用

| `ui/assets/style.qss` | 修改 | 侧边栏底部状态栏样式 |

#### 2.3 侧边栏布局调整

**当前侧边栏布局**（v0.1.1）：
```
[导航按钮: 下载任务]
[导航按钮: 链接抓取]

**目标侧边栏布局**（v0.1.2）：

[addStretch]
[状态栏: 总数 N · 下载中 N · 已完成 N · 失败 N]  ← 新增固定区域
```

#### 2.4 NavBar 类修改

**新增成员**：

| 成员 | 签名 | 行为描述 |
|---|---|---|
| `_status_label` | `QLabel` | 状态栏标签，显示"总数 N · 下载中 N · 已完成 N · 失败 N" |
| `update_status` | `(self, total: int, downloading: int, completed: int, failed: int) -> None` | 更新状态栏文字 |

**布局**：在 `addStretch` 之后 `addWidget(_status_label)`，使其固定在侧边栏底部。

#### 2.5 DownloadPage 类修改

**移除成员**：
- `_status_label`（页面底部状态栏标签）
- `update_status_bar` 方法（统计逻辑移至主窗口或保留供主窗口调用）

#### 2.6 MainWindow 类修改

**新增成员**：

| 成员 | 签名 | 行为描述 |
|---|---|---|
| `_refresh_nav_status` | `(self) -> None` | 从 `TaskItemRepository` 统计各状态数量，调用 `nav_bar.update_status()` |

**Bridge 信号连接**：

| Bridge 信号 | 连接到 | 行为 |
|---|---|---|
| `progress_updated` | `_refresh_nav_status` | 实时刷新侧边栏状态栏 |
| `item_completed` | `_refresh_nav_status` | 完成时刷新 |
| `item_failed` | `_refresh_nav_status` | 失败时刷新 |
| `item_added`（若有） | `_refresh_nav_status` | 入队时刷新 |

#### 2.7 QSS 样式

```css

    font-size: 11px;
    color: #6B7280;  /* Secondary */
    padding: 8px 16px;
    border-top: 1px solid #E5E7EB;
}
```

#### 2.8 验证点

- 侧边栏底部显示"总数 N · 下载中 N · 已完成 N · 失败 N"
- 切换到非下载页时，状态栏仍可见且数据正确

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 状态栏数据实时刷新不及时 | 用户看到的统计数字滞后 | 确保所有任务状态变化都触发 `_refresh_nav_status`；考虑 300ms 防抖避免高频刷新 |
| 侧边栏底部状态栏挤占导航按钮空间 | 窄屏下导航按钮被压缩 | 状态栏高度固定 32px，文字 11px，不影响导航按钮 |
| QSS border-bottom 移除影响其他样式 | 其他组件边框异常 | 全量回归测试所有页面样式 |
| Bridge 信号未覆盖入队场景 | 入队后状态栏不更新 | 确认 `add_task_items` 是否发出信号，若无则补充 |

### 8.2 实现注意事项

1. **状态栏防抖**：`progress_updated` 信号高频触发，`_refresh_nav_status` 需加 300ms 防抖（QTimer）
2. **状态栏初始数据**：应用启动时从 DB 加载初始统计，不依赖信号触发
3. **按钮移位后信号连接**：`_download_btn` 的 `clicked` 信号连接保持不变，仅位置调整
4. **下载目录暂保留**：本里程碑仅移位开始下载按钮，下载目录显示与浏览按钮暂保留在底部操作栏，v0.1.3 再移除
