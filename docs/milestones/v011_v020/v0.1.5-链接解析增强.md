### 4.1 分享文本提取依据（用户反馈 #1）


### 4.2 类型标签显示依据（用户反馈 #8）

用户反馈明确要求："链接抓取的时候就要解析是图文还是视频，在抓取列表项的右侧就显示出来"。

### 4.3 短链接正则策略

保守匹配 `https://v.douyin.com/xxx/` 格式：
- 正则：`r'https?://v\.douyin\.com/[A-Za-z0-9]+/?'`
- 不匹配描述文字中的其他内容
- 提取后调用已有的 `follow_redirect()` 获取真实链接

### 4.4 类型判定依据（v0.1.3 已完成）

`VideoInfo.type` 字段判定（v0.1.3 已实现）：
- `image_count > 0` -> `image_set`
- `duration >= LONG_VIDEO_DURATION_THRESHOLD`（1800 秒）-> `long_video`
- 其他 -> `video`

| `type` 值 | 标签文字 | objectName | 背景色 | 文字色 |

### 任务 1：分享文本短链接提取

#### 1.1 目标

`URLParser.parse()` 增强为支持完整分享文本输入，自动从中匹配 `https://v.douyin.com/xxx/` 短链接。

#### 1.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `crawlers/url_parser.py` | 修改 | 新增分享文本提取逻辑 |

#### 1.3 实现要点

**新增正则常量**：
```python
import re

_SHORT_URL_PATTERN = re.compile(r'https?://v\.douyin\.com/[A-Za-z0-9]+/?')
```

**`URLParser.parse()` 增强逻辑**：
1. 输入文本可能含多行内容
2. 对每行用 `_SHORT_URL_PATTERN` 搜索，提取所有匹配的短链接
3. 对每个短链接调用 `follow_redirect()` 获取真实链接
4. 走 `extract_aweme_id`/`extract_sec_user_id` 识别类型
5. 跳过无法匹配的行（不抛异常）

**新增方法**：
```python
def extract_short_urls(self, text: str) -> list[str]:
    """从文本中提取所有抖音短链接。"""
    return _SHORT_URL_PATTERN.findall(text)
```

#### 1.4 多行输入容错

**`parse()` 方法改造**：
```python
def parse(self, text: str) -> list[ParsedURL]:
    """解析多行文本，返回所有有效链接的 ParsedURL 列表。"""
    results = []
    for line in text.splitlines():
        line = line.strip()
        if not line:
            continue
        short_urls = self.extract_short_urls(line)
        if not short_urls:
            continue  # 跳过无法匹配的行
        for short_url in short_urls:
            try:
                real_url = await self.follow_redirect(short_url)
                parsed = self._parse_single(real_url)
                if parsed:
                    results.append(parsed)
            except Exception:
                continue  # 跳过解析失败的链接
    return results
```

#### 1.5 验证点

- 输入完整分享文本能正确提取短链接
- 输入纯链接仍能正常解析
- 多行混合输入（含描述文字、空行、有效链接）能跳过无效行
- 无法匹配的行不抛异常

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 抖音分享文本格式变化 | 短链接提取失效 | 正则保守匹配，定期维护；漏匹配不报错，仅跳过该行 |
| 短链接 follow 遇风控 | 解析失败 | 复用 `HttpClient` 的 Cookie 池与重试机制；失败行跳过不中断 |
| 类型标签 QSS 样式未定义 | 标签显示异常 | 确认 `ui/assets/style.qss` 含 `tagVideo`/`tagImageSet`/`tagLongVideo` 样式 |
| `parse()` 改为批量返回 `list[ParsedURL]` 破坏现有调用方 | 调用方报错 | 保留原 `parse_single()` 方法；`parse()` 改为批量返回；或新增 `parse_batch()` 方法 |

### 8.2 实现注意事项

1. **保守正则**：仅匹配 `https://v.douyin.com/[A-Za-z0-9]+/?`，不扩展到其他域名
2. **逐行解析**：`splitlines()` 分行处理，跳过空行与无法匹配的行
3. **异常隔离**：单行解析失败不影响其他行，`try/except` 包裹
4. **类型标签样式一致**：复用 `task_item_widget.py` 的 objectName 与 QSS，避免样式不一致
5. **`parse()` 方法签名变更**：若原 `parse()` 返回单个 `ParsedURL`，改为返回 `list[ParsedURL]` 可能破坏调用方，需同步更新调用方或新增 `parse_batch()` 方法
