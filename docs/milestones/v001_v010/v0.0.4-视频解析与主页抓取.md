## 1. 里程碑概述

### 1.1 背景

v0.0.4 里程碑在数据层、签名算法、链接解析与 HTTP 客户端三个前置里程碑完成的基础上，实现爬虫组件层的核心业务能力：**视频解析**与**主页抓取**。本里程碑产出可直接被工作线程层与 UI 层调用的业务接口，是连接"基础设施"与"用户可见功能"的关键环节。

### 1.2 前置依赖

| 前置里程碑 | 提供能力 | v0.0.4 使用方式 |
|---|---|---|
| v0.0.1 数据层 | `Database`、`CookieRepository`、`MetadataRepository`、`Cookie` dataclass | Cookie 池取用、元数据持久化 |
| v0.0.2 签名算法 | `Signer` 协议（X-Bogus / A_Bogus / msToken / verifyFp） | VideoParser / UserHomeCrawler 调用前注入签名参数 |
| v0.0.3 链接解析与 HTTP 客户端 | `HttpClient`、`URLParser`、`ParsedURL`、异常类层次结构 | 复用统一请求入口、Cookie 池健康检查、风控错误分类 |

### 1.3 里程碑目标

1. 实现 `VideoParser`：根据 `aweme_id` 调用抖音 `aweme/v1/web/aweme/detail` 接口，提取无水印直链与完整元数据，区分视频 / 图集 / 长视频三种类型。
2. 实现 `UserHomeCrawler`：根据 `sec_user_id` 分页拉取主页作品列表，支持类型 / 数量 / 时间段过滤与进度回调。
3. 实现"测试 Cookie"验证逻辑：通过轻量 API 验证 Cookie 有效性，返回结构化结果。
4. 落地抖音 Web API 调用规范：明确两个核心接口的请求参数、签名要求、响应字段路径与错误处理映射。
5. 配套 VCR.py 录制测试，爬虫层覆盖率 ≥ 75%，且 fixture 不含敏感 Cookie 信息。

### 1.4 范围边界

| 本里程碑包含 | 本里程碑不包含 |
|---|---|
| VideoParser / UserHomeCrawler / CookieTester 的业务逻辑实现 | 下载引擎（v0.0.5） |
| 抖音 Web API 调用规范的代码落地（参数构造、字段提取） | UI 层调用与信号桥接（v0.0.7） |
| VCR.py fixture 录制与单元测试 | 签名算法本身的实现与维护（v0.0.2 已完成） |
| 异常分类与抛出（复用 v0.0.3 已定义异常类） | HttpClient 底层网络与重试机制（v0.0.3 已完成） |
| 元数据提取（点赞/评论/分享/收藏/标签） | 元数据写入 SQLite（由 v0.0.5 下载引擎在完成时触发） |

### 3.3 VideoParser 类

**定义位置**：`crawlers/video_parser.py`

**构造函数**：

```text
__init__(self, http_client: HttpClient, signer: Signer) -> None
```

- 通过依赖注入接收 `HttpClient`（提供签名 + Cookie 注入的请求能力）与 `Signer`（VideoParser 内部不直接调用 sign，保留注入以便未来扩展自定义请求参数）
- 不持有网络连接，所有请求经 `http_client.get()` 发起

**核心方法**：

```text
async def parse_video(self, aweme_id: str, cookie: str) -> VideoInfo
```

**方法职责**：
1. 构造 `aweme/v1/web/aweme/detail` 接口请求参数（业务参数 + 固定参数，见任务 4）
2. 调用 `http_client.get(url, params, cookie=cookie)` 发起请求（签名与 Cookie 注入由 HttpClient 完成）
3. 根据响应特征分类处理（HTTP 状态码 + `status_code` 字段 + HTML 内容判断）
4. 解析 JSON 响应，按 3.2 节字段映射表提取数据
5. 执行无水印直链提取（见 3.4 节）与类型判断（见 3.5 节）
6. 构造并返回 `VideoInfo`

**异常抛出映射**（复用 v0.0.3 已定义的异常类）：

| 响应特征 | 抛出异常 | 异常消息示例 |
|---|---|---|
| HTTP 461 / 412 | `CookieInvalidError` | "Cookie 失效或被限流" |
| HTTP 429 | `RateLimitedError` | "请求过于频繁，请稍后重试" |
| HTTP 200 + `status_code != 0` 且错误码表明作品不存在 | `VideoNotFoundError` | "作品已删除或设为私密" |
| HTTP 200 + 响应含滑动验证 HTML 特征 | `VerifyRequiredError` | "触发抖音安全验证" |
| httpx 连接超时 / DNS 失败 | `NetworkError` | "网络连接失败" |
| 响应 JSON 结构不符合预期（`aweme_detail` 缺失） | `VideoNotFoundError` | "作品详情解析失败" |

**辅助方法（私有）**：

| 方法签名 | 职责 |
|---|---|
| `_build_detail_params(aweme_id: str) -> dict` | 构造 detail 接口业务参数（`aweme_id` + 固定参数），固定参数从 `api_spec.py` 读取 |
| `_detect_video_type(detail: dict) -> VideoType` | 根据响应数据判断 video / image_set / long_video（见 3.5 节） |
| `_extract_no_watermark_url(detail: dict) -> str \| None` | 提取视频无水印直链（见 3.4 节） |
| `_extract_image_urls(detail: dict) -> list[str]` | 提取图集原图直链列表（见 3.4 节） |
| `_extract_tags(detail: dict) -> list[str]` | 从 `text_extra` 提取标签名列表 |
| `_format_duration(ms: int) -> str` | 毫秒转 'MM:SS'（≥ 60s）或 'Xs'（< 60s）展示文本 |
| `_check_verify_html(response: httpx.Response) -> bool` | 检测响应是否为滑动验证 HTML（含 `slider` / `verify` 等特征字符串） |

### 3.4 无水印直链提取逻辑

#### 3.4.1 视频类型（video / long_video）

**主路径**：从 `aweme_detail.video.play_addr.url_list[0]` 取首个 URL。

**回退路径**（当主路径返回的 URL 含 `playwm` 水印标记时）：将 URL 中的子串 `playwm` 替换为 `play`，得到无水印直链。

**实现要点**：
- 优先使用 `url_list[0]`，若列表为空则返回 None 并记录日志
- 替换逻辑仅对含 `playwm` 的 URL 生效，避免误改其他 URL
- 替换后可选校验：URL 是否以 `https://` 开头（防止协议被破坏）

#### 3.4.2 图集类型（image_set）

**提取路径**：遍历 `aweme_detail.images` 数组，对每个元素取 `url_list[0]`，组成列表返回。

**实现要点**：
- `images` 字段可能缺失或为空，此时返回空列表
- 单张图片的 `url_list` 可能为空，跳过该项
- 不对图片 URL 做水印替换（图集原图本身无水印）

### 3.5 类型判断规则

**判断方法**：`_detect_video_type(detail: dict) -> VideoType`

**判断顺序**（严格按以下顺序，先命中先返回）：

| 步骤 | 判断条件 | 返回类型 |
|---|---|---|
| 1 | `detail.get("images")` 非空（列表长度 > 0） | `"image_set"` |
| 2 | `detail.get("video", {}).get("duration", 0) > 60000`（时长 > 60 秒） | `"long_video"` |
| 3 | 其他情况（含 `aweme_type == 0` 且无 images） | `"video"` |

> **说明**：`aweme_type` 字段（0=视频，68/150=图集等）仅作为辅助参考，不作为主要判断依据，因为抖音可能调整类型编码。以"是否有 images 字段"和"duration 是否 > 60s"为准，更稳定。

### 3.6 错误处理流程

```text
parse_video(aweme_id, cookie)
    │
    ▼
http_client.get(detail_url, params, cookie=cookie)
    │
    ├─ 网络异常 → 抛 NetworkError
    │
    ├─ HTTP 461/412 → 抛 CookieInvalidError
    ├─ HTTP 429     → 抛 RateLimitedError
    │
    ▼
检查响应是否为验证 HTML（_check_verify_html）
    │
    ├─ 是 → 抛 VerifyRequiredError
    │
    ▼
解析 JSON
    │
    ├─ JSON 解析失败 → 抛 NetworkError（响应格式异常）
    │
    ▼
检查 status_code 字段
    │
    ├─ status_code != 0 → 抛 VideoNotFoundError（含 status_msg）
    │
    ▼
检查 aweme_detail 是否存在
    │
    ├─ 缺失 → 抛 VideoNotFoundError
    │
    ▼
_detect_video_type → _extract_no_watermark_url / _extract_image_urls
    │
    ▼
构造 VideoInfo 并返回
```

### 4.2 数据结构

#### 4.2.1 HomeFilters dataclass

**定义位置**：`crawlers/user_home_crawler.py`

| 字段名 | 类型 | 默认值 | 说明 |

### 4.3 UserHomeCrawler 类

**定义位置**：`crawlers/user_home_crawler.py`

**构造函数**：

```text
__init__(self, http_client: HttpClient, signer: Signer) -> None
```

**核心方法**：

```text
async def fetch_user_posts(
    self,
    sec_user_id: str,
    filters: HomeFilters,
    cookie: str,
    progress_callback: Callable[[int], None] | None = None,
) -> AsyncIterator[PostItem]
```

**方法职责**：
1. 维护分页游标 `max_cursor`，初始为 `0`
2. 循环调用 `aweme/v1/web/aweme/post` 接口（参数见任务 4）
3. 每页响应解析出 `aweme_list`，逐条构造 `PostItem`
4. 对每个 PostItem 应用过滤逻辑（见 4.4 节），符合条件则 `yield`
5. 每拉取一页后调用 `progress_callback(已抓取总数)` 通知调用方进度
6. 根据 `has_more` 与 `max_count` 决定是否继续翻页
7. 异常情况按 4.5 节处理

**分页循环伪逻辑**（不写实现代码，仅描述流程）：

```text
max_cursor = 0
yielded_count = 0
fetched_count = 0

while True:
    response = http_client.get(post_url, params={sec_user_id, max_cursor, count=20, ...}, cookie=cookie)
    检查响应（同 3.6 节错误处理）
    aweme_list = response.json()["aweme_list"]
    has_more = response.json()["has_more"]
    next_cursor = response.json()["max_cursor"]

    for aweme in aweme_list:
        fetched_count += 1
        item = _build_post_item(aweme)
        if _match_filters(item, filters):
            yield item
            yielded_count += 1
            if filters.max_count > 0 and yielded_count >= filters.max_count:
                return  # 达到数量上限，提前结束

    progress_callback(fetched_count)  # 通知已抓取总数（含未通过过滤的）

    if has_more != 1:
        return  # 无更多作品
    if next_cursor == max_cursor:
        return  # 游标未变化，防止死循环
    max_cursor = next_cursor
```

**辅助方法（私有）**：

| 方法签名 | 职责 |
|---|---|
| `_build_post_params(sec_user_id: str, max_cursor: int) -> dict` | 构造 post 接口业务参数 |
| `_build_post_item(aweme: dict) -> PostItem` | 从单条 aweme 节点构造 PostItem |
| `_match_filters(item: PostItem, filters: HomeFilters) -> bool` | 应用过滤逻辑（见 4.4 节） |
| `_detect_type(aweme: dict) -> str` | 同 3.5 节类型判断规则 |
| `_check_verify_html(response: httpx.Response) -> bool` | 检测滑动验证 HTML（复用 VideoParser 的实现或提取为公共函数） |

### 4.4 过滤逻辑

**过滤方法**：`_match_filters(item: PostItem, filters: HomeFilters) -> bool`

**过滤维度**（全部为内存中过滤，不打额外 API）：

| 维度 | 过滤条件 | 不过滤的情况 |
|---|---|---|
| 类型过滤 | `filters.type_filter == "all"` 或 `item.type == filters.type_filter` | `type_filter == "all"` |
| 时间段过滤（起始） | `filters.start_date is None` 或 `item.create_time >= start_date` | `start_date is None` |
| 时间段过滤（结束） | `filters.end_date is None` 或 `item.create_time <= end_date + 23:59:59` | `end_date is None` |
| 数量上限 | 由 `fetch_user_posts` 主循环控制（达到上限提前 return），不在本方法内 | `max_count == 0` |

**实现要点**：
- 日期比较：将 `item.create_time`（ISO8601）与 `start_date` / `end_date`（`YYYY-MM-DD`）统一转为 Unix 时间戳比较
- `end_date` 含当天：结束时间按当日 23:59:59 计算
- 多个条件为 AND 关系，全部满足才返回 True

### 4.5 错误处理

**异常抛出映射**：

| 响应特征 | 抛出异常 | 说明 |
|---|---|---|
| HTTP 461 / 412 | `CookieInvalidError` | Cookie 失效 |
| HTTP 429 | `RateLimitedError` | 触发限流 |
| HTTP 200 + `status_code != 0` 且错误码表明用户不存在 | `UserNotFoundError` | 用户主页不存在或不可见 |
| HTTP 200 + 响应含验证 HTML | `VerifyRequiredError` | 触发安全验证 |
| httpx 网络异常 | `NetworkError` | 网络连接失败 |
| 响应 JSON 缺失 `aweme_list` 字段 | 视为空列表，正常结束迭代 | 容错处理 |

> **说明**：主页抓取过程中，单页失败会终止整个抓取（因为是顺序分页）。不实现单条跳过重试——重试由上层调用方（工作线程）决定是否重新发起整个抓取任务。

### 4.6 进度回调

**回调签名**：`progress_callback: Callable[[int], None] | None`

**调用时机**：
- 每完成一页拉取（解析完该页所有 aweme 后）调用一次
- 传入参数为"已抓取总数"（累计遍历过的 aweme 数量，含未通过过滤的）
- 用于 UI 显示"已抓取 N 条"

**实现要点**：
- 回调为可选参数，为 None 时跳过调用
- 回调同步执行（在 asyncio 协程内直接调用，不另起线程）
- 回调内部异常不应中断抓取：用 try/except 包裹回调调用，异常仅记录日志

## 5. 任务 3："测试 Cookie"验证逻辑

### 5.1 涉及文件

| 文件路径 | 操作 | 说明 |
|---|---|---|
| `crawlers/cookie_tester.py` | 新建 | CookieTester 类与 CookieTestResult dataclass |
| `crawlers/__init__.py` | 编辑 | 导出 CookieTester、CookieTestResult |

> **说明**：接口文档 7.3 节将"测试 Cookie"逻辑的触发入口放在 `CookieRepository.test_all()`，但实际的网络验证逻辑独立为 `CookieTester` 类，符合单一职责原则。`CookieRepository` 负责数据持久化，`CookieTester` 负责网络验证，二者通过工作线程层组合调用。

### 5.2 数据结构：CookieTestResult dataclass

**定义位置**：`crawlers/cookie_tester.py`

| 字段名 | 类型 | 说明 |
|---|---|---|
| `is_valid` | `bool` | Cookie 是否有效 |
| `error_message` | `str` | 无效时的具体错误信息；有效时为空字符串 |
| `user_nickname` | `str \| None` | 有效时返回当前登录用户昵称（若 API 响应包含）；无效时为 None |

**实现要求**：
- 使用 `@dataclass(frozen=True)`

### 5.3 CookieTester 类

**定义位置**：`crawlers/cookie_tester.py`

**构造函数**：

```text
__init__(self, http_client: HttpClient, signer: Signer) -> None
```

**核心方法**：

```text
async def test_cookie(self, cookie_content: str) -> CookieTestResult
```

**方法职责**：
1. 选择轻量 API 验证 Cookie（推荐 `aweme/v1/web/general/search/single/`，备选见任务 4 的 4.3 节）
2. 构造请求参数（`keyword=test`、`count=10`、`offset=0` + 固定参数）
3. 调用 `http_client.get(url, params, cookie=cookie_content)` 发起请求
4. 根据响应特征判断 Cookie 有效性（见 5.4 节）
5. 返回 `CookieTestResult`

**辅助方法（私有）**：

| 方法签名 | 职责 |
|---|---|
| `_build_test_params() -> dict` | 构造测试接口业务参数 |
| `_extract_user_nickname(response: httpx.Response) -> str \| None` | 从响应中尝试提取用户昵称（若接口返回） |
| `_check_verify_html(response: httpx.Response) -> bool` | 检测滑动验证 HTML |

### 5.4 验证逻辑

**判断规则**（按顺序判断，先命中先返回）：

| 响应特征 | 判定 | 返回结果 |
|---|---|---|
| HTTP 200 + `status_code == 0` | 有效 | `CookieTestResult(is_valid=True, error_message="", user_nickname=...)` |
| HTTP 461 / 412 | 无效 | `is_valid=False, error_message="Cookie 失效或被限流"` |
| HTTP 200 + `status_code != 0` | 无效 | `is_valid=False, error_message=<status_msg 字段值>` |
| HTTP 200 + 响应含验证 HTML | 无效 | `is_valid=False, error_message="触发抖音安全验证"` |
| httpx 网络异常 | 无法判定 | `is_valid=False, error_message="网络异常：{具体描述}"` |

**实现要点**：
- 网络异常时 `is_valid` 返回 False（与接口文档 7.3 节"无法判定 → untested"略有差异：本里程碑统一返回 False，由调用方根据 error_message 区分"无效"与"网络问题"，避免引入第三种状态增加 UI 复杂度）
- `user_nickname` 提取：search/single 接口响应中通常不含用户昵称，需调用备选接口（`aweme/v1/web/user/profile/self/`）获取。本里程碑优先用 search/single 验证有效性，`user_nickname` 字段在无法获取时返回 None，不阻塞验证流程

### 5.5 批量测试支持（可选扩展）

**方法签名**：

```text
async def test_all(self, cookies: list[tuple[int, str]]) -> list[tuple[int, CookieTestResult]]
```

**职责**：批量测试多个 Cookie，返回 `(cookie_id, result)` 列表。内部用 `asyncio.gather` 并发测试（受 HttpClient 内部 Semaphore 约束）。

> **说明**：本方法为可选扩展，若 v0.0.4 时间紧张可推迟到 v0.0.6（Cookie 配置页 UI）实现。单条 `test_cookie` 为必须实现项。

#### 7.2.1 VCR.py 配置

**配置位置**：`tests/conftest.py`

**配置要求**：

| 配置项 | 值 | 说明 |

#### 7.2.2 录制流程

1. **申请 Cookie**：开发者从浏览器获取测试 Cookie，存入本地 `.env` 文件（`DOUYIN_TEST_COOKIE`、`DOUYIN_TEST_SEC_USER_ID`、`DOUYIN_TEST_AWEME_ID`、`DOUYIN_TEST_IMAGE_SET_AWEME_ID`）
2. **首次录制**：运行测试时 VCR.py 自动录制真实响应到 `tests/fixtures/*.yaml`
3. **擦除敏感信息**：VCR.py 配置自动擦除 `Cookie` / `Set-Cookie` 头
4. **人工核对**：录制完成后人工检查 fixture 文件，确认不含真实 Cookie 字符串
5. **后续回放**：CI 与其他开发者运行测试时直接回放 fixture，无需真实 Cookie
6. **清除 Cookie**：录制完成后清空 `.env` 中的 Cookie 字段（不删除文件，保留模板）

#### 7.2.3 敏感信息检查清单

录制后的 fixture 文件提交前，逐项检查：

- [ ] 不含 `Cookie:` 头
- [ ] 不含 `Set-Cookie:` 头
- [ ] 不含 `Authorization:` 头
- [ ] 不含 `ttwid`、`msToken`、`passport_csrf_token` 等 Cookie 字段值
- [ ] 不含真实用户昵称、uid 等可识别信息（必要时用占位符替换）
- [ ] URL 中的 `sec_user_id`、`aweme_id` 可保留（非敏感，且测试需要匹配）

## 10. 风险与注意事项

### 10.1 技术风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 抖音 API 字段路径变更 | VideoParser / UserHomeCrawler 解析失败 | 字段路径集中在 `api_spec.py`，变更时单点修改；增加防御性取值（`dict.get` + 默认值） |
| 抖音风控升级，响应结构变化 | 验证 HTML 检测失效 | `VERIFY_HTML_MARKERS` 维护多个特征字符串，定期更新 |
| VCR.py fixture 录制时网络不稳定 | 录制失败 | 录制时确保网络稳定；录制失败可重试，fixture 未生成时测试自动跳过（标记 `@pytest.mark.skipif`） |
| 签名算法在录制后失效 | fixture 回放正常但真实调用失败 | fixture 回放不依赖签名有效性（VCR.py 按 URL 匹配，不校验签名）；真实调用失败由 v0.0.2 签名算法维护 |
| 图集 images 字段结构变化 | image_urls 提取失败 | 增加类型检查与异常捕获，返回空列表而非抛异常 |

### 10.2 安全注意事项

1. **Cookie 不入库**：测试 Cookie 仅存 `.env`（已在 `.gitignore`），严禁硬编码到代码或 fixture
2. **fixture 擦除**：VCR.py 配置 `filter_headers` 擦除 `Cookie` / `Set-Cookie`，录制后人工复核
3. **日志脱敏**：VideoParser / UserHomeCrawler 记录日志时，不得记录完整 Cookie 字符串（仅记录 Cookie 标签或前 8 位）
4. **测试后清除**：录制完成后立即清空 `.env` 中的 Cookie 字段
5. **不提交真实用户数据**：fixture 中的用户昵称、uid 等可识别信息应替换为占位符（如"测试用户"）

### 10.3 与其他里程碑的衔接

| 衔接里程碑 | 衔接点 | 说明 |
|---|---|---|
| v0.0.5 下载引擎 | VideoParser 产出的 `VideoInfo` 含 `no_watermark_url` / `image_urls`，供下载引擎使用 | 本里程碑不触发下载，仅产出直链 |

### 11.3 进度回调使用示例（供 UI 层参考）

> 本节仅为说明进度回调的使用方式，不属本里程碑实现范围。

UI 层（通过工作线程）调用 `fetch_user_posts` 时，传入进度回调函数。回调收到"已抓取总数"后，通过 Qt 信号 `parse_progress(parsed_count, total_count)` 通知 UI 更新进度条。其中 `total_count` 可能为未知（`max_count == 0` 时），UI 层应处理"总数未知"的情况（显示"已抓取 N 条"而非百分比）。
