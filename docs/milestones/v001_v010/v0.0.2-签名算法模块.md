## 任务清单

### 任务 1：异常类定义

| 项 | 内容 |
|---|---|
| 任务描述 | 定义爬虫层异常类层次结构，重点支持签名失败场景。本里程碑定义根异常、爬虫层基类及签名相关异常；其他爬虫异常（链接格式、用户不存在、触发验证）预留位置，在后续里程碑补充 |
| 涉及文件 | `crawlers/exceptions.py`（新建） |

#### 实现要点

1. **异常继承层次**（与接口设计文档第 3.6 节保持一致，并新增 `SignError`）：

```
Exception
└── DouyinCatcherError                    # 项目所有自定义异常的根
    └── CrawlerError                      # 爬虫层异常基类
        ├── CookieInvalidError            # Cookie 失效或被风控
        ├── RateLimitedError              # 触发限流（HTTP 461/412/429）
        ├── VideoNotFoundError            # 作品已删除/私密
        ├── NetworkError                  # 网络异常（连接超时/DNS 失败）
        └── SignError                     # 签名生成失败（本里程碑新增）
```

2. **各类异常的触发场景、用户提示、上层行为**：

| 异常类 | 触发场景 | 用户提示 | 上层行为 |
|---|---|---|---|
| `DouyinCatcherError` | 所有自定义异常的兜底基类，不直接抛出 | "发生未知错误" | 顶层 `except` 兜底 |
| `CrawlerError` | 爬虫层异常基类，不直接抛出 | — | 上层按子类分别处理 |
| `CookieInvalidError` | HTTP 461/412 响应；Cookie 池无可用 Cookie；"测试 Cookie"返回非 0 status_code | "Cookie 已失效，抖音需要重新登录验证" | 跳转 Cookie 配置页 |
| `RateLimitedError` | HTTP 429 或风控限流响应 | "请求过于频繁，请稍后重试" | 该项标记失败，原因提示等待 |
| `VideoNotFoundError` | aweme/detail 返回 status_code 非 0 且错误码表明作品不存在 | "该作品已被删除或设为私密，无法下载" | 跳过该项 |
| `NetworkError` | httpx.ConnectTimeout / httpx.ConnectError / httpx.ReadTimeout 等 | "网络连接失败，请检查网络后重试" | 交给下载引擎重试逻辑 |
| `SignError` | 签名算法内部异常（参数缺失、计算失败、算法不支持的输入等） | "请求签名生成失败" | 标记失败，记录详情供开发者排查 |

3. **`SignError` 设计说明**：
   - 继承自 `CrawlerError`
   - 构造函数接收 `message: str` 与可选 `algorithm: str`（标识失败的具体签名算法，如 `'xbogus'` / `'abogus'`），便于日志定位
   - 签名子模块在内部捕获意外异常时统一转为 `SignError` 抛出，避免裸 `Exception` 上浮

4. **预留异常说明**：接口设计文档第 3.6 节还定义了 `InvalidURLFormatError`、`UserNotFoundError`、`VerifyRequiredError`（爬虫层）及 `DownloaderError` 系列（下载引擎层）。这些异常分别在 v0.0.3（链接解析器）、v0.0.4（视频解析器）、v0.0.6（下载引擎）里程碑中补充，本里程碑不实现，但在 `exceptions.py` 顶部注释中标注完整层次图作为指引。

5. **编码规范**：
   - 所有异常类仅含 `pass` 或调用 `super().__init__()`，无复杂逻辑
   - 每个异常类附 Google 风格文档字符串，说明触发场景与用户提示
   - 使用 `from __future__ import annotations`

#### 验收标准

- [ ] `DouyinCatcherError` 继承自 `Exception`
- [ ] `CrawlerError` 继承自 `DouyinCatcherError`
- [ ] `CookieInvalidError` / `RateLimitedError` / `VideoNotFoundError` / `NetworkError` / `SignError` 均继承自 `CrawlerError`
- [ ] `SignError` 可携带 `algorithm` 属性
- [ ] 每个异常类有文档字符串
- [ ] `ruff check crawlers/exceptions.py` 无报错
- [ ] `black --check crawlers/exceptions.py` 无报错

### 任务 2：X-Bogus 签名算法

| 项 | 内容 |
|---|---|
| 任务描述 | 用纯 Python 自主实现抖音 X-Bogus 签名算法。输入请求 URL（含查询参数）与 User-Agent，输出 X-Bogus 签名字符串 |
| 涉及文件 | `crawlers/signer/xbogus.py`（新建） |

#### 实现要点

1. **参考方向**（不写具体算法逻辑）：
   - 参考 A-Bogus / X-Bogus 算法的公开原理资料（GitHub 上公开的算法分析文档、技术博客）
   - 参考 Evil0ctal/Douyin_TikTok_Download_API 项目的设计思路（仅参考思路，不 vendoring、不 import 其代码）
   - X-Bogus 算法的核心通常涉及：对请求参数串进行字符编码、位运算（位移/异或）、查表混淆、Base64 变体编码

2. **算法输入/输出契约**：
   - 输入：规范化后的请求 URL（含完整查询参数串）+ User-Agent 字符串
   - 输出：X-Bogus 签名字符串（长度与字符集符合抖音前端规律，通常为 28 位左右的 Base64 变体字符串）
   - 同一输入应产生确定输出（算法本身是确定性的，不含随机因子）

3. **模块结构**（建议的函数划分，实现时按算法实际步骤组织）：
   - `class XBogusSigner:` —— 主类
     - `def sign(self, url: str, user_agent: str) -> str:` —— 对外入口，返回 X-Bogus 值
     - 内部私有函数按算法步骤拆分（如参数序列化、位运算处理、混淆编码），具体命名与划分在实现时确定
   - 模块顶部定义算法所需的常量（如查找表、固定盐值、字符集映射），常量命名使用 `UPPER_SNAKE_CASE`

4. **纯 Python 实现约束**：
   - 严禁依赖任何 JS 执行环境（不使用 PyExecJS、Node.js 子进程、pyminiracer 等）
   - 仅使用 Python 标准库（`hashlib`、`base64`、`struct`、`urllib.parse` 等按需使用）
   - 不引入新的第三方依赖

5. **错误处理**：
   - 输入校验：`url` 与 `user_agent` 均为非空字符串，否则抛出 `SignError`（`algorithm='xbogus'`）
   - 算法内部异常（如索引越界、编码错误）捕获后转为 `SignError` 抛出，附带原始异常信息

6. **参数规范化**：
   - URL 查询参数需按抖音前端的排序规则排序后参与签名（通常按键名字典序）
   - 实现时需明确参数排序、URL 编码（百分号编码）的处理方式，与抖音前端保持一致

#### 验收标准

- [ ] `XBogusSigner.sign(url, user_agent)` 返回非空字符串
- [ ] 同一输入多次调用返回一致结果（确定性）
- [ ] 纯 Python 实现，无 JS 执行环境依赖
- [ ] 输入为空字符串时抛出 `SignError`
- [ ] `ruff check` / `black --check` 无报错

### 任务 4：msToken 生成

| 项 | 内容 |
|---|---|
| 任务描述 | 生成随机的 msToken 字符串。msToken 是抖音 Web 请求中的随机性签名参数，无需服务端校验输入，但长度与字符集需符合抖音前端规律 |
| 涉及文件 | `crawlers/signer/mstoken.py`（新建） |

#### 实现要点

1. **参考方向**：
   - msToken 在抖音 Web 请求中为随机生成的 base64 风格字符串
   - 参考抖音 Web 前端请求中实际观察到的 msToken 参数格式（从浏览器开发者工具 Network 面板采集样本）
   - 通常为 128 位（约 170+ 字符的 base64 编码）随机数据

2. **算法输入/输出契约**：
   - 输入：无（纯随机生成）
   - 输出：msToken 字符串
   - 每次调用产生不同的随机值（与 X-Bogus/A_Bogus 的确定性不同）

3. **模块结构**：
   - `class MsTokenGenerator:` —— 主类
     - `def generate(self) -> str:` —— 对外入口，返回 msToken 值
   - 模块顶部定义长度常量（如 `MSTOKEN_LENGTH = 170` 或按实际样本确定）与字符集

4. **实现要点**：
   - 使用 `secrets` 模块（密码学安全的随机数生成器）或 `os.urandom` 生成随机字节，再编码为 base64
   - 字符集与长度需对齐抖音前端实际样本（避免因格式不符被风控拦截）
   - 不依赖时间戳或可预测因子，确保随机性

5. **错误处理**：
   - 随机数生成极少失败；若 `os.urandom` 异常，转为 `SignError`（`algorithm='mstoken'`）抛出

#### 验收标准

- [ ] `MsTokenGenerator.generate()` 返回非空字符串
- [ ] 连续调用 1000 次无重复值
- [ ] 输出字符集与长度符合抖音前端规律（与样本对齐）
- [ ] `ruff check` / `black --check` 无报错

### 任务 5：verify_fp / s_v_web_id 生成

| 项 | 内容 |
|---|---|

### 任务 6：Signer 统一接口

| 项 | 内容 |
|---|---|
| 任务描述 | 实现 Signer 聚合入口，组合四个子模块，对外暴露稳定的签名接口。算法失效时只需修改子模块，调用方代码不变 |
| 涉及文件 | `crawlers/signer/__init__.py`（新建） |

#### 实现要点

1. **接口签名**（扩展接口设计文档第 3.2 节，新增 `user_agent` 参数）：

```python
from __future__ import annotations


class Signer:
    """签名算法模块聚合入口。

    内部组合 XBogusSigner / ABogusSigner / MsTokenGenerator / VerifyFpGenerator
    四个子算法，对外暴露稳定接口。算法失效时只需替换子模块实现。
    """

    def __init__(self, user_agent: str | None = None) -> None:
        """初始化签名器。

        参数:
            user_agent: 默认 User-Agent 字符串。sign() 调用时若未显式传入，
                则使用此默认值。None 时使用模块内置的 PC Chrome 默认 UA。
        """
        ...

    def sign(self, url: str, params: dict, user_agent: str | None = None) -> dict:
        """为请求生成完整的签名参数集合。

        参数:
            url: 请求 URL（不含查询参数）。
            params: 业务请求参数（query / form 数据）。
            user_agent: 本次请求的 User-Agent。None 时使用构造函数传入的默认值。

        返回:
            需要追加到请求中的签名参数字典，包含:
            {
                'X-Bogus': str,
                'a_bogus': str,
                'msToken': str,
                'verifyFp': str,
            }
            调用方将这些参数合并到原 params 后发起请求。

        异常:
            SignError: 任一子算法签名失败。
        """
        ...

    def generate_ms_token(self) -> str:
        """生成 msToken 参数值。"""
        ...

    def generate_verify_fp(self) -> str:
        """生成 verify_fp 参数值。"""
        ...
```

> **接口扩展说明**：接口设计文档第 3.2 节 `Signer.sign(self, url, params)` 未含 `user_agent` 参数。本里程碑因 X-Bogus / A_Bogus 子算法均依赖 User-Agent，故在 `sign()` 与构造函数中增加 `user_agent` 参数（带默认值，向后兼容）。此扩展需同步更新接口设计文档第 3.2 节修订记录。

2. **子模块组合调用逻辑**（`sign()` 内部流程）：
   - 步骤 1：确定 User-Agent（优先用 `sign()` 显式传入，其次用构造函数默认值）
   - 步骤 2：将 `params` 序列化为查询参数串，拼接到 `url` 上得到完整 URL（供 X-Bogus 使用）
   - 步骤 3：调用 `XBogusSigner.sign(完整URL, user_agent)` 得到 `X-Bogus`
   - 步骤 4：调用 `ABogusSigner.sign(params, user_agent)` 得到 `a_bogus`
   - 步骤 5：调用 `MsTokenGenerator.generate()` 得到 `msToken`
   - 步骤 6：调用 `VerifyFpGenerator.generate()` 得到 `verifyFp`
   - 步骤 7：组装为字典返回
   - 任一子算法抛出 `SignError` 时，直接向上抛出（附带算法标识）
   - 子算法抛出其他异常时，包装为 `SignError` 抛出

3. **默认 User-Agent 常量**：
   - 在 `__init__.py` 顶部定义 `DEFAULT_USER_AGENT` 常量，使用主流 PC Chrome UA 字符串
   - 与接口设计文档第 7.1 节"必需请求头"中的 User-Agent 格式一致

4. **包导出**：
   - `crawlers/signer/__init__.py` 中 `from .xbogus import XBogusSigner` 等导入子模块类，并在 `__all__` 中声明 `Signer`、`XBogusSigner`、`ABogusSigner`、`MsTokenGenerator`、`VerifyFpGenerator`
   - 上层调用方通过 `from crawlers.signer import Signer` 使用

5. **依赖方向**：
   - `signer/__init__.py` 依赖四个子模块与 `crawlers.exceptions.SignError`

### Signer 聚合接口

```python
# crawlers/signer/__init__.py
from __future__ import annotations

DEFAULT_USER_AGENT: str  # PC Chrome 默认 UA 常量


class Signer:
    def __init__(self, user_agent: str | None = None) -> None: ...
    def sign(
        self,
        url: str,
        params: dict,
        user_agent: str | None = None,
    ) -> dict: ...
    def generate_ms_token(self) -> str: ...
    def generate_verify_fp(self) -> str: ...
```

### 子模块接口

```python

class XBogusSigner:
    def sign(self, url: str, user_agent: str) -> str: ...

# crawlers/signer/abogus.py
class ABogusSigner:
    def sign(self, params: dict, user_agent: str) -> str: ...

# crawlers/signer/mstoken.py
class MsTokenGenerator:
    def generate(self) -> str: ...

# crawlers/signer/verify_fp.py
class VerifyFpGenerator:
    def generate(self) -> str: ...
    def generate_s_v_web_id(self) -> str: ...
```

### 异常接口

```python
# crawlers/exceptions.py
class DouyinCatcherError(Exception): ...
class CrawlerError(DouyinCatcherError): ...
class CookieInvalidError(CrawlerError): ...
class RateLimitedError(CrawlerError): ...
class VideoNotFoundError(CrawlerError): ...
class NetworkError(CrawlerError): ...

class SignError(CrawlerError):
    def __init__(self, message: str, algorithm: str | None = None) -> None: ...
    algorithm: str | None  # 失败的签名算法标识：'xbogus'/'abogus'/'mstoken'/'verify_fp'
```

```python
    "verifyFp": str,   # VerifyFpGenerator 生成
}
```

## 风险与注意事项

### 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **签名算法随抖音更新失效** | 高 — 签名失效导致所有爬虫请求被拦截 | 接口与实现解耦（`Signer` 聚合入口稳定，子模块可独立替换）；建立应急更新流程（配置规范文档第 10.3 节）；定期验证算法有效性 |
| **算法实现复杂度高** | 中 — X-Bogus / A_Bogus 涉及位运算与混淆逻辑，实现易出错 | 以已知输入/输出对作为正确性锚点；分步骤实现，每步用单元测试验证；参考多个公开资料交叉验证 |
| **真实 API 验证依赖 Cookie** | 中 — 无法在 CI 中自动验证算法对真实 API 有效性 | 单元测试用已知输入/输出对保证算法逻辑正确；真实 API 验证作为可选人工步骤，向用户申请 Cookie 后本地执行 |
| **公开资料与实际算法存在偏差** | 中 — 参考的算法原理可能滞后于抖音最新版本 | 优先以真实请求样本（浏览器抓包）为准；实现后用真实 Cookie 验证；保留多组已知用例覆盖边界 |
| **msToken / verify_fp 格式不符** | 低 — 随机参数格式偏差可能触发风控 | 从浏览器开发者工具采集实际样本，严格对齐长度与字符集 |

### 注意事项

1. **不 vendoring 开源代码**：设计文档第 1.4 节明确要求不 vendoring、不 import Evil0ctal/Douyin_TikTok_Download_API 源码。本里程碑仅参考其设计思路与公开测试数据，签名算法完全自主实现。

2. **Cookie 安全**：
   - 真实 Cookie 仅用于可选的集成测试，存入 `.env`（已加入 `.gitignore`）
   - 严禁在代码、测试用例、日志、fixture 中硬编码 Cookie
   - `known_signer_vectors.json` 提交前人工核对，确保不含 Cookie 字段
   - 测试完成后清除 `.env` 中 Cookie（配置规范文档第 6.1.3 节）

3. **接口扩展需同步文档**：本里程碑对 `Signer.sign()` 新增 `user_agent` 参数、新增 `SignError` 异常，需同步更新接口设计文档（第 3.2 节、第 3.6 节）修订记录。

4. **算法常量管理**：签名算法涉及的查找表、固定盐值、字符集等常量，集中在各子模块顶部以 `UPPER_SNAKE_CASE` 定义，附注释说明来源，便于算法失效时定位与更新。

5. **确定性 vs 随机性**：X-Bogus / A_Bogus 为确定性算法（同输入同输出），测试用已知对验证；msToken / verify_fp 为随机生成，测试用格式与随机性验证，不可用固定输出对。
