## 1. 里程碑概述

### 1.1 背景

v0.0.9 里程碑在数据层、工作线程桥接、UI 框架、UI 页面实现四个前置里程碑完成的基础上，实现面向非技术用户的**首次引导流程**与**错误处理系统**。本里程碑是"产品可用性"的最后一公里，核心目标是落实设计文档第 7.1 节的核心原则：**绝不让用户看到原始异常栈，每个错误都要有人话解释 + 下一步建议**。

本里程碑交付物包括：4 步首次引导流程、8 类错误的统一处理框架、Toast 轻量提示、Loading 遮罩组件、日志导出功能，以及与各业务页面的集成验证。完成后应用具备"开箱即用、出错可懂、操作有反馈"的完整用户体验，为 v1.0.0 正式发布做最后准备。

### 1.2 前置依赖

| 前置里程碑 | 提供能力 | v0.0.9 使用方式 |
|---|---|---|
| v0.0.1 数据层 | `ConfigRepository`（`get_onboarding_done`/`set_onboarding_done`/`get`/`set`）、`CookieRepository`、`app/config.py` 路径常量（`DEFAULT_DOWNLOAD_DIR`、`LOG_DIR`） | 引导状态读写、下载目录默认值、日志目录定位 |
| v0.0.6 工作线程桥接 | `AsyncWorker`（异步任务执行 + 信号桥接）、爬虫层接口（`CookieTester.test_cookie` 等） | Cookie 测试异步调用、Loading 遮罩与异步任务联动 |
| v0.0.7 UI 框架 | `MainWindow`（导航栏 + 页面切换）、全局 QSS 样式表、`PageBase` 基类、信号总线 | 引导流程与主窗口集成、页面切换、样式复用 |
| v0.0.8 UI 页面实现 | `DownloadPage`、`FetchPage`、`CookiePage`、`SettingsPage`、Cookie 教程组件 | 引导完成后跳转主界面、Cookie 引导复用教程组件、设置页接入日志导出 |

### 1.3 里程碑目标

1. 实现 4 步首次引导流程（欢迎 → 目录设置 → Cookie 配置 → 完成），引导状态记录在 `config` 表，后续启动直接进主界面。
2. 实现统一错误处理系统 `ErrorHandler`，覆盖设计文档 7.2 节定义的 8 类错误，每类错误提供"人话解释 + 下一步建议"，并按错误类型分发到任务行级 / 全局弹窗 / 输入框下方三种展示位置。
3. 实现 Toast 轻量提示组件，自动消失、不阻塞 UI，用于操作成功 / 信息 / 警告反馈。
4. 实现 LoadingOverlay 半透明遮罩组件，覆盖父组件、支持取消，用于解析链接 / 测试 Cookie / 主页抓取等耗时操作。
5. 实现设置页"导出日志"按钮，打开日志文件所在目录。
6. 捕获未预期异常，显示"未知错误"弹窗 + 复制详情，避免应用崩溃。
7. 与各业务页面集成验证，确保错误不打断其他任务、Toast 与 Loading 正确联动。

## 3. 任务 1：首次引导框架

### 3.1 涉及文件

| 文件路径 | 操作 | 说明 |
|---|---|---|
| `ui/pages/onboarding_page.py` | 新建 | OnboardingPage 类与 4 个步骤子页面类 |
| `ui/pages/__init__.py` | 编辑 | 导出 OnboardingPage |

### 3.2 设计决策：继承 QWidget（自定义分页）

**决策**：OnboardingPage 继承 `QWidget`，采用自定义分页实现，不使用 `QWizard`。

**理由**：
- `QWizard` 默认样式与应用 QSS 扁平化风格不一致，深度定制成本高
- 自定义分页可完全复用 UI/UX 规范定义的步骤指示器、按钮样式、动画
- 4 步流程固定且简单，自定义分页实现成本低
- 引导页与主窗口共用同一 QSS 样式表，视觉一致性好

### 3.3 OnboardingPage 类

**定义位置**：`ui/pages/onboarding_page.py`

**继承**：`QWidget`

**职责**：管理 4 步引导流程的页面切换、步骤指示器渲染、引导状态读写、与主窗口的跳转衔接。

**构造函数**：

```text
__init__(self, config_repo: ConfigRepository, cookie_repo: CookieRepository,
         async_worker: AsyncWorker, main_window: MainWindow, parent: QWidget | None = None) -> None
```

- 通过依赖注入接收 `ConfigRepository`（读写引导状态）、`CookieRepository`（Cookie 步骤查询已有 Cookie）、`AsyncWorker`（Cookie 测试异步调用）、`MainWindow`（引导完成后跳转主界面）
- 初始化内部 `QStackedWidget` 容纳 4 个步骤子页面
- 初始化步骤指示器（4 个圆点，当前步骤实心、已完成步骤实心、未完成步骤空心）
- 初始化底部导航按钮区（上一步 / 下一步 / 跳过 / 开始使用 / 进入应用，按当前步骤动态显示）

**信号**：

| 信号名 | 签名 | 触发时机 |
|---|---|---|
| `onboarding_completed` | `Signal()` | 引导完成（设置 `onboarding_done=1` 后），主窗口收到后切换到下载任务页 |
| `onboarding_skipped` | `Signal(bool)` | 引导被跳过，参数为 `cookie_configured`（是否已配置 Cookie），主窗口据此决定是否提示用户 |

**核心方法**：

| 方法签名 | 职责 |
|---|---|
| `start() -> None` | 启动引导流程：重置到第 1 步（欢迎页），显示 OnboardingPage |
| `_go_to_step(step_index: int) -> None` | 切换到指定步骤（0-3），更新 QStackedWidget 当前页、步骤指示器、底部按钮显隐 |
| `_next_step() -> None` | 进入下一步（当前步骤 +1），若已是最后一步则触发完成 |
| `_prev_step() -> None` | 返回上一步（当前步骤 -1），第 1 步时禁用 |
| `_skip_onboarding() -> None` | 跳过引导：调用 `ConfigRepository.set_onboarding_done(True)`，发 `onboarding_skipped` 信号 |
| `_complete_onboarding() -> None` | 完成引导：调用 `ConfigRepository.set_onboarding_done(True)`，发 `onboarding_completed` 信号 |
| `_update_step_indicator() -> None` | 刷新步骤指示器圆点状态（当前/已完成/未完成） |
| `_update_nav_buttons() -> None` | 刷新底部导航按钮显隐与启用状态（按当前步骤） |
| `_check_cookie_configured() -> bool` | 查询 `CookieRepository.get_all()` 是否有至少一条 Cookie，用于跳过时判断是否提示 |

**步骤指示器规格**（UI/UX 规范 5.6 节）：
- 4 个圆点水平居中排列，圆点直径 8px，间距 12px
- 当前步骤：实心主色 `#7C3AED`
- 已完成步骤：实心主色 `#7C3AED`
- 未完成步骤：空心 `#D1D5DB`
- 圆点上方/下方可选显示步骤序号文字（12px，Text-Secondary）

**底部导航按钮显隐规则**：

| 步骤 | 上一步 | 下一步/主操作 | 跳过 |
|---|---|---|---|
| 0 欢迎页 | 隐藏 | "开始配置"（主按钮） | 显示（"跳过引导"文本按钮） |
| 1 目录设置 | 显示 | "下一步"（主按钮） | 显示 |
| 2 Cookie 配置 | 显示 | "完成"（主按钮，测试通过后启用） | 显示（"跳过，稍后配置"文本按钮） |
| 3 完成页 | 隐藏 | "开始使用"（主按钮） | 隐藏 |

### 3.4 引导状态管理

**状态键**：`config` 表 `key='onboarding_done'`

**读取**：`ConfigRepository.get_onboarding_done()` 返回 `bool`

**写入**：
- 引导完成（完成页点"开始使用"）：`ConfigRepository.set_onboarding_done(True)`
- 跳过引导（任意步骤点"跳过"）：`ConfigRepository.set_onboarding_done(True)`

> **注意**：无论完成还是跳过，均设置 `onboarding_done=1`，后续启动直接进主界面，不再显示引导。跳过与完成的区别仅在于：跳过时若 Cookie 未配置，主窗口提示用户"未配置 Cookie 无法下载，稍后可在 Cookie 配置页添加"。

### 3.5 应用启动时的引导判断

**集成位置**：`main.py`（应用入口，v0.0.7 已创建）

**判断逻辑**（由 `MainWindow` 或 `main.py` 调用 OnboardingPage 前判断）：

```text
应用启动
    │
    ▼
读取 config.onboarding_done
    │
    ├─ False（未完成引导） → 显示 OnboardingPage（全屏覆盖主窗口内容区）
    │
    └─ True（已完成引导）  → 直接显示主界面（下载任务页）
```

**实现方式**：OnboardingPage 作为 `MainWindow` 的覆盖层显示（`QStackedWidget` 顶层或模态显示），引导完成后 `MainWindow` 移除 OnboardingPage 并显示正常导航 + 下载任务页。

### 5.3 目录可读性检查逻辑

**校验方法**：`_validate_directory(path: str) -> tuple[bool, str]`

**校验步骤**：
1. 路径非空检查：空路径返回 `(False, "请选择下载目录")`
2. 目录创建检查：尝试 `Path(path).mkdir(parents=True, exist_ok=True)`，失败返回 `(False, "目录无法创建，请选择其他位置")`
3. 写入权限检查：尝试在目录下创建临时文件并删除，失败返回 `(False, "目录无写入权限，请选择其他位置")`
4. 全部通过返回 `(True, "")`

**实现要点**：
- 校验在后台快速执行（目录创建是本地 IO，不阻塞 UI，但仍用 try/except 包裹）

### 8.4 handle_error 分发逻辑

**方法签名**：`handle_error(error_type: str, context: dict) -> None`

**参数**：
- `error_type`：错误类型字符串，取值见 8.5 节映射表的 key
- `context`：错误上下文，含以下可选键：
  - `task_item_id`：任务项 ID（任务行级错误必需）
  - `input_widget`：输入框控件（输入错误必需）
  - `details`：错误详情（未知错误用于复制）
  - `directory`：磁盘空间不足时的目录路径
  - `reason`：下载失败的具体原因

**分发逻辑**：

```text
handle_error(error_type, context)
```

#### 8.6.3 输入框下方错误（show_input_error）

**方法签名**：`show_input_error(input_widget: QWidget, message: str) -> None`

**实现方式**：
- `input_widget.setProperty("error", True)` + 刷新样式（`style().unpolish` + `polish`），输入框边框变红 `#EF4444`

### 8.7 未预期异常捕获

**捕获方式**：

1. **Python 全局异常钩子**：`sys.excepthook = exception_handler`
   - 在 `main.py` 中设置，捕获未处理的 Python 异常
   - 调用 `ErrorHandler.handle_error("unknown_error", {"details": traceback.format_exc()})`
   - 避免应用直接崩溃

2. **Qt 事件循环异常捕获**：`qApp` 安装事件过滤器或 `sys.__excepthook__` 兜底
   - 捕获 Qt 信号槽中抛出的异常

**异常处理流程**：

```text
未预期异常发生
    │
    ▼
sys.excepthook 捕获
    │
    ▼
记录完整栈到日志（logger.error(traceback)）
    │
    ▼
ErrorHandler.handle_error("unknown_error", {"details": formatted_traceback})
    │
    ▼
显示"发生未知错误"弹窗 + "复制详情"按钮
    │
    ▼
用户点"复制详情" → 剪贴板写入错误详情
用户点"关闭" → 关闭弹窗，应用继续运行（不退出）
```

**实现要点**：
- 日志记录完整异常栈（便于开发者排查），用户弹窗只显示简短描述
- `unknown_error` 的 `user_message` 中 `{简短描述}` 取异常类名 + 异常消息前 100 字符
- 不主动退出应用（除非是致命的启动错误）

## 16. 风险与注意事项

### 16.1 技术风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| QWizard 样式定制成本高 | 引导页视觉与应用风格不一致 | 已决策使用 QWidget 自定义分页，完全复用 QSS |
| Toast 与 LoadingOverlay 动画在低性能机器卡顿 | 用户体验下降 | 动画时长控制在 200ms，尊重系统"减少动画"设置 |
| Cookie 测试异步调用时序复杂 | LoadingOverlay 显示/隐藏时机错误 | 严格按信号流程：`cookie_test_started` → 显示遮罩 → 结果回传 → `cookie_test_finished` → 隐藏遮罩 |
| 全局异常捕获可能遗漏 Qt 内部异常 | 部分异常仍导致崩溃 | `sys.excepthook` + Qt 事件过滤器双重捕获；关键操作 try/except 兜底 |
| 引导页与主窗口叠加层级处理 | 引导页被主窗口内容遮挡 | OnboardingPage 作为主窗口内容区顶层覆盖，引导完成后移除 |
| Cookie 教程组件复用耦合 | CookieStep 依赖 CookiePage 教程组件 | 教程组件设计为独立可复用 Widget，CookieStep 与 CookiePage 共同 import |

### 16.2 实现注意事项

1. **引导状态一致性**：`onboarding_done` 无论完成还是跳过都设为 `True`，避免反复弹引导。判断逻辑用 `ConfigRepository.get_onboarding_done()` 统一读取。

2. **错误信息人话化**：严格按第 13 节映射表实现，不向用户暴露技术术语（如"HTTP 461"、"status_code != 0"、"asyncio.CancelledError"）。

3. **Toast 单例管理**：同一 parent 同时只显示一个 Toast，新 Toast 显示前主动隐藏旧 Toast，避免堆叠。

4. **LoadingOverlay 父组件跟随**：遮罩需监听 parent 的 resize 事件重新计算几何，否则窗口缩放后遮罩不覆盖全区域。

5. **ErrorHandler 线程安全**：ErrorHandler 在 UI 主线程调用，业务层错误通过信号回传到 UI 线程后再调用 `handle_error`，不跨线程直接调用。

6. **异常捕获不吞错**：`sys.excepthook` 捕获后必须 `logger.error(traceback)` 记录完整栈，不能只弹窗不记录，否则开发者无法排查。

7. **日志目录路径来源**：日志导出使用 `app.config.LOG_DIR`，不硬编码 `%APPDATA%`，保证路径与日志系统一致。

8. **Cookie 教程资源缺失容错**：教程截图 step1-7.png 可能未提供，教程组件加载图片失败时显示占位灰色块 + 步骤文字，不抛异常。
