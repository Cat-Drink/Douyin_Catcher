## 2. 里程碑概述

### 2.1 里程碑定位

本里程碑负责让下载任务页真正对接 Python sidecar 的任务查询与控制接口，完成下载流程的第一条主链路。

### 2.2 前置依赖

| 依赖项 | 来源 | 说明 |
|---|---|---|
| v0.2.3 完成 | 前一里程碑 | 前端原型冻结 |
| v0.2.4 完成 | 前一里程碑 | sidecar API 已可用 |

### 2.3 交付目标

| 目标 | 衡量指标 |
|---|---|
| 下载任务列表可见 | 可从 API 拉取任务列表 |
| 实时状态可见 | 进度和状态通过 WebSocket 刷新 |
| 核心操作可用 | 暂停 / 恢复 / 重试 / 清空已完成可用 |
| 搜索过滤可用 | 标题 / 作者本地过滤正常 |
| 空状态与错误态可用 | 页面在无任务、服务异常时可正确提示 |

---

## 3. 目标与范围

### 3.1 本里程碑包含

| 编号 | 内容 | 归类 | 涉及模块 |
|---|---|---|---|
| 1 | 任务列表查询接入 | 数据展示 | 下载任务页 |
| 2 | WebSocket 进度接入 | 实时刷新 | 任务状态 |
| 3 | 单任务控制接入 | 操作控制 | 暂停 / 恢复 / 重试 |
| 4 | 批量控制接入 | 操作控制 | 全部暂停 / 全部开始 / 清空已完成 |
| 5 | 搜索与过滤接入 | 本地交互 | 搜索栏 |
| 6 | 空状态 / 错误态接入 | 体验补全 | 状态反馈 |

### 3.2 本里程碑不包含

- 解析页接入
- Cookie 和设置页面接入
- 系统托盘和更新能力

### 3.3 范围边界

- 仅处理下载任务页需要的接口和状态
- 不扩展业务模型，不新增下载规则
- 所有进度更新须通过统一通道进入前端状态

## 4. 任务清单

### 任务 1：任务列表查询

#### 目标

将任务列表从 mock 切换为真实 API。

#### 验证点

- 页面打开即显示真实任务
- 空数据时显示空状态

### 任务 2：WebSocket 进度接入

#### 目标

将下载进度、状态变化、完成/失败结果接入前端状态。

#### 验证点

- 进度条随后端变化更新
- 状态变化与后端一致

### 任务 3：单任务控制接入

#### 目标

实现任务暂停、恢复、重试等控制。

#### 验证点

- 单条任务操作生效
- 操作后列表状态刷新

### 任务 4：批量控制接入

#### 目标

实现全部暂停、全部开始、清空已完成。

### 任务 5：搜索与过滤接入

#### 目标

在前端实现标题 / 作者关键词过滤。

### 任务 6：空状态 / 错误态接入

#### 目标

在无任务、接口失败、侧边栏异常时提供清晰反馈。

---

## 5. 验收标准

- 下载任务页显示真实数据
- 进度变化实时可见
- 核心控制操作可用
- 空状态、错误态清晰

---

## 6. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 实时状态不同步 | 页面和后端状态不一致 | 统一事件模型 |
| 控制动作失配 | 前后端任务 ID 映射错误 | 明确 API 契约 |
