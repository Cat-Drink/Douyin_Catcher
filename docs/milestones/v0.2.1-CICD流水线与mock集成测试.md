## 4. 设计依据与技术约束

### 4.1 测试与 lint 配置依据（pyproject.toml）

`pyproject.toml` 是 CI 测试与 lint 的配置来源：
- `requires-python = ">=3.11"`，CI 固定 Python 3.11
- ruff/black `line-length = 100`、`target-version = "py311"`
- pytest `addopts = "--cov=. ... --cov-fail-under=80"`，CI 用 `-o addopts=""` 清空后由命令行显式传覆盖率参数
- markers 含 `integration: 集成测试（需真实 Cookie，CI 默认跳过）`

### 4.2 发布规范依据（规范文档 8.4 节）

规范文档第 8.4 节打包发布规范要求：PyInstaller 打包 → Inno Setup 出安装包 → GitHub Release 上传。Release workflow 将该流程自动化。

### 4.3 版本号注入依据（计划文档第 2 步）

`installer.iss` 原 `OutputBaseFilename=DouyinCatcher_Setup_v0.2.0` 为硬编码。用 ISPP `#ifndef` 守卫改造为可注入：本地编译用默认值，CI 用 `ISCC /DMyAppVersion=<tag版本>` 覆盖，`#define` 与 `OutputBaseFilename` 同时生效。

### 任务 1：创建 CI workflow

#### 1.1 目标

创建 `.github/workflows/ci.yml`，实现 push 到 master / PR 到 master 时自动跑 ruff 检查、black 格式校验、单元测试（排除 e2e）并上传覆盖率到 Codecov。

#### 1.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `.github/workflows/ci.yml` | 新建 | CI 质量门禁 workflow |

#### 1.3 实现步骤

1. 触发与并发控制：
   ```yaml
   on:
     push:
       branches: [master]
     pull_request:
       branches: [master]
   concurrency:
     group: ci-${{ github.ref }}
     cancel-in-progress: true
   ```
   同分支并发推送取消旧任务，节省 CI 资源。

2. 环境变量（Windows runner 下 Qt 测试所需）：
   ```yaml
   env:
     QT_QPA_PLATFORM: windows
     PYTHONFAULTHANDLER: 1
     QT_QUICK_BACKEND: software
   ```

3. Job `lint-test`（runs-on `windows-latest`）步骤：
   - 检出代码（`actions/checkout@v4`）
   - 设置 Python 3.11（`actions/setup-python@v5`，cache pip，依赖 `requirements-dev.txt`）
   - 安装依赖（`pip install -r requirements-dev.txt`）
   - Ruff 检查（`ruff check .`）
   - Black 格式校验（`black --check .`）
   - 单元测试（排除 e2e）：
     ```bash
     pytest tests/ --ignore=tests/test_e2e \
       -o addopts="" \
       --cov=. --cov-report=xml --cov-report=term-missing
     ```
   - 上传覆盖率到 Codecov（`codecov/codecov-action@v4`，`files: ./coverage.xml`，`fail_ci_if_error: false`）

#### 1.4 验证点

- push 到 master 触发 CI
- PR 到 master 触发 CI
- ruff / black 全部通过
- 单元测试通过（排除 e2e）
- `coverage.xml` 生成并上传 Codecov
- 同分支新推送取消旧任务

### 任务 2：创建 Release workflow

#### 2.1 目标

创建 `.github/workflows/release.yml`，实现打 tag `vX.Y.Z` 时自动 PyInstaller 打包、Inno Setup 编译安装包、创建 GitHub Release 并上传安装包。

#### 2.2 文件清单

| 文件 | 类型 | 说明 |
|---|---|---|
| `.github/workflows/release.yml` | 新建 | tag 触发打包发 Release workflow |

#### 2.3 实现步骤

1. 触发：`push tags: ["v*"]`，仅 tag 触发。

2. Job `build-release`（runs-on `windows-latest`，`permissions: contents: write`）步骤：
   - 检出代码
   - 设置 Python 3.11（cache 依赖 `requirements.txt`）
   - 安装依赖与 PyInstaller：`pip install -r requirements.txt pyinstaller`
   - 解析 tag 版本号：
     ```bash
     TAG="${GITHUB_REF#refs/tags/}"
     VERSION="${TAG#v}"   # v0.2.1 -> 0.2.1
     echo "version=$VERSION" >> "$GITHUB_OUTPUT"
     ```
   - PyInstaller 打包：`pyinstaller DouyinCatcher.spec --noconfirm`
   - 校验打包产物（4 个关键文件）：
     ```bash
     test -f dist/DouyinCatcher/DouyinCatcher.exe
     test -f dist/DouyinCatcher/_internal/ui/assets/style.qss
     test -d dist/DouyinCatcher/_internal/ui/assets/cookie_tutorial
     test -f dist/DouyinCatcher/_internal/assets/icon.ico
     ```
     缺失任一即 `exit 1`。
   - 安装 Inno Setup 6：`choco install innosetup -y --no-progress`
   - Inno Setup 编译（注入版本号）：
     ```powershell
     & $iscc.FullName "/DMyAppVersion=$env:APP_VERSION" installer.iss
     ```
   - 校验安装包产物：`test -f dist/DouyinCatcher_Setup_v<版本>.exe`
   - 创建 GitHub Release 并上传安装包（`softprops/action-gh-release@v2`）：
     - `name: v<版本>`
     - `draft: false`
     - `prerelease: ${{ contains(steps.version.outputs.version, '-') }}`（版本号含 `-` 视为预发布）
     - `files: dist/DouyinCatcher_Setup_v<版本>.exe`
     - `generate_release_notes: true`

#### 2.4 验证点

- push 普通分支不触发 Release
- push tag `v*` 触发 Release
- 版本号从 tag 名正确解析
- 打包产物 4 个关键文件齐全
- Inno Setup 编译生成安装包
- GitHub Release 创建并含安装包附件
- 含 `-` 的版本号标记为 prerelease

## 8. 风险与注意事项

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| PySide6 在 Linux 无头环境缺 Qt 依赖 | CI 单测 SIGABRT 崩溃 | **已发生并解决**：ubuntu-latest 需 libEGL/libGL/xvfb，经 3 轮修复仍不稳定，最终切换至 `windows-latest`。Windows runner 原生支持 Qt 测试，与开发环境一致。详见 8.2 实现注意事项第 1 条 |
| Inno Setup 中文语言包缺失 | Release workflow 编译失败 | `choco install innosetup` 含中文语言包；若缺失改用手动下载方案 |
| PyInstaller CI 首次打包 hiddenimports 漏配 | 打包产物运行报模块缺失 | spec 已配较全，风险低；打包后校验 4 个关键文件 |
| mock 集成测试异步时序 | 测试偶发失败或卡死 | 正确处理 AsyncWorker 生命周期，参考 e2e 的 finally 清理模式 |
| ISCC 版本号注入破坏契约测试 | `test_version_consistency.py` 失败 | ISPP 改造不改变默认行为，契约测试仍通过；CI 注入值与 tag 一致 |
| Codecov tokenless 上传失败 | 覆盖率未上报 | `fail_ci_if_error: false`，不阻塞 CI；网络问题重试 |

### 8.2 实现注意事项

1. **CI runner 选型（关键经验）**：首次采用 `ubuntu-latest`，但 PySide6 桌面 GUI 应用在 Linux 无头环境需要 `libEGL.so.1`/`libGL`/`xvfb` 等系统依赖。实际开发经历 4 轮 CI 失败修复：
   - 第 1 轮：Ruff UP042 报错（`str`+`Enum` 应迁移 `StrEnum`），修复枚举类
   - 第 2 轮：pytest-qt 缺 `libEGL.so.1`，安装 Qt 系统依赖
   - 第 3 轮：装 libEGL 后仍 SIGABRT，加 `xvfb-run` 包装 pytest
   - 第 4 轮：仍不稳定，切换至 `windows-latest` 根治
   
   结论：PySide6 桌面 GUI 应用 CI 优先选 `windows-latest`，Qt 测试开箱即用，与开发环境一致。ci.yml 头部注释已记录此历史。

2. **`-o addopts=""` 绕开机制**：`pyproject.toml` 的 `addopts` 含 `--cov-fail-under=80` 与 e2e marker 配置。CI 用 `-o addopts=""` 清空后由命令行显式传 `--cov`/`--cov-report`，避免 marker 冲突，并使覆盖率不强制 80% 阈值（CI 仅上报不阻塞）。

3. **Codecov tokenless**：公开仓库无需配 secret，`codecov-action@v4` 不传 token 即可。`fail_ci_if_error: false` 确保上传失败不阻塞主流程。

4. **仅 tag 触发 Release**：push 到 master 不打包，避免每次提交都产出安装包。只有显式打 tag `vX.Y.Z` 才触发发布流水线。

5. **AppId 固定 GUID**：`installer.iss` 的 `AppId` 影响升级识别，发布后不可更改，CI 不得改动。

6. **ISCC `/D` 注入不改仓库文件**：版本号通过命令行 `/DMyAppVersion=<版本>` 注入，不修改 `installer.iss` 的默认值，本地编译行为保持不变。

7. **mock 集成测试不标记 integration**：故意不标 `@pytest.mark.integration`，使 CI 的 `pytest --ignore=tests/test_e2e` 能跑到它，让 CI 也覆盖集成层。
