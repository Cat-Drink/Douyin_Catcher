## 2. 里程碑概述

### 2.1 里程碑定位

本里程碑负责把现有 Python 代码包装成服务化接口，为前端提供统一访问入口。重点不是重写业务逻辑，而是把现有爬虫、下载、Cookie、配置与数据库能力稳定暴露出去。

### 2.2 前置依赖

| 依赖项 | 来源 | 说明 |
|---|---|---|
| v0.2.3 完成 | 前一里程碑 | 前端原型和设计冻结 |
| 现有 Python 核心代码 | 当前仓库 | 业务逻辑复用基础 |
| FastAPI / Uvicorn | 第三方依赖 | 服务化承载 |

### 2.3 交付目标

| 目标 | 衡量指标 |
|---|---|
| Python 服务可启动 | Uvicorn 能正常运行 |
| REST API 可用 | 下载 / 解析 / Cookie / 配置接口可调用 |
| WebSocket 可用 | 进度与状态可实时推送 |
| 健康检查可用 | 前端可判断服务就绪状态 |
| 进程管理可用 | Tauri 能启动与停止 sidecar |

---

## 3. 目标与范围

### 3.1 本里程碑包含

| 编号 | 内容 | 归类 | 涉及模块 |
|---|---|---|---|
| 1 | FastAPI 服务结构搭建 | 服务基础 | Python sidecar |
| 2 | 下载任务 REST API | 任务控制 | 下载接口 |
| 3 | 解析与抓取 REST API | 爬虫接口 | 解析接口 |
| 4 | Cookie REST API | Cookie 管理 | Cookie 接口 |
| 5 | 配置 REST API | 配置访问 | 配置接口 |
| 6 | WebSocket 进度通道 | 实时通信 | 进度推送 |
| 7 | 健康检查接口 | 就绪判断 | 系统接口 |
| 8 | Tauri sidecar 启动管理 | 进程联动 | 桌面壳 |
| 9 | 旧 Qt worker 桥接收敛 | 架构清理 | `worker/` 方向 |

### 3.2 本里程碑不包含

- 页面级 UI 接入
- 下载页/抓取页/设置页的真实数据展示
- 系统托盘、更新、快捷键等桌面系统能力

### 3.3 范围边界

- 业务逻辑尽量复用现有 Python 代码
- API 设计以前端调用便利为优先
- sidecar 服务必须可独立启动、可健康检查、可关闭

---

## 4. 设计依据与技术约束

- Python 继续作为唯一业务执行语言
- 以 REST 为主，WebSocket 为辅
- 接口应尽量稳定、语义清晰、前后端解耦
- 现有数据库与下载逻辑不应在此阶段被重写

---

## 5. 任务清单

### 任务 1：搭建 FastAPI 服务结构

#### 目标

建立 Python sidecar 的服务入口与模块结构。

#### 涉及文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `backend/` | 新建 | Python sidecar 根目录 |
| `backend/app.py` | 新建 | 服务入口 |
| `backend/api/` | 新建 | 路由层 |
| `backend/services/` | 新建 | 业务服务封装 |

#### 验证点

- 服务可在本机启动
- 健康检查端点可响应

### 任务 2：实现下载任务 REST API

#### 目标

暴露下载任务控制接口。

#### 涉及接口

- `GET /api/download/tasks`
- `POST /api/download/start`
- `POST /api/download/pause`
- `POST /api/download/resume`
- `POST /api/download/retry`
- `POST /api/download/clear-completed`

#### 验证点

- 前端可读取任务列表
- 下载控制动作可调用

### 任务 3：实现解析与抓取 REST API

#### 目标

暴露链接解析与主页抓取能力。

#### 涉及接口

- `POST /api/crawler/parse`
- `POST /api/crawler/fetch-home`
- `POST /api/crawler/preview`

#### 验证点

- 批量解析与主页抓取可调用
- 返回结构适合前端消费

### 任务 4：实现 Cookie REST API

#### 目标

暴露 Cookie 管理能力。

#### 涉及接口

- `GET /api/cookie/list`
- `POST /api/cookie/add`
- `POST /api/cookie/test`
- `POST /api/cookie/test-all`
- `DELETE /api/cookie/{id}`

### 任务 5：实现配置 REST API

#### 目标

提供下载目录、并发数、分块大小、元数据格式等配置读写能力。

### 任务 6：实现 WebSocket 进度通道

#### 目标

把下载进度、解析进度、状态变化推送给前端。

### 任务 7：实现健康检查接口

#### 目标

提供服务健康检查和就绪状态，供 Tauri 与前端确认 sidecar 是否可用。

### 任务 8：实现 Tauri sidecar 启动管理

#### 目标

让 Tauri 能管理 Python sidecar 的启动、停止、端口绑定与异常恢复。

### 任务 9：旧 Qt worker 桥接收敛

#### 目标

清理或隔离原 `worker/` 桥接路径，避免与新服务层并行冲突。

---

## 6. 验收标准

- Python sidecar 可独立启动
- REST API 可被前端调用
- WebSocket 可持续推送状态
- 前端可判断服务是否就绪
- 旧 Qt worker 路径已不再作为主链路

---

## 7. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 接口设计过散 | 前端调用困难 | 先定义统一 API 风格 |
| 进度推送不稳定 | UI 看不到实时状态 | 以 WebSocket 作为统一通道 |
| Sidecar 崩溃恢复 | 用户体验中断 | 加健康检查与重启策略 |
