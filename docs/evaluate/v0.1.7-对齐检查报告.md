## 二、P1 幻觉修复记录

### 原幻觉项：任务 6.5/6.6 图片直链失效重新解析未实现

**初版审计发现**：plan 6.5/6.6 节明确要求图集下载阶段若图片直链失效（403/404），调用 `VideoParser.parse_video(aweme_id, cookie)` 重新获取 `image_urls`，按 `selected_image_indices` 筛选后重试。但初版 `_download_image_set` 只做并发下载 + M/N 张进度上报，完全没有 4xx 重新解析逻辑；`_should_retry` 对 4xx 返回 `False` 直接标记失败。

### 修复内容

1. **Downloader 依赖注入**（[downloader.py](file:///d:/Program/Douyin_Catcher/downloader/downloader.py)）
   - 构造函数新增 `video_parser: VideoParser | None = None` 与 `cookie_repository: CookieRepository | None = None` 两个可选依赖
   - 用 `TYPE_CHECKING` 注解避免运行时循环导入
   - 为 None 时保持原行为（4xx 直接失败），向后兼容

2. **图片直链失效重新解析**（`_download_image_set` 改造）
   - 新增 `_is_link_expired(error)`：判定 `HTTP 403`/`HTTP 404` 为直链失效
   - 新增 `_can_reparse()`：两依赖同时注入才具备重新解析能力
   - 新增 `_get_cookie_string()`：从 CookieRepository 取有效 Cookie 的 `content`
   - 新增 `_reparse_single_image_url(task_item, idx)`：调用 `VideoParser.parse_video` 重新获取全量 `image_urls`，按 `selected_image_indices` 重新筛选，取第 idx 个
   - `_download_one` 内部：子下载失败且 `_is_link_expired` 为真时，触发 `_reparse_single_image_url` 获取新 url 重试一次；重新解析失败则按原失败结果处理
   - 新增模块级 `_select_urls_by_indices`：与 `download_bridge._filter_image_urls` 语义一致，避免 downloader→worker 循环依赖

3. **Scheduler 传递依赖**（[scheduler.py](file:///d:/Program/Douyin_Catcher/downloader/scheduler.py)）
   - `__init__` 新增 `video_parser`/`cookie_repository` 可选参数，透传给 Downloader

4. **单元测试**（[test_downloader.py](file:///d:/Program/Douyin_Catcher/tests/test_downloader.py)）
   - 新增 24 个测试，覆盖 `_select_urls_by_indices` / `_is_link_expired` / `_can_reparse` / `_get_cookie_string` / `_reparse_single_image_url`（成功/带勾选/无 parser/解析失败/无 cookie/无 aweme_id/索引越界）/ 图集集成（403 重新解析成功 / 重新解析失败标记 failed / 无 parser 直接失败）
