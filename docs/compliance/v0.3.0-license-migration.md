# v0.3.0 许可证迁移说明（MIT → Apache License 2.0）

- **分支**：`feature/v0.3.0-license-apache-2.0`
- **基线**：`master`（v0.3.0 发布后状态）
- **生效版本**：`v0.3.0` 起
- **目标**：将本项目开源协议由 **MIT** 切换为 **Apache License 2.0**，作为 v0.3.0 发布的一部分；所有相关的代码、配置、文档、测试同步更新。

## 1. 背景

本项目自首次发布起使用 **MIT License**。v0.3.0 阶段在完成 `update/v0.3.0-compliance` 合规与归属更新（见 `docs/superpowers/specs/2026-08-01-v0.3.0-compliance-update-design.md`）的基础上，将协议升级为 **Apache License 2.0**。

升级决定基于以下考虑：

1. **与上游参考项目协议对齐**：本项目后端在调研阶段参考了 [`Evil0ctal/Douyin_TikTok_Download_API`](https://github.com/Evil0ctal/Douyin_TikTok_Download_API)，该项目本身采用 **Apache License 2.0**。本项目升级到 Apache 2.0 后，与上游参考项目的协议完全一致，避免未来在协议解释、专利授权、署名链条上出现分歧。
2. **显式专利授权**：Apache 2.0 §3 明确授予贡献者与下游使用者专利使用权，对贡献者与下游使用者都更有保护。
3. **明确商标与贡献条款**：Apache 2.0 §6 关于商标、§5 关于贡献提交的约定更清晰，有利于项目未来可能的协作扩展。

## 2. 协议兼容性

- **MIT → Apache 2.0 单向升级，MIT 下游使用者权利不受影响**：
  - MIT 要求保留版权声明与许可声明；Apache 2.0 同样要求在显著位置附带 `LICENSE` 与 `NOTICE`（如有）。MIT 的署名/版权要求自然满足 Apache 2.0 的对应要求。
  - 先前按 MIT 分发的副本仍然可以继续按 MIT 使用，不会因为新版本协议变化而失效。
- **与上游参考项目兼容**：上游 `Evil0ctal/Douyin_TikTok_Download_API` 本身就是 Apache-2.0，与本项目新协议完全兼容。
- **与依赖兼容**：本项目运行时依赖（PySide6/LGPL、httpx/BSD-3-Clause、h2/hpack/hyperframe/MIT、httpx、Tauri/Apache-2.0 OR MIT 等）均与 Apache 2.0 兼容。完整列表由 `scripts/generate_license_report.py` 自动生成至 `licenses/THIRD-PARTY-LICENSES.md`。
- **生效时间点**：v0.3.0 起。v0.3.0 之前（含 v0.1.x、v0.2.x）的发布版本继续遵循 MIT 协议；其分发副本不受本次升级影响。

## 5. 风险与回滚

- **协议升级不可逆**：一旦合并到 master 并发布 v0.3.0（含 v0.3.0 在内的所有后续版本），将基于 Apache 2.0 分发。如需回滚协议，必须再次切换并发布新版本，但不会追溯影响已分发的副本（先前分发仍按当时协议有效）。
- **第三方依赖清单**：升级为 Apache 2.0 后，所有随安装包或 sidecar 分发的第三方组件仍按各自上游协议分发；`licenses/THIRD-PARTY-LICENSES.md` 不变，发布前仍应人工核验 `需人工核实` 项。
- **回滚策略**：本分支以单次提交形式合并；如需回退协议，可通过 `git revert` 撤销该提交，但需同时发布版本号变更说明。
